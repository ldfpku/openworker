# 不良品处理单与 8D 报告

把一张或几张不良品处理单，连同检验记录和现场信息，整理成一份证据齐全、能被质量部门签字关闭的 8D 报告。

## 适用场景

- 客户、审核员或公司内部要求对一次不良出具 8D 报告。
- 不良品处理单开了，但「原因分析」只写了一句话，要补成完整的分析和闭环。
- 同一台设备、同一种不良反复开单，换过措施仍然复发，需要升级处理。
- 返厂维修发现的故障（密封失效、芯轴拉伤、定子脱胶等）要追溯到制造或装配环节。
- 内审或客户审核前，要核对处理单是不是真的关闭了，还是只是把状态改成了「已关闭」。

## 需要的输入

| 输入 | 常见形式 | 常见列名或内容（以用户文件为准） |
| --- | --- | --- |
| 不良品处理单 / NCR | Excel 一行一张单，或单张 Word 表单 | 单号、日期、车间、设备（设备编号）、零件（零件名称 / 图号）、不良描述（不良类型 / 缺陷）、数量（不良数量）、原因分析、纠正措施、责任人、状态（已关闭 / 处理中） |
| 相关检验记录 | 各车间的检验记录表 | 日期、车间、设备、零件、工序、送检数（送检数量）、不良数（不合格数）、不良类型、处置（返修 / 报废 / 让步接收）、检验员 |
| 现场信息 | 用户口头说明 | 谁发现、什么时候、在哪道工序、怎么发现的、涉及哪些批次、不良品现在在哪、有没有流到下道工序或已发货 / 已出租 |
| 同类历史处理单 | 同设备或同不良的旧单 | 单号、日期、原因分析、措施、关闭日期 |
| 工艺与检验文件（可选） | 图纸、工艺卡、检验规程、控制计划 | 公差、工艺参数、检验项目与频次 |
| 客户投诉或返厂记录（可选） | 返厂检验记录、维修记录 | 工具编号、井号、入井 / 出井日期、累计入井时间、故障部位、故障现象、处理措施 |

缺处理单只有口头描述：先按下面 D2 的 5W2H 把问题描述补全，再往下做。缺检验记录：数量和波及范围写「待核实」，不要补数。缺历史处理单：问用户「这台设备 / 这种不良以前开过单吗」，答不上来就在 D2 注明「历史情况未核实」。

## 工作步骤

1. **读处理单，核对基本信息。** 单号、日期、设备、零件、不良描述、数量、状态逐项核对；缺项列出来问用户。多张单一起给的，先按「设备 × 不良类型」分组，看哪些其实是同一个问题。
2. **关联检验记录。** 按设备、零件、日期找到对应的送检批次，核对处理单上的数量和检验记录的不良数是否一致，不一致写明两个来源各是多少。同时找出同设备同不良的历史记录和旧处理单，判断是「首次」还是「重复」。
3. **D0 准备：决定要不要启动 8D。** 按贵司规定；缺省建议满足任一条就启动：客户投诉或返厂故障、有报废、同一「设备 × 不良类型」重复出现 ≥ 2 次、涉及安全或 API 关键特性（承载件、螺纹连接、压力密封）。一次性的小问题用处理单闭环即可，不必硬套 8D。
4. **D1 小组。** 列出需要的角色和人：质量牵头（组长），加上工艺、生产班组长、设备（设备类问题）、采购（材料 / 外协类）、研发（设计类）、售后（返厂类）。不知道具体人名就写角色，让用户填。
5. **D2 问题描述。** 用 5W2H 写：What（什么零件、什么特性不合格、实测值与公差）、Where（哪个车间、哪台设备、哪道工序、零件上哪个部位）、When（首次发现日期、持续时间、是否集中在某班次）、Who（谁发现的、检验还是客户）、How（怎么发现的：首件、巡检、终检、试压、现场使用）、How many（不良数 / 送检数、涉及几个批次、有没有流出）、Why it matters（对装配、对客户、对交期的影响）。再写一组「是什么 / 不是什么」：只出在这台设备不出在其他设备、只出在这种零件不出在其他零件、只出在这周不出在上周。这些对比是 D4 分层的起点。
6. **D3 围堵。** 分四块写清：已产出的不良品去向（隔离、标识、返修、报废、让步接收各多少件，对应的单号）；在制品和库存排查（同批次、同设备同期加工的零件查了多少、结果如何）；已发货和在外工具排查（同批次装机的工具编号、客户、井号；租赁在外和各服务基地库存要不要召回检查）；围堵期间的临时措施（加严检验、100% 检、换设备生产）。围堵要有有效性证据：围堵后连续几批检验结果。
7. **D4 根因。** 调用 `root-cause-analysis` 技能做分层、鱼骨图和 5Why。必须分两条链：**发生根因**（为什么会产生这个不良）和**流出根因**（为什么没有在本工序或下道检验拦住）。每个根因写出支撑证据（记录、测量数据、再现试验），没有验证的写「待验证」。
8. **D5 纠正措施。** 针对每个根因各出一条措施，写明「措施 → 针对哪条根因 → 怎么验证有效」。「加强教育」「加强检查」「提高质量意识」不算措施；要落到参数、工装、程序、检验项目、点检项目、文件版本上。有多个方案时列出比较（成本、周期、副作用）让用户选。
9. **D6 实施与验证。** 每条措施：实施日期、责任人、实施证据（更换记录、调试记录、程序版本号）、验证方法与数据（实施后连续 N 批或 N 天的检验结果；N 按贵司规定，缺省建议连续 3 批且不少于 30 天零复发）。验证没达到就不能进 D7。
10. **D7 预防与标准化。** 把措施写进文件：工艺卡、检验规程、控制计划、PFMEA、设备点检表、作业指导书、培训记录，每项写文件名和新版本号。横向展开：同类设备、同类零件、其他车间、其他服务基地是否有同样风险，查了没有、结果如何。
11. **D8 关闭。** 核对下面「行业口径」里的关闭条件，逐条打勾；全部满足才能提交质量签字。处理单的状态同步改为「已关闭」并写关闭日期。
12. **成稿前确认。** 先把 D2 和 D4 发给用户确认，再出全文；用户改了口径（例如让步接收算不算围堵完成）就重新整理。

## 行业口径与判断规则

**处理单与 8D 的对应关系**

| 处理单字段 | 对应 8D 步骤 | 说明 |
| --- | --- | --- |
| 单号、日期、设备、零件、不良描述、数量 | D2 | 8D 的 D2 要比处理单详细得多，处理单是起点不是终点 |
| 处置（返修 / 报废 / 让步） | D3 | 处置只解决眼前这批，围堵还要管在制品、库存、在外工具 |
| 原因分析 | D4 | 处理单上一句话的原因通常是直接原因，不是根因 |
| 纠正措施 | D5、D6 | 处理单写「已更换刀片」只是实施，没有验证数据不算 D6 |
| 责任人 | D1、D5 | 8D 的责任人按措施分，不是一个人包全单 |
| 状态 | D8 | 处理单「已关闭」不等于 8D 可以关闭，反过来 8D 关闭时处理单必须同步关闭 |

一张处理单可以单独做一份 8D；同设备同不良的多张处理单应合并成一份 8D，把所有单号列进 D2，按时间排出「每次的原因分析和措施」，这本身就是 D4 的重要证据。

**「换了措施仍复发」的升级规则**

- 判定：同一「设备 × 不良类型」在处理单关闭后再次出现，就是复发；按设备不按零件（同一台车床加工不同零件出同一种超差，是设备、刀具或程序的问题）。
- 复发说明前次根因没找对，或者措施没落实。禁止在新单上再写一遍同样的措施关闭。
- 第 1 次复发：原 8D 重新打开（不是新开一份），D4 加一节「前次分析复核」，写明前次原因、前次措施、复发日期和数量；升级到质量负责人复核 D4。按贵司规定，缺省建议如此。
- 第 2 次复发：升级到技术或生产负责人，小组扩大到跨部门；查更上游的因素（机加：刀补、主轴跳动、卡盘、程序、材料批次；热处理：温控仪表、炉温均匀性、装炉方式；装配：密封件批次、清洁度、装配工装）。
- 涉及客户、返厂故障或已发货产品的复发：是否通知客户、是否召回在外工具，由用户决定，先征得确认。

**根因的几条硬规则**

- 根因不能是人：「操作工疏忽」「检验员漏检」不是根因，要接着问「为什么系统允许疏忽发生」「为什么漏检没有被拦住」。
- 发生根因和流出根因缺一不可。只写发生根因，下次还是靠运气拦。
- 围堵不是纠正。D3 的「加严检验」「100% 全检」是临时的，验证有效后要在 D7 撤掉或转成常规控制，并写明撤掉的日期。
- 返厂故障要先区分三种可能：井下工况超出设计（入井时间、载荷、温度、介质）、制造或装配缺陷、上次维修质量。没有入井记录和现场工况就别下「制造缺陷」的结论，写「待补工况信息」。
- 让步接收必须有依据（图纸容许、工艺评审、客户书面同意），8D 里要写明依据来源，不能用让步代替措施。

**时限**（按贵司规定，缺省建议）

- D3 围堵：发现后 24 小时内。
- D4 初步根因和 D5 措施：10 个工作日内。
- D8 关闭：验证数据够了才关，缺省不超过 60 天；超期的在报告里注明原因。

**关闭条件（只有质量能签关闭）**

- 所有围堵的不良品都有去向凭证：返修件的复检记录、报废单号、让步单号。
- D4 每条根因都有验证证据，不是推测。
- D5 每条措施都有 D6 的实施证据和验证数据，验证达到约定的批次 / 天数。
- D7 的文件更新有文件名和版本号；横向展开有检查结果。
- 处理单状态已同步更新。
- 签字人是质量部门负责人或其授权人；生产、工艺可以提交关闭申请，不能自己签关闭。

## 交付前自检

- [ ] 处理单上的每张单号都出现在 D0 或 D2 里，数量和检验记录对得上，不一致的已注明。
- [ ] D2 有「是什么 / 不是什么」对照，不是只抄了处理单的不良描述。
- [ ] D3 的四个范围（不良品、在制品 / 库存、已发货、在外工具）都有交代，没查的写「未排查」而不是空着。
- [ ] D4 分了发生根因和流出根因，每条都有证据或标了「待验证」；没有把人当根因。
- [ ] D5 的每条措施都对应一条根因，且写了验证方法；没有「加强教育」这类空话。
- [ ] D6 的验证批次 / 天数按用户确认的口径，没达到的没有进 D7。
- [ ] 复发的单已按升级规则处理，没有用同样的措施再关一次。
- [ ] 关闭条件逐条核过，签字人是质量部门。
- [ ] 所有时限和验证批次写成「按贵司规定，缺省建议 X」，没有编造企业制度。

## 边界

- 只整理和分析，不替用户认定「责任在谁」；原因分析引用处理单、记录和用户的原话。
- 不修改用户的原始处理单和检验记录；状态更新由用户在系统里操作。
- 通知客户、召回在外工具、发送报告、写入质量系统，一律先问用户。
- 根因分析的方法细节以 `root-cause-analysis` 技能为准，本技能只负责把结论放进 D4。
- 缺证据就写「待验证」「待补」，不编造数据、不替用户下结论。
