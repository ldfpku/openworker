# 科学头脑风暴(Scientific Brainstorming)

## 目的与边界

使用本技能来创建、组织、质疑并透明地排定候选研究方向的优先级。把每一项输出都当作**提案(proposal)**,而不是研究结论。创造性方法可以改变参与度和创意产出量，但没有任何一种方法能普遍地提升原创性、实用性或科学有效性。相关证据基础及其局限性总结在 `references/sources.md` 中。

以下这些活动要保持分开:

- **构思(Ideation)** 产生问题、机制、备选方案或研究构想。
- **证据评估(Evidence assessment)** 检查可靠文献和数据支持了什么。
- **假设验证(Hypothesis validation)** 需要观测数据、预测、合适的研究设计、分析方法以及独立审查；头脑风暴无法验证假设。
- **伦理、生物安全、两用性(dual-use)、监管与机构审查** 需要相关的授权审查人员。头脑风暴本身绝不等同于审批通过。
- **临床建议** 需要合格的临床医生以及针对具体患者的背景信息。不要把研究构思转化为诊断或治疗指导。

对于由观测引导的可检验假设，请转交给 `hypothesis-generation`。对于研究架构，使用 `experimental-design`;对于样本量，使用 `statistical-power`;对于已有证据，使用 `literature-review`;对于分析工作，使用 `statistical-analysis`。

## 操作规则

1. 将每项论断标注为**创意(idea)**、**假定(assumption)**、**预测(prediction)**、**已定位证据(located evidence)**,或**决策(decision)**。绝不混淆这些类别。
2. 在让参与者接触他人或 AI 生成的创意之前，先独立生成创意。面对面轮流发言可能会阻碍产出，而示例则可能锚定后续的输出。
3. 保留少数意见、阴性证据、不确定性和弃权。共识不等于真理，票数也不是效应量(effect size)。
4. 记录出处来源，但不暴露机密、个人、受管制或未发表的信息。
5. 在打分之前先定义评估标准和方向。保留原始评分、理由、区间和分歧，使其可见。
6. 在条件允许的情况下，于**首轮独立构思之后**检索文献，然后有意识地重新开放构思环节。这样可以减少早期锚定效应，同时避免把一次不完整的检索误当作研究空白。
7. 不要自动选出一个"赢家"。分数只是可追溯的决策辅助工具；定性判断、不确定性、可行性和伦理关卡仍然起决定作用。

## 可复现的工作流程

### 1. 确定会议范围

写出一个焦点问题，并记录:

- 目的、受众、决策负责人和时间跨度;
- 范围内和范围外的主题;
- 真实的、假定的、可协商的或未知的约束条件;
- 现有知识、尚未解决的观测事实，以及被禁止的输出内容;
- 是否可能涉及人类参与者、动物、临床护理、敏感数据、病原体、受管制技术或环境释放。

如果请求寻求针对具体患者的诊疗、规避监督、有害的优化，或提供可操作的两用性细节，应停止构思，转交给相应的专业人员或机构流程。

### 2. 有意识地多元化视角

邀请相关的方法论、领域、实施、统计、安全、伦理、利益相关方及亲历经验(lived-experience)视角。多元化并不保证创造力:要说明代表了谁的视角、缺失了谁的视角，或者哪些视角在结构上处于不利地位。在适当情况下，使用无障碍的参与方式和匿名化的参与者 ID。

主持人应披露利益冲突，避免率先给出自己偏好的答案，防止资深成员主导讨论，并要求领导者在独立构思环节之后再发表意见。

### 3. 独立生成创意

给每个人相同的中性提示、约束条件和固定的时间窗口。参与者在讨论之前私下、并行地写下创意。对每个创意，记录:

- 一个稳定的 ID 和一句话陈述;
- 贡献者 ID 及所处阶段(`independent`、`discussion` 或 `post-check`);
- 来源(`human`、`AI-assisted`、`literature-inspired`、`mixed` 或 `other`);
- 假定条件、预测的观测结果、不确定性，以及可能的证伪证据;
- 受文献启发的创意的来源标识，以及 AI 辅助所用工具和用途的披露。

除非确有必要，否则在本轮之前不要展示示例解答；如果确有必要，需将它们记录为潜在的锚定因素。

### 4. 分享但不立即评估

采用轮流发言或集中静默分享的方式。在不带倾向性的情况下澄清措辞。允许使用私密或匿名的渠道。询问每位参与者:遗漏了什么、什么与主流框架相矛盾，以及听完小组讨论后哪个创意变得不那么显而易见了。

### 5. 按结构聚类

按明确的关系对创意分组，例如共同的结局、机制、人群、规模或方法。保留原始 ID 和文字。记录合并与拆分。措辞相似并不能证明语义上等价；当假设、干预措施、人群或预测存在差异时，应保留为不同的创意。参见 `references/facilitation_workflows.md`。

### 6. 定义透明的评估标准

在打分之前，先定义每项标准、方向、量表锚点、所需证据、利益冲突以及明确的权重。常见的评估维度包括:

- 潜在的信息增益以及具有区分力的预测;
- 与既定问题范围的相关性;
- 相对于已检索文献(而不仅仅是相对于房间里其他人)的原创性;
- 可行性、所需资源和可逆性;
- 方法学严谨性及对偏倚的易感性;
- 伦理、安全、公平性、两用性和监管负担;
- 若结果为阴性或与偏好机制相矛盾时的价值。

在评估者不确定时，使用区间或置信度标签。不要把否决意见(veto)隐藏在平均分数里。参见 `references/idea_evaluation.md`。

### 7. 进行对抗性审查(Adversarial review)

为每个入围的创意指派一位并非该创意提出者的审查人。提出以下问题:

- 什么样的观测结果会使这个创意被证伪或变得没有信息量?
- 有哪些替代解释能同样解释预测的结果?
- 有哪些隐藏的依赖关系、测量失败、混杂因素或选择效应可能占主导地位?
- 是权威性、锚定效应、群体忠诚度、发表激励，还是某项有吸引力的技术在驱动偏好?
- 这是否可能造成伤害、加剧不平等、暴露敏感信息，或被滥用?

记录审查回应、缓解措施、剩余的不确定性，以及该创意是否被修改——而不仅仅是通过/未通过的判定。

### 8. 核查文献与证据

检索权威数据库、原始研究、方法学指南、阴性结果以及相邻领域。逐条核实每一条引用的原始出处。对每个创意，记录检索式/日期、筛查过的来源、支持和反对的证据，以及检索的局限性。使用诸如 `not-checked`(未核查)、`search-incomplete`(检索不完整)、`support-located`(已找到支持证据)、`challenge-located`(已找到质疑证据)或 `mixed`(混合)之类的状态标签。

在一次有界检索中未找到相关文献，并不能确立该创意的新颖性；而支持性文献也不能验证一个新机制。在完成证据核查之后，重新开放一轮简短的独立构思。

### 9. 应用可行性、严谨性和伦理关卡

在推进某个创意之前，确定合适的领域审查方式:

- 对于生物医学工作，要考虑既往研究的严谨程度、稳健的研究设计、相关的生物学变量，以及资源的真实性核验(resource authentication)。当适用 NIH 政策时，应从研究问题本身直到设计、分析和报告的全过程都考虑性别作为生物学变量(sex as a biological variable);若采用单一性别范围，需用相关证据加以说明。
- 将涉及人体受试者、动物、生物安全、数据治理、出口管制、临床、环境及其他受监管的工作，转交给相应的主管部门。
- 及早为生命科学和赋能技术(enabling-technology)相关创意筛查两用性或被滥用的可能性。目前美国的监管政策仍在演变之中；应咨询所在机构和当前的机构政策，而不是依赖一份静态清单。
- 不要将敏感、未发表、专有、受管制或个人信息上传到外部 AI 服务。

伦理或可行性方面的顾虑可能要求重新设计、受控处理，或直接停止。极高的创造力评分永远不能凌驾于关卡之上。

### 10. 决策与记录

负有责任的人类决策负责人应记录:

- 已考虑的候选方案及所使用的评估标准/权重;
- 原始评分、不确定性区间、异议、弃权，以及敏感性分析结果;
- 文献检索和审查的日期;
- 各关卡的通过结果及所需的批准;
- 决策内容、理由、被否决的备选方案、尚未解决的风险、负责人，以及重新评估的触发条件。

正确标注下一步行动:进一步检索、咨询、模拟、试点设计(pilot design)、方案制定(protocol development)、预注册(preregistration),或不采取行动。如果计划开展验证性研究，应在结果揭晓之前预注册假设和分析决策；之后应透明地报告任何偏离和探索性工作。预注册能提升透明度，但不等于同行评审、伦理批准，也不能证明有效性。

## 偏倚与失败的控制措施

- **生产阻滞(Production blocking)**: 在口头讨论之前先进行私下的并行构思。
- **锚定效应与设计固化(Design fixation)**: 在独立构思环节结束之前，不给出领导者的答案或 AI 示例；在证据审查之后重新开放构思。
- **权威与地位效应**: 让领导者最后发言、匿名提交、独立评分，并让异议可见。
- **群体思维(Groupthink)**: 指派一个真正负责生成替代方案的角色，邀请外部审查，并记录被否决的方案。把"群体思维"当作一类风险的统称，而不是单一的、已被普遍确认的诊断。
- **评估焦虑(Evaluation apprehension)**: 尽可能将贡献与归属分开；批评创意本身，而不是批评贡献者。
- **过早收敛**: 固定的发散时间窗口，之后进行明确的过渡，并预先声明评估标准。
- **虚假精确性(False precision)**: 使用有锚点的量表、不确定性区间、敏感性分析和叙述性审查。
- **研究空白夸大**: 记录检索的边界，使用"未找到直接证据",而不是"从未被研究过"。
- **AI 幻觉或同质化**: 以人为先的构思、出处记录、独立验证、多个非 AI 视角，以及对可疑的重复性框架进行比对。参见 `references/responsible_ai.md`。

## 可选的本地命令行工具

这些脚本是确定性的、仅依赖标准库的工具。它们不会调用网络服务、LLM 或科学数据库，也不会做出科学结论。

```bash
python scripts/session_scaffold.py --help
python scripts/validate_register.py --help
python scripts/evaluate_matrix.py --help
```

创建一份会议记录(session register):

```bash
python scripts/session_scaffold.py \
  --session-id "microbiome-01" \
  --title "Microbiome mechanism ideation" \
  --question "Which mechanisms could explain the scoped observation?" \
  --participant P01 --participant P02 \
  --output session.json
```

校验结构和出处记录:

```bash
python scripts/validate_register.py session.json --output validation.json
```

从 CSV 计算一份完全公开的加权矩阵，包括评分区间和逐一变动权重的敏感性分析:

```bash
python scripts/evaluate_matrix.py scores.csv \
  --config criteria.json \
  --weight-delta 0.10 \
  --output matrix.json
```

除非显式传入 `--force`,否则输出会拒绝符号链接和已存在的文件；输入和集合大小有边界限制。校验器检查的是结构，而不是真实性。该矩阵会保留定性审查意见和不确定性，并将 `decision` 字段留空(null)。输入格式及解读方式记录在 `references/idea_evaluation.md` 中。
