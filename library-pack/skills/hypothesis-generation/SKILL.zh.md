# 科学假设生成（Scientific Hypothesis Generation）

将一项观察结果转化为一组透明的候选解释与检验方案。假设是一个有待挑战的提议，
不是发现、事实、诊断或建议。

## 不可协商的边界

在使用未发表、敏感、受管控、个人、专有、受出口管制或与安全相关的材料之前：

1. 确认已获授权，并确认适用的机构、资助方、出版方、数据使用、隐私及 AI 相关政策。
2. 除非获得授权人员明确批准某个具名的外部目的地和数据范围，否则将材料保留在本地。
3. 将输入最小化。未经授权，不得将敏感或未发表的数据放入网络搜索或外部 AI 系统中。
4. 在适当的人类、动物、生物安全、两用性（dual-use）、数据治理或监管关口处停下。

绝不可以：

- 把某个假设、机制、因果效应、引用或表面上的模式呈现为已确立的证据；
- 仅因为一次快速检索没有找到结果就声称具有新颖性；
- 仅从关联性、单纯的时间先后顺序、预测准确度或模型输出中推断因果关系；
- 提供针对具体患者的诊断、治疗、剂量、预后或其他临床建议；
- 就病原体、毒素、武器、规避手段或其他滥用场景，提供有害的实验优化或操作细节；
- 绕过 IRB/REC（伦理审查委员会）、IACUC（动物照护和使用委员会）、IBC（机构生物安全委员会）、
  生物安全、两用性、隐私、法律或监管审查；
- 编造来源、标识符、检索覆盖范围、数据、结果、批准文件或预注册记录；
- 自动为科学假设打分、排名、筛选、接受或拒绝。

如果某个请求触及某项安全关口，只应给出一份高层级的风险/监督说明，
并将其转交给具备资质的本地权责方。不要继续提供操作层面的细节。

## 保持对象彼此区分

| 对象 | 含义 |
|---|---|
| **观察结果（Observation）** | 被测量、被注意到或被报告的内容，附带来源与不确定性 |
| **研究问题（Research question）** | 界定研究范围的、可回答的问题 |
| **假设（Hypothesis）** | 一个候选的、具有解释性或关联性的命题 |
| **机制（Mechanism）** | 将条件与结局联系起来的、被提议的过程 |
| **因果估计目标（Causal estimand）** | 需要估计的、被精确定义的因果对比 |
| **预测（Prediction）** | 在查看目标结果之前推导出的、可观察的推论 |
| **替代解释（Alternative explanation）** | 一种竞争性说法，包括偏倚或非因果性解释 |
| **零假设（Null hypothesis）** | 分析中所使用的、被明确设定的"无效应/无差异"模型 |
| **阴性对照（Negative control）** | 预期不会通过所提出机制发生作用的对照 |
| **操作化（Operationalization）** | 一个构念如何转化为变量、测量、干预或类别 |
| **分析计划（Analysis plan）** | 预先设定的转换、模型、对比、不确定性和决策规则 |
| **证据（Evidence）** | 与某项主张相关的观察结果或来源；绝不等同于该主张本身 |

不要把这些标签混为一谈。一段机制性的叙述不是预测；一个预测不是证据；
拒绝一个零假设并不能证明某种机制成立；支持一个候选解释并不能排除未被考虑到的其他竞争解释。

## 工作流程

### 1. 执行范围与安全性把关

记录以下内容：

- 负责任的人类所有者及预期用途；
- 数据敏感性、授权、留存期限，以及允许的处理方式；
- 受影响的人员、动物、生态系统、社区，或安全利益；
- 所需的伦理、可行性、生物安全、两用性以及监管审查；
- 尚未解决的阻碍事项，以及所需的领域专业知识。

脚本获得通过不等于伦理、安全、监管或科学层面的批准。

### 2. 固化观察结果

在做出解释之前先写下观察结果本身：

- 测量方式或来源；
- 人群、系统、地点和时间；
- 观察单元与分析单元；
- 不确定性、缺失情况、排除标准，以及预处理方式；
- 该模式是预期中的、探索性发现的，还是在查看结果后才被挑选出来的。

使用"报告显示"、"观察到"或"相关"这类措辞，而不是因果语言，除非某个因果设计
及估计目标确实能够支撑这样的措辞。

### 3. 构建研究问题的框架

只在适用时才选用某个框架：

- **PICO/PICOT** 用于干预/有效性问题：人群（Population）、干预（Intervention）、
  对照（Comparator）、结局（Outcome），可选加入时间（Time）。
- **PECO** 用于暴露相关问题。
- **人群–指示检验–参照标准–目标状况** 用于诊断准确性研究。
- **人群–预后因素–结局–时间** 用于预后研究。
- 针对定性、描述性、机制性或理论性工作，使用特定领域的
  "构念–情境–结局"框架。

PICO 并非通用模板。需要明确利益相关方、情境、边界、可行性，以及什么样的答案
会改变知识或实践。FINER 是用于打磨问题的助记口诀——可行（Feasible）、
有趣（Interesting）、新颖（Novel）、符合伦理（Ethical）、相关（Relevant）——
而不是一套打分体系。在有文献检索记录且经过专家评审支持之前，应将"新颖性"
视为尚未确定的问题。

### 4. 建立一个标注日期的证据边界

在做出依赖文献的陈述之前先进行检索。优先使用一手研究、官方政策、
一手方法学论文、当前的报告指南，以及用于把握方向的系统综述。

记录以下内容：

- 检索日期和截止时间；
- 数据库/索引、检索式、筛选条件，以及筛选边界；
- 纳入和排除的来源类型；
- 支持、挑战或为每项主张提供背景的来源；
- 已知的获取渠道、语言、数据库和时间方面的局限性。

一次检索能够确定"检索了什么"，而不能确定普遍意义上的"不存在"。
应说"在已记录的检索边界内未找到"，而不是"不存在先前的工作"。
使用 `assets/search_boundary_template.json`、`assets/evidence_ledger_template.csv`，
以及 `references/literature_search_strategies.md`。

### 5. 在选择检验方案之前先生成竞争性解释

在合理的情况下，从真正不同的解释类别中生成多个候选解释：

- 所提出的机制；
- 测量或处理过程中的伪影（artifact）；
- 混杂因素或共同原因；
- 选择偏倚或失访/流失；
- 对撞变量（collider）条件化带来的偏倚；
- 反向因果；
- 时间、情境或边界条件方面的差异；
- 随机（stochastic）变异；
- 另一尺度上的竞争性机制。

在借助 AI 扩展之前，先独立生成一组初始的竞争性解释，以减少锚定效应
（anchoring）和同质化。不要强行凑出固定数量的解释，也不要制造虚假的对称性。
将每个候选解释都标注为 `candidate`（候选）。

Platt 的强推理（strong-inference）模式的用意在于激发替代假设和关键检验，
但淘汰了替代假设并不意味着幸存下来的那个假设就是真的。未被考虑到的替代解释、
辅助性假定、测量误差，以及混合机制，仍然都是可能的。

### 6. 声明主张的类型与估计目标

将每个研究目标归类为：

- 描述性（descriptive）；
- 关联性（associational）；
- 预测性（predictive）；
- 因果性（causal）；
- 机制性（mechanistic）。

对于因果性目标，需要在分析之前定义：

- 目标人群或系统；
- 干预/暴露与对照；
- 结局与时间跨度；
- 人群层面的汇总统计量；
- 相关情况下的处理版本和并发事件（intercurrent-event）处理方式；
- 识别假设，以及目标试验/设计的类比对象。

将混杂、选择、对撞变量、测量以及反向因果方面的风险分别记录清楚。
一个观察性研究得出的因果估计始终依赖于所作的假设。参见
`references/causal_inference_and_claims.md`。

### 7. 推导判别性预测

对每个候选解释都要：

1. 陈述条件与边界条件。
2. 指明可观察量及测量方式。
3. 陈述预期模式及其不确定性。
4. 在所声明的假设下，陈述一个与该候选解释不相容的结果。
5. 将预期结果与至少一个竞争性解释进行对比。
6. 定义不确定的结果，以及从中能学到什么。

优先选择那些不同竞争性解释所预测结果存在实质性差异的检验方案。
在科学上适当时，加入阳性对照、程序性对照和阴性对照。阴性对照必须
不可能通过目标机制起作用，同时又要共享相关的偏倚路径；它不是一个
装饰性的未处理组。

使用 `assets/prediction_rival_matrix_template.csv` 和
`assets/falsification_controls_template.json`。

### 8. 将构念操作化并验证测量方式

对每个构念都要记录：

- 变量角色及操作性定义；
- 人群/系统、单位、时机与条件；
- 仪器/方法、校准、质量控制以及盲法；
- 信度/可重复性；
- 效度证据及适用性；
- 缺失情况、检测限、转换方式、切点，以及这些做法的依据；
- 相关情况下的测量不变性或跨组可比性；
- 可预见的测量偏倚及局限性。

不要把一个方便测量的代理指标当作构念本身。使用以下方式验证：

```bash
python3 scripts/check_operationalization.py local-operationalization.json
```

### 9. 使设计与分析方法匹配所要提出的主张

需要明确说明：

- 抽样方式、实验单元、分配方式、随机化、盲法以及对照；
- 纳入/排除标准和终止规则；
- 基于所声明假设的样本量、精度或信息量依据；
- 结局、对比、估计目标、模型、效应量指标，以及不确定性；
- 缺失数据和并发事件的处理方式；
- 跨结局、模型、亚组、多次查看数据点，以及多重假设检验带来的多重性问题；
- 假设条件、诊断方法、稳健性和敏感性分析；
- 重复实验或独立验证计划；
- 哪些是验证性的（confirmatory），哪些是探索性的（exploratory）。

不要使用"放之四海而皆准"的样本量下限。不要把某个经过阈值判断的 p 值
解释为该假设为真的概率，也不要将其解释为效应的重要程度。
参见 `references/experimental_design_patterns.md`。

对于干预性试验，在适用的情况下使用当前的 SPIRIT 2025 方案指南和
CONSORT 2025 报告指南。它们能提高完整性，但并不能证明设计质量、
伦理合规性或监管合规性。

### 10. 防止 HARKing，并披露偏离计划的情况

在接触目标结局数据之前，尽可能对研究问题、候选解释、预测、结局、
排除标准、转换方式、分析方法、多重性处理、缺失数据计划以及终止规则加盖时间戳。

之后需要：

- 将依赖数据得出的想法和分析标注为探索性的；
- 保留并报告预先设定的分析计划；
- 列出每一处偏离，注明日期、理由、决策者，以及预期影响；
- 绝不能把一个事后观察到的模式改写成一个事先做出的预测。

预注册（Preregistration）是一份透明的计划，而不是禁止适应性调整的规定。
Registered Reports（注册报告）在期刊政策下增加了不看结果的同行评审
和原则性接受机制。参见 `references/preregistration_and_open_science.md`。

### 11. 规划重复验证与知识更新

需要区分：

- **可重复性（reproducibility）**：使用相同的数据/代码/条件得到一致的计算结果；
- **可复现性（replicability）**：不同研究针对同一个问题收集新数据后得到一致的结果。

在获得授权分享的情况下，保留来源信息、版本、代码、材料和决策日志。
针对相关的边界条件，规划独立的重复验证或迁移性检验。当出现相反的、
零效应的或重复验证的证据时，应更新候选解释的状态；不要隐藏阴性结果。

### 12. 落实人类的责任担当

负责任的人类必须核实以下内容：

- 每一条引用及其来源与主张之间的对应关系；
- 领域内的合理性以及测量的效度；
- 因果假设与统计设计；
- 伦理、可行性、安全性、隐私以及监管状态；
- 所有借助 AI 生成的文本、想法和引用；
- 是否需要更广泛的专业知识或社区意见。

AI 可能会虚构引用、锚定推理方向，并使候选解释集合趋于同质化。
应记录被允许的 AI 使用范围及其产生的实质性影响。在整个流程中
保留独立的人类构思与竞争性解释生成环节。

## 本地工具索引

所有 CLI 工具都是有边界限制、无依赖、本地运行、确定性的，且不会打分：

| 任务 | 资产 | 命令 |
|---|---|---|
| 假设记录模式（schema） | `assets/hypothesis_record_template.json` | `python3 scripts/validate_hypothesis_schema.py record.json` |
| 测量清单 | `assets/operationalization_template.json` | `python3 scripts/check_operationalization.py checklist.json` |
| 预测/竞争解释矩阵 | `assets/prediction_rival_matrix_template.csv` | `python3 scripts/validate_prediction_matrix.py matrix.csv` |
| 主张措辞检查（lint） | 带注释的 Markdown | `python3 scripts/lint_causal_claims.py draft.md` |
| 证伪/对照检查 | `assets/falsification_controls_template.json` | `python3 scripts/check_falsification_controls.py controls.json` |
| 证据/来源审计 | `assets/evidence_ledger_template.csv` + `assets/search_boundary_template.json` | `python3 scripts/audit_evidence_ledger.py ledger.csv boundary.json` |
| 预注册脚手架 | `assets/preregistration_scaffold_template.md` | `python3 scripts/generate_preregistration_scaffold.py record.json -o preregistration.md` |

退出码含义：`0` 表示结构上有效的输出，`1` 表示已完成验证但存在错误，
`2` 表示输入格式错误或不安全。这些报告仅验证声明内容和内部一致性，
并不验证科学真实性，也不会为你选择某个假设。完整的模式定义见
`references/tool_reference.md`。
