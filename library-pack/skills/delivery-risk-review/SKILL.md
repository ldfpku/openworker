# 交期风险排查

把散在订单清单、排产计划、进度跟踪里的信息按订单号对到一起，告诉用户哪些订单真的会延、为什么延、下一步找谁、对客户怎么说。

## 适用场景

- 周一生产例会前要一份「哪些订单有延期风险」的清单，数据分别在销售、计划、车间三个人手里。
- 销售问「这张单能不能按期交」，要拿数据回答而不是凭感觉。
- 客户催货，要一份有根据、口径一致的答复。
- 想知道延期的根子是缺料、工序拖期、设备故障还是外协，好决定找采购、找车间还是找外协厂。
- 怀疑某台设备或某种物料拖住了不止一张订单，要看连锁影响。
- 月底要向管理层汇报交付情况，需要一份「已延期交付」的清单。

## 需要的输入

| 输入 | 常见形式 | 常见列名（以用户文件为准） |
| --- | --- | --- |
| 订单清单 | 一张表，每行一张订单 | 订单号（合同号 / 销售单号）、客户、产品（产品名称 / 型号 / 规格）、数量、合同交期（交期 / 交货日期 / 要求交期）、订单状态（生产中 / 已发货 / 已完成 / 暂停）、业务员、备注 |
| 排产计划 | 一张表，每行一张订单的一道工序 | 订单号、工序（工序名称 / 工序号）、车间、设备（设备编号）、计划开始、计划结束、实际开始、实际结束、状态 |
| 进度跟踪 | 一张表，每行一张订单 | 订单号、当前工序、完成率（进度 / 完成百分比）、异常类型、异常说明、预计完成日期、更新日期、责任人 |
| 「今天」是哪天 | 用户口头给 | — |
| 风险窗口 | 用户口头给；没给就按两周（14 天） | — |
| 客户重要性或违约条款 | 可选，用来排优先级 | — |

三张表靠订单号关联。缺了哪张，能做到哪一步：

| 缺的输入 | 还能做什么 | 必须注明什么 |
| --- | --- | --- |
| 订单清单 | 做不了，先要 | — |
| 排产计划 | 能分级、能归类异常 | 「工序拖期」只能靠进度跟踪里的异常说明判断，没有按工序核对 |
| 进度跟踪 | 只能按交期排序 | 这是「只看交期」的结果，没有交叉比对，不叫风险排查 |
| 「今天」 | 不能算距交期天数 | 先问，不用系统日期猜 |

## 工作步骤

1. **定「今天」和窗口。** 用户没说「今天」就问。风险窗口缺省 14 天，用户另有说法按用户的。
2. **读全三张表。** 每个文件看有几张工作表、表头在第几行、末尾有没有合计行或说明行。记下每张表的数据行数，成稿时写进「数据来源」。
3. **统一订单号。** 三张表的订单号写法可能有差别（大小写、空格、全角半角、前导零、「DD-0017」和「DD0017」）。对齐后，列出三张表里对不上的订单号：订单清单有、另两张没有的，和另两张有、订单清单没有的，都报给用户，不要悄悄丢掉。
4. **并表。** 以订单清单为主，把进度跟踪按订单号并上；排产计划一张订单多行，按订单号汇总成「总工序数、已完成工序数、拖期工序数、最晚计划结束日期」再并上。同一订单号在订单清单里出现两行的（一行旧状态、一行新状态），问用户以哪行为准。
5. **剔除不在范围的订单。** 状态是「已发货 / 已完成」的不算当前风险；但它的发货日期晚于合同交期的，另列一张「已延期交付」表给用户参考。状态「暂停」的单独列出，问用户算不算。
6. **算距交期天数。** 距交期 = 合同交期 − 今天。负数就是已过期。交期列是文本不是日期的（「10 月 10 日」「2026/10/10」「待定」），先转换，转不了的单列「交期不明」。
7. **分级。** 按下面「行业口径」里的规则分成 A / B / C 三级和「关注」一档。核心一条：交期近但进度正常、无异常的订单不是风险，放进「关注」，不进风险清单。
8. **判断进度是否落后。** 有排产计划的，用「计划结束已过、实际未结束」的工序数判；只有完成率的，用「行业口径」里的完成率规则判。两种都有就都看，矛盾的以排产计划为准并注明。
9. **归类异常原因。** 把异常类型和异常说明里的写法合并成缺料 / 工序拖期 / 设备故障 / 外协 / 其他五类，列成合并口径表交用户认可后再汇总。例如：

   | 归为 | 原始写法举例 |
   | --- | --- |
   | 缺料 | 锻件未到货、物料未到、密封件缺货、采购在途 |
   | 工序拖期 | 深孔工序积压、装配未按计划开始、返修占用 |
   | 设备故障 | 主轴异响停机检修、炉温不稳停炉 |
   | 外协 | 外协热处理拖期、外协镀铬未回厂（不归工序拖期） |
   | 其他 | 图纸变更待确认、客户要求暂停 |

   异常类型为空、但异常说明里有内容的，按说明归类并标「类型列空白」；「无」「—」「空白」都算无异常。
10. **看连锁影响。** 连锁的要在报告里单独点出来，因为解决一个点能救几张单。三个方向：
   - 设备：异常说明里提到的设备编号，去排产计划里找还有哪些订单排在它上面。
   - 物料：同一种物料出现在几张订单的异常说明里。
   - 外协：同一家外协厂或同一外协工序出现在几张订单里。
11. **逐单写建议措施。** 按原因类别套「行业口径」里的措施方向，再结合这张单的具体情况写一两条；写不出具体措施的写「建议 XX 确认」，不编。
12. **写答复口径。** 每张 A / B 级订单给一段对客户的答复草稿：现状、原因的对外说法、承诺的时间点或下次反馈时间、补救措施。没有经过排产确认的新交期不写具体日期，写「X 日前给出确认交期」。
13. **先核对再成稿。** 把分级表和合并口径先发用户确认；用户改口径（比如窗口改成 10 天、暂停的单算不算）就重算；确认后再出全文和答复口径。

## 行业口径与判断规则

- **三级分法（缺省）**：
  - A 级：已过交期、未发货。
  - B 级：距交期在 0 到 14 天之间（按贵司规定，缺省 14 天）、未发货，并且进度落后或有异常。
  - C 级：有异常但距交期在 14 天以外；现在不急，但异常不处理会变成 B 级。
  - 关注：距交期在 14 天内、进度正常、无异常。列出来让用户知道，但不算风险、不进风险清单。
- **进度落后的判定**：有排产计划的，任一工序「计划结束早于今天、实际未结束」即为落后；只有完成率的，缺省规则是距交期不超过 7 天而完成率低于 70%，或距交期不超过 14 天而完成率低于 50%（按贵司规定，缺省建议）。完成率是按工序数还是按工时算，问用户；成稿时写明。
- **完成率的写法**：0.35 和 35% 可能混在同一列，统一后再比；空白不等于 0，标「未填」。
- **交期是发货日还是到货日**：合同上写的可能是到厂日期，要扣掉运输天数；发往新疆的运输周期和发往广汉、天津的不一样。问用户，缺省按发货日。
- **外协单独一类**：原因在厂外，措施和厂内不同（催外协厂、换外协厂、收回自制）；外协热处理拖期不算「工序拖期」。
- **缺料要算「到货后还要做多久」**：预计到货日加上剩余工序所需天数晚于交期，就是必延，哪怕物料马上到；预计到货日「未确认」的比「晚几天」更严重，要升级。
- **设备故障看连锁**：一台设备停机，排产计划里排在它上面的所有订单都受影响；要把这些订单一起列出来，而不是只列异常说明里提到的那张。
- **优先级排序**：先 A 后 B 后 C；同一级里先看客户重要性和违约条款（用户给），再看距交期天数，再看估计延期天数。
- **估计延期天数**：有排产计划的，用「最晚计划结束 − 合同交期」或拖期工序的拖期天数估；估不出来写「待排产确认」，不编。
- **井下工具的交付常绑着客户的作业窗口**：工具是跟着作业队到井日期走的，错过窗口比晚几天本身更严重。答复口径里要问客户的作业时间；有可调的租赁工具时写成「可与客户商议临时调配」，不写成承诺。
- **答复口径不甩锅**：对客户说原因时不点供应商、外协厂的名字，除非用户要求；不承诺没经排产确认的日期。
- **异常写法合并**要给用户看过再用；同一张单多个异常的按最严重的一类归，其它的在说明里保留。
- **「暂停」订单**：客户要求暂停的不算风险，但要列出暂停起始日和恢复条件；没写的问用户。
- **进度跟踪的更新日期**要看：更新日期比「今天」早一周以上的，完成率可能已经过时，报告里标「进度数据截至 YYYY-MM-DD」。
- **措施方向（按原因）**：缺料找采购要确认到货日并问能否部分到货先开工；工序拖期找车间看能否调机、加班或拆批；设备故障找设备部门要修复时间并看能否转到其它设备；外协找外协厂要回厂日期并评估收回自制。具体怎么调可以转到「排产与瓶颈分析」技能。

## 输出

先给分级表和合并口径，确认后出全文。

```markdown
# 交期风险排查（截至 YYYY-MM-DD，窗口 14 天）

## 一、总览
| 级别 | 订单数 | 订单号 |
| --- | --- | --- |
| A 已过交期未发货 | | |
| B 两周内到期且落后或有异常 | | |
| C 有异常、交期较远 | | |
| 关注（交期近但正常） | | |
一句话总评：共 N 张在产订单，A 级 X 张、B 级 Y 张；主要原因集中在 ……。

## 二、风险订单明细
| 级别 | 订单号 | 客户 | 产品 | 合同交期 | 距今 | 完成率 | 当前工序 | 异常类别 | 异常说明 | 估计延期 | 来源 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
按级别、再按距交期排序；来源写成（订单清单.xlsx › 订单 › 第 N 行；进度跟踪.xlsx › 进度 › 第 M 行）

## 三、异常原因归类
| 原因类别 | 订单数 | 订单号 | 合并的原始写法 |
| --- | --- | --- | --- |
缺料 / 工序拖期 / 设备故障 / 外协 / 其他
连锁影响：
| 连锁点 | 类型（设备 / 物料 / 外协） | 影响订单数 | 订单号 |
| --- | --- | --- | --- |

## 四、逐单建议措施
每张 A / B 级订单一条：订单号 → 卡在哪 → 建议做什么 → 找谁确认 → 什么时候能给出确认交期

## 五、对客户的答复口径（草稿，发送前需确认）
每张 A / B 级订单一段：现状、原因（对外说法）、承诺的时间点或下次反馈时间、补救措施

## 六、关注名单
交期近但进度正常的订单：订单号、交期、完成率，一句「按计划推进，暂不列为风险」

## 七、已延期交付（参考，不计入当前风险）
状态为已发货但发货日期晚于合同交期的订单：订单号、合同交期、实际发货日、延期天数

## 数据来源
文件名、工作表、数据行数；三张表订单号对不上的清单；异常写法合并口径；「今天」和窗口；进度数据的最近更新日期
```

来源写法示例：`DD-xxxx 完成率 60%（进度跟踪.xlsx › 进度 › 第 9 行），合同交期 2026-11-20（订单清单.xlsx › 订单 › 第 6 行）`。

答复口径的写法示例（示意，不是固定原话）：

> 贵司 XX 订单目前完成 N 道工序中的 M 道，因关键锻件到货推迟，预计较合同交期延后约 X 天；我们已安排到货后优先加工，并将于 YYYY-MM-DD 前向贵司确认最终发货日期。如贵司现场作业时间紧，可商议临时调配同规格工具。

## 交付前自检

- [ ] 「今天」和风险窗口是用户给的，不是猜的。
- [ ] 三张表对不上的订单号已列出，没有被悄悄丢掉。
- [ ] 每张风险订单都能回指到订单清单和进度跟踪的行号。
- [ ] 交期近但进度正常、无异常的订单在「关注」里，不在风险清单里。
- [ ] 异常写法的合并口径已列出并经用户认可。
- [ ] 外协没有被归进工序拖期；设备故障的连锁影响已列全。
- [ ] 估计延期天数要么有依据，要么写「待排产确认」。
- [ ] 答复口径里没有未经确认的新交期，没有点供应商、外协厂的名字（除非用户要求）。
- [ ] 「已发货」「暂停」「交期不明」的订单处理方式已向用户说明。
- [ ] 连锁影响里列出的订单都能在排产计划或异常说明里找到依据。

## 边界

- 只排查、归类、给建议，不替用户决定哪张单先做、哪张单放弃；也不下「责任在谁」的结论。
- 答复口径只是草稿，发给客户、通知业务员、改排产计划、在系统里改交期，都要先问用户。
- 不修改用户的原始表格。
- 不估算违约金额；用户给了合同条款，也只做天数计算，金额由用户核。
- 数据对不上、异常说明空白、完成率没更新，如实写在「数据来源」里，不补数、不推测。
