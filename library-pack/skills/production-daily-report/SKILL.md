# 生产日报与周报

把车间报上来的完工数、停机、出勤整理成一份能发给生产例会的日报或周报：产量和计划对得上、停机原因说得清、明天干什么写明白。

## 适用场景

- 每天下班前要一份日报，数据分别在机加、热处理、装配三个车间的报工表里。
- 周五要周报，要把一周的日报合起来看达成率、停机趋势和订单进度。
- 领导问「某张订单做到哪了」，要从报工记录里把工序进度找出来。
- 停机多，想知道是设备坏了、等料、还是在换型。
- 上一期有日报或周报，这期要照同样的格式续写。
- 月底要一份月度汇总，把几周的周报合起来看趋势。

## 需要的输入

| 输入 | 常见形式 | 常见列名（以用户文件为准） |
| --- | --- | --- |
| 报工 / 完工记录 | 每个车间一张表，每行一条报工（通常按工序报） | 日期、车间、班次、订单号、零件 / 产品（零件名称 / 图号）、工序、设备、操作工、计划数量、完工数量（报工数 / 产量）、合格数、不良数、实作工时 |
| 停机记录 | 一张表，每行一次停机 | 日期、车间、设备、开始时间、结束时间、停机时长（小时 / 分钟）、原因类别、原因说明、处理人、状态 |
| 出勤 | 每车间每天一行，或人员名单 | 日期、车间、应到、实到、请假、加班人数、加班小时 |
| 计划 | 日计划或周计划表；没有就用报工表里的「计划数量」列 | 日期、车间、订单号、工序、计划数量 |
| 期间与「今天」 | 用户口头给：日报是哪天、周报是哪周 | — |
| 上一期日报 / 周报 | 可选，当格式参考 | — |
| 投料记录 | 可选，用来算在制品 | 日期、订单号、零件、投料数量 |

缺了哪项，能做到哪一步：

| 缺的输入 | 还能做什么 | 必须注明什么 |
| --- | --- | --- |
| 报工记录 | 做不了，先要 | — |
| 停机记录 | 其余照做 | 停机一节写「本期未提供停机记录」 |
| 出勤 | 其余照做 | 出勤一节省略 |
| 计划 | 只报产量 | 「无计划数据，未算达成率」 |
| 上一期报告 | 用缺省结构 | 「较上期」一列留空 |

## 工作步骤

1. **定期间。** 日报：哪一天、含哪几个班次；周报：缺省周一到周日，用户另说按用户的。用户没给「今天」就问。
2. **读全每个文件。** 看有几张工作表、表头在第几行、末尾有没有合计行；记下每个文件的数据行数。
3. **统一列名和单位。** 「报工数」「完工数量」「产量」对齐成完工数；停机时长有的记分钟有的记小时，统一成小时；对不上的列问用户。
4. **筛本期。** 只保留日期在期间内的记录；夜班跨日的按「行业口径」里的规则归属。范围外的行数报给用户。
5. **按车间汇总产量。** 报工是按工序的，不能把各工序完工数加总当产量；按「订单 × 工序」先汇总，车间产量按本车间最后一道工序（或用户指定的计产工序）的完工数计。
6. **算达成率。** 达成率 = 完工 ÷ 计划；按车间、按订单各一张。分子用合格数还是完工数按「行业口径」。
7. **列订单进度和在制品。** 每张订单当前到哪道工序、本期完工多少、累计完工多少、还剩多少；在制品按车间汇总。
8. **汇总停机。** 原因写法先合并再汇总，合并口径列给用户认可，例如：

   | 归为 | 原始写法举例 |
   | --- | --- |
   | 设备故障 | 导轨报警、液压压力低、报警停机、炉温不稳 |
   | 待料 | 等锻件、毛坯未到、等上道工序 |
   | 换型调机 | 换刀、换工装、首件调试 |
   | 计划保养 | 点检、润滑、定期保养 |
   | 待检验 | 等首件检验、等检验员 |

   合并后按原因类别汇总次数和小时；按设备汇总；同一设备本期停机 2 次以上的单独列出来。
9. **算出勤。** 出勤率 = 实到 ÷ 应到；加班小时按车间汇总。
10. **找异常。** 达成率低于阈值的车间或订单；停机时长超过阈值的设备；不良数明显高的工序（只列数，原因分析交给质量周报）；出勤明显不足的车间。阈值见「行业口径」。
11. **写次日 / 下周计划。** 从计划表里取下一期的计划；本期没完成的转结进去；没有计划表的写「待计划员确认」。
12. **成稿。** 按上一期的章节顺序写；先把产量汇总表和停机汇总表发给用户确认口径，再出全文。

## 行业口径与判断规则

- **产量口径**：报工按工序，一个零件经 6 道工序会被报 6 次；车间产量按最后一道工序（或指定计产工序）计，不把工序报工加总。各工序的报工数留在「订单进度」里看。
- **完工数与合格数**：达成率分子缺省用合格数（按贵司规定）；不良数在日报里只列，不分析原因，原因分析用质量周报。
- **计量单位分车间**：机加按件、热处理按炉批（一炉多少件要在记录里）、装配按台套；汇总时分开列，不换算成同一单位。
- **夜班归属**：缺省按班次开始日期归属（夜班 3 月 10 日 20:00 到 3 月 11 日 8:00 算 3 月 10 日），按贵司规定调整，成稿时写明。
- **停机分类（通用，按贵司规定调整）**：设备故障 / 待料 / 换型调机 / 计划保养 / 无任务 / 待检验 / 其它。设备故障和待料是生产例会最关心的两类，分开列；计划保养不算异常停机，但在汇总里单列。
- **停机时长**：有开始、结束时间的按时间差算；和记录里的时长对不上时以时间差为准并注明；跨班次的停机按班次拆开。
- **周报的达成率**按周合计算（周完工 ÷ 周计划），不是把每天的达成率平均。
- **在制品** = 已投入 − 已完成最后工序；没有投料记录的按报工推算并注明「按报工推算」。
- **人均产出**不要乱算：不同车间、不同产品不可比；只在同车间同产品时才算。
- **异常阈值（缺省建议，按贵司规定）**：达成率低于 80% 的车间或订单；单台设备本期停机超过 4 小时（日报）或 8 小时（周报）；出勤率低于 90%。
- **较上期**：周报要和上周比（达成率升降、停机小时增减）；日报有上一日数据时也比一下。
- **月度汇总**：把几周的周报合起来时，产量按月合计、达成率按月合计算，停机按月按类别累计；不要把周达成率平均。
- **报工记录里的重复行**（同一订单同一工序同一天报了两次）要列给用户确认是补报还是重复。
- **常见坑**：
  - 报工表的「计划数量」是当天计划还是订单总量，两种都见过；问清楚再算达成率。
  - 完工数量填的是累计数不是当天数；看前后几天是否单调递增就能发现。
  - 停机记录只有「开始时间」没有「结束时间」的，是还没恢复；写「停机中，时长截至 YYYY-MM-DD HH:MM」。
  - 出勤表里的「实到」有时包含借调人员，按贵司口径决定算不算本车间。
  - 热处理一炉里混了几张订单的零件，报工按炉记，订单进度要按炉内明细拆。

来源写法示例：`机加车间完工 118 件（报工记录-机加车间.xlsx › 报工 › 第 2 到 31 行，按最后工序计）`。

「较上期」一列的写法：`+3.5 个百分点` 或 `−2 h`，没有上期数据就留空并在数据来源里说明。

日报和周报用同一套章节，周报多一节「本周趋势」：逐日达成率、逐日停机小时各一行，连续三天下滑的标出来。

## 交付前自检

- [ ] 产量没有把工序报工加总；计产工序已声明。
- [ ] 达成率的分子分母口径已声明，周报按周合计算。
- [ ] 停机小时总和能对到停机记录；计划保养单列。
- [ ] 夜班归属按声明的规则，范围外的行数已报给用户。
- [ ] 每条异常都能回指到记录行号；措施引用的是记录原话。
- [ ] 次日 / 下周计划来自计划表或标了「待确认」；本期未完成的已转结。
- [ ] 热处理、装配的单位没有和机加混着加。
- [ ] 上一期报告提到的异常，本期有「已解决 / 仍在」的交代。
- [ ] 停机原因的合并口径已列出并经用户认可。
- [ ] 还没恢复的停机标了「停机中」，没有按已结束算时长。
- [ ] 周报有「本周趋势」一节，连续下滑的已标出。

## 边界

- 只汇总和陈述，不下「谁的责任」的结论；原因引用停机记录和报工备注的原话。
- 不修改用户的原始报工、停机、出勤记录。
- 发送日报、写入 MES 或 ERP、通知车间主任，都要先问用户。
- 数据缺口（某车间没报工、某天没记录）如实写在「数据来源」里，不补数。
- 不良原因分析不在这里做，转质量周报。
- 不算人工成本、加班费；只报小时数。
