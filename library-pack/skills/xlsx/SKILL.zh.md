# XLSX 的创建、编辑与分析

| 任务 | 方法 |
|---|---|
| 对公式/格式进行**创建或编辑** | `openpyxl`——参见下文的注意事项 |
| 批量数据的**导入或导出** | `pandas`（`read_excel`、`to_excel`） |
| 对某个工作表进行**快速查看** | `markitdown file.xlsx`——每个工作表对应一个 `## SheetName`；也能读取 `.xlsm`。不含单元格坐标，因此不要据此规划编辑 |
| 模型的**读取**（须同时得到公式与值） | 两次 `load_workbook` 读取——参见下文的注意事项 |

> `openpyxl`、`pandas` 与 `markitdown` 均已预装——不要先运行
> `uv pip install`；直接编写脚本并导入即可。仅当导入失败（或
> `markitdown` 命令不存在）时，才 `uv pip install` 缺失的包。

> 下文的脚本路径均相对于本技能所在目录。

## 每份输出都必须满足的要求

- 通篇使用**专业字体**（Arial、Times New Roman），除非用户另有说明。
- **公式错误数为零**：只要 `recalc.py` 报告 `errors_found`，就绝不能交付。如果你认为某个错误在你介入之前就已存在，需要证明这一点：用 `data_only=True` 加载*原始*文件，查看该单元格。你引入的错误，看起来会和继承来的错误一模一样。
- **使用公式，绝不使用写死的结果**。应写 `sheet['B10'] = '=SUM(B2:B9)'`，而不是用 Python 算好的合计数。工作表必须能在输入变化时重新计算。
- **严格按照用户的要求执行**：确切的工作表名、确切的列标题，以及用户明确写出的公式。即便重新设计后的方案更精巧，只要算的是别的东西，就算失败。
- **在读者能看到的地方，记录每一个假设与写死的数字**——单元格批注，或表格末尾相邻的单元格。若存在真实来源，予以引用（`Source: Company 10-K, FY2024, Page 45, Revenue Note, [SEC EDGAR URL]`）；若数字来自用户，也要明确注明。
- **由你创建、供他人填写的工作簿**，需要一份简短图例，说明应编辑哪些单元格，并给出一行使用真实数值的示例，展示预期格式。对于用户要求你编辑的既有文件，绝不能添加这样的示例行。
- **编辑既有文件时：严格匹配其现有约定**，这一点凌驾于本文档的所有其他准则之上。先找出其指定的输入单元格——通常以特定的字体颜色、填充色或底纹标记——只在那里写入，并保持所有既有公式不变。

## 重新计算（只要文件包含公式，就必须执行）

openpyxl 把公式写成字符串，**不含缓存值**。在你重新计算之前，任何
读取缓存值的工具——`pandas`、`load_workbook(data_only=True)`，以及
大多数预览工具——读到的每个公式单元格都会是 `None`。

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # default 30
```

LibreOffice 会计算每一个公式，文件会被**原地重写**，然后你会得到一段
JSON：`status`（`success` | `errors_found`）、`total_formulas`、
`total_errors`，以及一个 `error_summary`，其中按错误类型列出最多
100 个单元格（`locations_truncated` 说明还有多少未被列出——要信任
`total_errors`，而不是列表的长度）。修复它指出的问题后再次运行。
**如果 JSON 里出现的是 `error` 键而不是 `status` 键，说明什么都没有
被重新计算**，而且只有这种情况才会以非零状态退出——`errors_found`
的退出码是 0，所以绝不能把干净的退出码当作工作簿本身没问题的证明。

**重新计算通过，只能证明你的公式能够求值，而不能证明它是正确的**。
一个偏移一行的范围，或引用了错误的行，都会得到一份干净、没有错误、
但数字错误的文件。在搭建整张表格之前，先写 2–3 个公式，检查它们
取到的确实是你预期的值。

**链接到另一个文件的工作簿会丢失这些链接**，前提是你用 openpyxl
重新保存后再重新计算。这样的公式读起来是
`='[1]Returns Analysis'!$B$2`——其中的 `[1]` 是该工作簿外部引用
列表中的一个索引，指向*磁盘上的另一个独立文件*，而不是某个工作表。
那个文件在这里通常并不存在，所以该单元格的缓存值是保存其数据的
唯一凭借。openpyxl 在保存时会剥离该缓存值；随后 LibreOffice 就必须
真正去解析该引用，结果失败，写入 `#NAME?`，并删除每一个链接。
`recalc.py` 在这种状态下会拒绝运行——在你覆盖保存原始文件之前，
先把那些单元格的值复制出来（`--force` 可以覆盖此行为，并接受这一
损失）。

## 挑选能通过验证的公式

LibreOffice 实现的函数比 Excel 少，凡是它无法求值的函数，都会在
你交付的文件中变成字面意义上的 `#NAME?`。

- **优先使用 Excel 2007 时代的函数**——`SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT`——这些函数不需要加前缀。
- **有六个 2007 年之后新增的函数可以使用，但必须带上 `_xlfn.` 前缀**，因为 openpyxl 会把公式原样写入 XML，而 Excel 存储 2007 年之后的函数名时会加前缀（只是其界面把前缀隐藏了）：`_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。若不加前缀直接写，每一个都会得到 `#NAME?`。
- **绝不要使用 `XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE` 或 `SEQUENCE`**。该运行环境所用的 LibreOffice 无论加*任何*前缀都无法对它们求值。较新的版本确实能对它们求值，但它们属于溢出型数组函数，而 openpyxl 写出的文件不含溢出元数据，因此该区域只有左上角的单元格会得到值——而 `recalc.py` 会在这个被截断的结果上报告 `total_errors: 0`。查找请改用 `INDEX`/`MATCH`，排序、筛选与去重则在写入单元格之前用 Python 完成。
- LibreOffice 无法解析的公式，写回时会变成**全部小写**——这是除了 `#NAME?` 之外的另一个快速识别标志。

## openpyxl 的注意事项

- **读取一个模型需要加载两次**。`data_only=True` 得到的是缓存值，公式本身消失了；默认方式得到的是公式字符串，没有值。一次读取无法同时得到两者。
- **`data_only=True` 如果之后保存，会具有破坏性**。该工作簿届时已不再含有任何公式，所以保存会把每一个公式都永久替换为字面值。
- **对刚被 openpyxl 写出的文件使用 `data_only=True`，处处都会返回 `None`**——请先运行 `recalc.py`。（结果为 `""` 的公式，读回来同样是 `None`。）
- **合并单元格：只写入左上角的锚点单元格**。该区域内其余每个单元格都是 `MergedCell`，其 `.value` 为只读。
- **`.xlsm` 会丢失其宏，除非向 `load_workbook` 传入 `keep_vba=True`**。
- **含空格的工作表名，在跨表引用中必须加引号**：`='Assumptions Inputs'!$B$5`。不加引号，会得到 `#VALUE!`。

## 财务模型

除非用户另有要求，或既有文件已经采用了其他做法。

**颜色**：蓝色文字（`0,0,255`）用于写死的输入项与情景杠杆变量；黑色
用于公式；绿色（`0,128,0`）用于指向另一个工作表的链接；红色
（`255,0,0`）用于指向另一个文件的链接；黄色填充（`255,255,0`）用于
关键假设，以及需要用户填写的单元格。

**数字**：货币格式 `$#,##0`，并在表头注明单位（如 `Revenue ($mm)`）；
零值显示为 `-`，百分比中的零值同样如此（`$#,##0;($#,##0);-`）；
负数用括号表示；百分比格式 `0.0%`，**以小数形式存储**（存储
`0.15` 会显示为 `15.0%`；存储 `15` 会显示为 `1500.0%`）；估值倍数
`0.0x`；年份以文本形式存储（`"2024"`，绝不能是 `2,024`）。

**结构**：每个假设都放在专属的带标签单元格中，由用到它的公式引用
（`=B5*(1+$B$6)`，绝不写 `=B5*1.05`）；同一投影区间内所有周期的公式
保持一致，因为行中孤立地改动某一个单元格，是最常见的隐性错误；对
可能为零的分母加以防护。
