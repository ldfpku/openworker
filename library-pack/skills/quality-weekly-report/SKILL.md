# 质量周报

把一周的检验记录和不良品处理单变成一份能直接发给生产例会的周报：数字对得上、问题点得出来、下周该盯什么写清楚。

## 适用场景

- 每周例会前要一份质量周报，数据散在几个车间的检验记录表里。
- 想知道本周合格率、不良件数、哪类不良最多、哪台设备出问题最多。
- 怀疑某个问题「上周就有、这周又来了」，要有数据证明。
- 不良品处理单开了一堆，想知道哪些还没关闭、原因分析到了哪一步。
- 上周有周报，这周要照着同样的格式续写。

## 需要的输入

| 输入 | 常见形式 | 常见列名（以用户文件为准） |
| --- | --- | --- |
| 检验记录 | 每个车间一个 Excel，每行一个送检批次 | 日期、车间、设备（设备编号）、零件（零件名称 / 图号）、工序、送检数（送检数量 / 数量）、不良数（不良数量 / 不合格数）、不良类型（不良描述 / 缺陷）、处置（返修 / 报废 / 让步接收）、检验员 |
| 不良品处理单 | 一张表，每行一张单 | 单号、日期、车间、设备、零件、不良描述、数量、原因分析、纠正措施、责任人、状态（已关闭 / 处理中） |
| 上周周报 | Word 或 Markdown，当格式参考 | — |
| 本周范围 | 用户口头给：第几周、起止日期、「今天」是哪天 | — |

缺检验记录就做不了，先要；缺处理单可以出周报，但「问题闭环」一节要注明「本周未提供处理单」；缺上周周报就用下面「输出」里的缺省结构。

## 工作步骤

1. **定范围。** 确认本周的起止日期和周次（如 2026-09-28 至 2026-10-02，第 40 周）。用户没说就问，不要自己猜「今天」。
2. **读全每个文件。** 逐个打开，先看有几张工作表、表头在第几行、最后有没有合计行。把每个文件的数据行数记下来，成稿时写进「数据来源」。
3. **统一列名。** 把各车间文件里意思相同、写法不同的列对齐（「送检数量」=「送检数」，「不合格数」=「不良数」）。对不上的列问用户，不要猜。
4. **筛出本周。** 只保留日期落在本周范围内的记录；把范围外的行数报给用户（「机加车间文件里有 3 行是上周的，未计入」）。
5. **按车间汇总。** 每个车间：送检合计、不良合计、返修件数、报废件数、让步件数；全厂合计；合格率 =（送检 − 不良）÷ 送检。
6. **不良类型 Pareto。** 按不良类型汇总件数，从多到少排；再按设备、按零件各排一次。前三名要写出具体是哪几行记录。
7. **找重复问题。** 同一「设备 × 不良类型」在本周出现 ≥ 2 次（不同日期）就算重复；列出每次的日期、零件、数量、处置。有上周周报的，把上周提到的问题逐条对照：本周还在不在、是多了还是少了。
8. **找趋势。** 同一不良类型按日排列，连续 3 天以上递增、或本周合计比上周翻倍，标为「恶化趋势」。
9. **核处理单。** 处理单按状态分「已关闭 / 处理中」；处理中的按开单日期算已挂了几天；同一设备多张单的，把原因分析按时间排一遍，看分析有没有在深入、有没有「换了措施还复发」的情况。
10. **成稿。** 按上周周报的章节顺序写；没有就用缺省结构。每个数字后面能回指到「文件 › 工作表 › 行号」。
11. **给用户核对。** 先把汇总表和前三个问题发给用户确认口径，再出全文；用户要改口径（比如让步接收算不算不良），改完重新汇总。

## 行业口径与判断规则

- **合格率**：缺省按「（送检 − 不良）÷ 送检」，以件数计；按批次计或扣除让步接收，按贵司规定，成稿时写明口径。
- **不良率的分母**是送检数不是产量；产量数据在生产日报里，别混用。
- **返修与报废**分开统计：返修件回流后要再检，报废件直接进成本，例会上关心的是报废。
- **重复出现**的判定看「设备 × 不良类型」，不看零件：同一台车床加工不同零件出同一种超差，是设备或刀具的问题，不是零件的问题。
- **换过措施仍复发**（处理单写了「已更换刀片」，下周同一不良又出现）要单独点出来：说明原因没找对，下一步应该查更上游的因素（刀补、主轴跳动、卡盘、程序、材料批次）。
- **热处理类不良**（硬度不合格、金相不合格）逐日上升时，优先怀疑设备状态（温控仪表漂移、炉温均匀性）而不是操作，周报里写成「建议核查 XX 炉温控仪表」而不是下结论。
- **让步接收**不是合格，也不是返修；单列一行，别并进合格数。
- **数量单位**：有的车间按件、有的按批（一批 N 件），汇总前统一成件；统一不了就分开列并注明。
- 同一问题在不同车间文件里写法不同（「螺纹中径超差」「中径超差」「螺纹超差」），合并前把合并口径列出来让用户认可。

## 输出

缺省结构（有上周周报就沿用它的章节和标题）：

```markdown
# 质量周报（第 N 周：YYYY-MM-DD 至 YYYY-MM-DD）

## 一、本周概况
| 车间 | 送检 | 不良 | 返修 | 报废 | 让步 | 合格率 |
| --- | --- | --- | --- | --- | --- | --- |
| 机加车间 | 600 | 16 | 15 | 1 | 0 | 97.3% |
| … | | | | | | |
| **合计** | | | | | | |
一句话总评：合格率较上周（X%）升/降 Y 个百分点；报废 Z 件，集中在 ……。

## 二、不良分布
按不良类型（前 5）：类型、件数、占比、涉及设备
按设备（前 3）：设备、不良件数、主要不良类型
按零件（前 3）

## 三、重复出现的问题
每条：设备 × 不良类型 → 出现日期和件数（逐次列出，带行号）→ 处理单编号与状态 → 已采取措施 → 是否复发 → 建议下一步

## 四、趋势预警
逐日递增或较上周翻倍的不良类型，列出每日件数和涉及设备

## 五、不良品处理单闭环
| 单号 | 日期 | 设备 | 不良 | 数量 | 原因分析 | 状态 | 已挂天数 |
处理中的单按已挂天数排序；超过 7 天（按贵司规定）的标为逾期

## 六、下周关注点
3–5 条，每条写清「盯什么、谁盯、怎么算关闭」

## 数据来源
文件名、工作表、数据行数、本周范围内行数；合并口径说明
```

数字后面的来源写法：`（检验记录-机加车间.xlsx › 检验记录 › 第 2、7、17、22 行）`。

## 交付前自检

- [ ] 合计数能从各车间数加出来，合格率的分子分母和口径说明一致。
- [ ] 每个「重复出现」的问题都列了具体行号，次数 ≥ 2 且日期不同。
- [ ] 上周周报提到的每个问题，本周都有「还在 / 已消失 / 加重」的交代。
- [ ] 处理单的状态和已挂天数按用户给的「今天」计算。
- [ ] 合并过的不良类型写法已列出并经用户认可。
- [ ] 没有凭印象写的数字；没有数据支撑的判断写成「建议核查」。
- [ ] 下周关注点每条都能检查是否完成。

## 边界

- 只汇总和分析，不替用户下「责任在谁」的结论；原因分析引用处理单上的原话。
- 不修改用户的原始检验记录和处理单。
- 发送周报、写入系统、通知责任人，都要先问用户。
- 数据缺口（某车间没交记录、某天没有检验）如实写在「数据来源」里，不补数。
