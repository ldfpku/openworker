# Market Research Reports(市场研究报告)

## 目的

创建以决策为导向的市场报告，其中的论断、计算、假设和不确定性都可被审计。
让深度和格式与问题及证据相匹配。没有硬性规定的篇幅、章节数、图表数量或
输出格式。

不要:

- 模仿或暗示与某个咨询、分析师或研究机构品牌存在关联;
- 编造引用、引语、市场份额或付费市场数据;
- 把 TAM/SAM/SOM 或某个预测呈现为唯一确定的真相;
- 把某个框架、图表或流畅的叙述本身当作证据;
- 提供投资、法律、反垄断、税务、会计或监管方面的建议。

## 运作原则

1. **先定义，后测算**。 明确产品、客户、地理范围、渠道、期间、
   度量指标、单位、分母、货币/基准年以及分类体系(taxonomy)。
2. **给每一条论断建立映射**。 每一条事实性或量化的论断都要有一个论断 ID
   和确切的来源 ID。
3. **区分陈述类型**。 区分事实、估计、计算、预测、观点和建议。
4. **优先使用一手证据**。 在使用二手综合资料之前，优先使用官方统计数据、
   监管机构记录、公司披露的备案文件，以及方法透明的原始研究。
5. **保留不确定性**。 保留来源之间的冲突、数据修订、情景区间、
   敏感性以及局限性。
6. **保持方法可复现**。 在可行的情况下使用本地结构化输入和确定性计算。
7. **合法、合乎道德地收集数据**。 不得欺骗、不得披露 PII(个人身份信息)、
   不得规避访问限制、不得获取机密材料或商业秘密。

## 工作流程

### 1. 确立研究契约

厘清以下事项:

- 决策、受众、截止时间和重要性阈值;
- 正式的市场定义及相邻的排除范围;
- 买方、付费方、用户、交易层级以及价值链层级;
- 地理范围，以及对进口、出口和渠道的处理方式;
- 历史期间、预测期间和数据检索截止日期;
- 是收入/支出、总产出/增加值、单位数量、产能、用户数,
  还是其他度量指标;
- 存量/流量、总额/净额、税项和分母;
- 货币、基准年，以及名义/实际/现价/不变价基础;
- 行业和产品分类及其版本;
- 允许使用的数据源、一手研究、保密性以及输出格式。

当缺失某个选择会实质性地改变分母或结果时，提出一个有针对性的问题。
否则，先陈述一个临时的范围界定，然后继续推进。

模块化报告设计使用 `references/report_structure_guide.md`。

### 2. 制定证据获取计划

将每个问题路由到最接近底层事件本身的来源:

1. 一手法律法规、监管机构裁定、官方备案文件，或官方统计数据;
2. 公司原始备案文件，或可归因的一手披露资料;
3. 方法公开、可核查的调查/研究;
4. 使用可辨识一手数据的机构或同行评审研究;
5. 覆盖范围公开的行业协会数据;
6. 可靠的二手综合资料;
7. 合法获取的、范围与方法可核查的付费估计数据;
8. 用于寻找线索或可归因事件的新闻/评论。

对于公司数据，优先使用相关司法辖区的官方备案系统。对于行业、劳动力、
价格、人口、贸易和国民账户数据，优先使用负责任的国家统计机构或
中央银行。对于跨国比较工作，只有在核实了定义和原始来源脉络之后,
才使用经协调统一的世界银行、IMF、OECD 或 Eurostat 数据。

在使用公共 API 之前，阅读 `references/official_data_sources.md`。API 规则
和限制只是某一时点的快照:在进行自动化或大批量检索之前，请核实当前的
官方条款。切勿把 API 密钥写入报告或打包的脚本中。

### 3. 创建来源台账(source ledger)

分配稳定的 ID(`S-001`、`S-002`、……)。记录:

- 标题、发布方、URL/永久标识符、来源类型;
- 发布日期和检索日期;
- 若通过聚合平台获取，记录原始生产方;
- 地理范围、覆盖人群、期间和数据版本(vintage);
- 货币、基准年、价格基础、度量类型、单位和分母;
- 分类体系及其版本;
- 初步/修订/最终/当前 状态;
- 方法、样本、插补、屏蔽处理以及局限性;
- 许可/条款，以及合法的本地快照存档路径。

使用 `assets/source_ledger_template.csv` 并对其进行校验:

```bash
python3 scripts/validate_evidence_ledger.py data/source_ledger.csv
```

如果发布日期不可得，记为 `not-stated`;不要猜测。

### 4. 维护论断台账(claims ledger)

分配 ID(`C-001`、……)。保留确切的论断原文、陈述类型、来源
ID、报告中的位置、截止日期(as-of date)、地理范围、货币/基准年、
度量指标/单位、分类体系、修订状态、置信度、计算 ID 以及假设 ID。

规则:

- 段落末尾的单一引用不能用来支撑与之无关的句子;
- 拆分依赖不同证据的复合论断;
- 一项计算应引用它的输入数据，而不是从未发布过该计算结果的来源;
- 聚合平台及其原始来源不构成独立的相互印证;
- 一个访谈主题不代表总体人群中的普遍程度;
- 缺少公开的功能证据意味着「未知(unknown)」,而不是「没有(no)」。

审计映射关系:

```bash
python3 scripts/audit_claim_citations.py \
  data/claims.csv data/source_ledger.csv
```

参见 `references/evidence_model.md`。

### 5. 以情景方式测算市场规模

#### 度量护栏(measurement guardrails)

为每个组成部分设定互不重叠的 `coverage_key`,以及一个共享的
`denominator_id`。不要把以下内容相加:

- 制造商收入与分销商或终端客户支出;
- 未经贸易/库存调节的生产量、进口量与销售量;
- 母公司与子公司的收入;
- 捆绑套餐与其所包含的组成部分;
- 总产出与增加值;
- 存量式的已安装基数与年度交易流量;
- 相互重叠的客户或地理细分市场。

当行业代码过于宽泛时，使用产品分类和供需(supply-use)逻辑。
保留一个未知/剩余类别，而不是强行凑出总数。

#### 自上而下与自下而上

分别独立计算:

```text
TAM_top = sum(disjoint in-scope component values)

TAM_bottom =
  sum(customer_count
      * addressable_fraction
      * annual_quantity_per_customer
      * price_per_unit)
```

然后应用特定情景下的可服务性和渗透假设:

```text
SAM_s = TAM * serviceable_fraction_s
SOM_s = SAM_s * obtainable_share_s
```

至少使用两个真正不同的情景；下行/基准/上行的三情景组合通常很有用。
陈述时间跨度、约束条件、证据和假设。SOM 并非有保证的收入预测。

运行确定性计算器:

```bash
python3 scripts/calculate_market_sizing.py \
  assets/market_sizing_scenarios_template.json
```

报告两种方法的结果、相对于中点的差距、范围差异、敏感性，以及
尚未调和的分歧。不要对不兼容的方法取平均值。

### 6. 在明确不确定性的前提下做预测

将已观测期间、估计期间和预测期间区分开来。记录序列 ID、
频率、单位、季节调整、数据变换、分类体系断点、检索日期,
以及数据版本/修订情况。

针对每个情景:

- 提供年度增长率路径或驱动因素方程;
- 陈述需求、价格、供给、监管、竞争、产能和时点方面的假设;
- 列出证据 ID 和假设 ID;
- 指出会使该情景失效的条件。

不要把情景边界称作置信区间或预测区间。在没有经过验证的概率模型
和诊断检验的情况下，不要赋予概率。

运行:

```bash
python3 scripts/forecast_sensitivity.py \
  assets/forecast_sensitivity_template.json
```

按年份展示区间范围、端点敏感性、有影响力的假设，以及切换值
(switching values)。参见 `references/data_analysis_patterns.md`。

### 7. 分析客户与一手研究

对于调查证据，披露赞助方、目标人群、抽样框、概率/非概率抽样设计、
招募方式、方式/语言、调查日期、未加权样本量、各子群体的样本基数、
加权方法、应答率/参与率、题项措辞、精度、数据处理过程以及局限性。

对于访谈/焦点小组，披露招募方式、知情同意、角色覆盖情况、
日期/形式、访谈提纲、编码方式、存在分歧的证据、隐私保护措施,
以及推广至总体的局限性。

切勿:

- 收集超过必要限度的个人数据;
- 在报告成果物中放入直接识别信息或原始录音;
- 把研究当作变相的推销或获客手段;
- 谎报身份/目的;
- 迫使参与者透露雇主/客户的秘密;
- 把定性提及次数当作市场普遍程度来报告。

遵循 `references/methods_and_ethics.md`。

### 8. 分析竞争对手与市场集中度

在选择竞争对手或计算市场份额之前，先从客户视角定义产品和地理范围。
在相关的情况下，考虑非价格维度、渠道、进口、数字化/多边平台特性,
以及创新与动态变化。

使用合法的公开证据，并采用统一的产品版本、地理范围和截止日期。
校验一份完整的矩阵:

```bash
python3 scripts/validate_competitor_matrix.py \
  assets/competitor_feature_matrix_template.csv \
  --source-ledger assets/source_ledger_template.csv
```

对于市场份额，应陈述所用指标(收入/单位数/产能/用户数或其他)、
分母、期间、剩余份额以及来源覆盖范围。HHI/CRn 是描述性的筛选工具,
而非法律结论。一个 TAM 类别不会自动构成反垄断意义上的相关市场。

### 9. 统一单位与定义

在合并数值之前:

- 对齐地理范围、期间、存量/流量、总额/净额、单位和分母;
- 使用明确标注的来源和汇率约定进行货币换算;
- 对齐基准年以及名义/实际基础;
- 不要强行对链式美元(chained-dollar)数值做可加性处理;
- 保留分类体系的版本信息，并记录对应关系(concordance)的不确定性;
- 把每一次换算都作为一次计算记录下来。

检查比较组:

```bash
python3 scripts/check_unit_consistency.py \
  assets/consistency_check_template.csv
```

### 10. 起草与审阅

以发现和不确定性为先导，而不是以框架为先导。可选的框架仅用于
组织问题；不要强行给出评分或固定数量的因素。让建议与证据保持
分离，并包含依赖关系、权衡取舍、决策阈值以及反证性证据。

可视化图表是可选的。如果使用，要基于经过验证的本地数据构建,
并包含范围、单位、来源 ID、计算 ID、已观测/预测的区分，以及
局限性。参见 `references/visual_generation_guide.md`。

生成一个 Markdown 工作区:

```bash
python3 scripts/generate_report_scaffold.py \
  assets/report_manifest_template.json ./market-report-workspace
```

或使用可选的 LaTeX 素材:

- `assets/market_report_template.tex`
- `assets/market_research.sty`
- `assets/FORMATTING_GUIDE.md`

## 发布关卡(release gate)

- 市场边界、分类体系、分母、地理范围和期间都已明确说明。
- 每一条事实性/量化论断都映射到确切的来源 ID。
- 发布/检索日期、修订情况、方法以及局限性均已记录。
- 货币/基准年、名义/实际基础、存量/流量以及单位保持一致。
- 自上而下与自下而上两种方法使用互不重叠的覆盖范围，并已相互调和。
- TAM/SAM/SOM 及预测均为附带敏感性分析的条件性情景。
- 调查/访谈证据附带方法说明、隐私保护措施以及推断的局限性。
- 竞争对手证据合法、注明日期、界定了范围，并诚实地使用「未知(unknown)」标注。
- 来源之间的冲突和数据修订保持可见。
- 不出现捏造/无支撑的付费数据、PII、商业秘密、欺骗性数据收集、
  品牌冒充，或投资建议式的表述。

### 模板与命令行工具

将 `assets/` 中的模板作为合成用的模式(schema)使用，而非真实世界的证据。
`scripts/` 中的所有脚本都是仅使用标准库、有边界、仅在本地运行的工具。
它们会拒绝过大或格式错误的输入，不跟随符号链接形式的输入，未经明确
许可不会覆盖输出文件，并且不发起任何网络请求、LLM 调用、图像调用、
动态求值(dynamic-evaluation)或 pickle 调用。
