# What-If Oracle —— 可能性空间探索器

一套通过严谨的多分支情景分析来探索不确定未来的结构化系统。Oracle 不会只给出单一预测，而是绘制出完整的**可能性空间（possibility space）**——一组分支时间线，其中每条路径都拥有自己的逻辑、概率和后果。

其基础是 What-If 范式（What-If Paradigm）:该理念认为，推测性的问题("假如 X 会怎样?")并非空想白日梦，而是一种**基本的计算操作（fundamental computing operation）**——是心智在把资源投入某一条路径之前，用来模拟各种未来的方式。

已发表的研究:[The What-If Paradigm (DOI: 10.5281/zenodo.18736841)](https://doi.org/10.5281/zenodo.18736841) | [IDNA v2 / Unified Digital Consciousness Theory (DOI: 10.5281/zenodo.18807387)](https://doi.org/10.5281/zenodo.18807387)

## 何时使用本技能

在用户出现以下情况时使用 Oracle:

- 提出"假如……会怎样"、"如果……会发生什么",或"探索一下各种可能性"
- 面临一个没有明显答案的岔路口式决策
- 想要带有概率的最好情况/最坏情况/可能情况分析
- 需要应急预案、风险图谱，或战略选项对比
- 想要对某个想法进行压力测试，或者思考其二阶后果

关于特定领域的框架设定（创业公司、技术架构、危机应对等）,见 [references/scenario-templates.md](references/scenario-templates.md)。

## 核心原则:0·IF·1

每一次情景分析都包含三个要素:

- **0** —— 未表达的状态（尚未发生的事情，即潜在可能性）
- **1** —— 已表达的状态（当下的实际状态，即当前现实）
- **IF** —— 条件性纽带（把 0 转变为 1 的那个决策、事件或变化）

分析的质量取决于 IF 的精确程度。一个含糊的"假如事情出了岔子会怎样?"只会产生含糊的结果。而一个精确的"假如我们的主要供应商在第三季度把价格上调 30% 会怎样?"则会产生可付诸行动的洞见。

## 如何运行 Oracle

### 第一阶段 —— 界定问题

拿到用户的 What-If 问题，并将其打磨得更精确:

**拆解为若干组成部分**:

- **变量（The Variable）**： 具体是什么发生了变化?（每次分析只针对一个变量）
- **幅度（The Magnitude）**： 变化幅度有多大?（尽可能量化）
- **时间范围（The Timeframe）**： 在多长的时间跨度内?
- **背景（The Context）**： 在变化发生之前，当前的状态是什么?

**如果问题含糊不清，将其打磨得更精确**:

- "假如 AI 接管一切会怎样?" → "假如在 [某个具体行业] 中，当前 40% 的知识型工作任务在 3 年内被 AI 自动化，会怎样?"
- "假如我们失败了会怎样?" → "假如从现在起，月收入连续 6 个月保持在 5000 美元以下，会怎样?"

在继续之前，把打磨后的问题呈现给用户以确认。

### 第二阶段 —— 绘制可能性空间

使用以下框架生成 **4-6 条情景分支**:

| 分支             | 定义                                                                   | 目的                                            |
| ------------------ | ---------------------------------------------------------------------------- | -------------------------------------------------- |
| **Ω 最好情况**    | 一切都顺利。所有关键假设都得到验证。运气眷顾。     | 界定上限——最大的上行空间是多少?    |
| **α 可能情况**  | 基于当前证据最可能发生的路径。没有重大意外。               | 把预期锚定在现实中                     |
| **Δ 最坏情况**   | 关键假设落空。有两件事同时出了岔子。                    | 界定下限——最大的下行风险是多少?    |
| **Ψ 黑天鹅（Wild Card）**    | 出现了一个没有任何人在追踪的意外变量。属于黑天鹅领域。 | 对不可想象的情况进行压力测试                   |
| **Φ 逆向思维（Contrarian）**   | 与共识观点相反的情况反而成真。                     | 挑战群体思维，揭示隐藏假设 |
| **∞ 二阶效应（Second Order）** | 一阶效应引发了没有人预料到的连锁后果。     | 描绘涟漪效应                                    |

### 第三阶段 —— 分析每一条分支

对每一条情景分支，提供以下内容:

```
╔══════════════════════════════════════════════╗
║  BRANCH: [Ω/α/Δ/Ψ/Φ/∞] — [Branch Name]    ║
╠══════════════════════════════════════════════╣
║  Probability: [X%]                           ║
║  Timeframe: [When this could materialize]    ║
║  Confidence: [HIGH/MEDIUM/LOW]               ║
╠══════════════════════════════════════════════╣
║  NARRATIVE:                                  ║
║  [2-3 sentences describing how this          ║
║   scenario unfolds step by step]             ║
║                                              ║
║  KEY ASSUMPTIONS:                            ║
║  • [What must be true for this to happen]    ║
║  • [And this]                                ║
║                                              ║
║  TRIGGER CONDITIONS:                         ║
║  • [Early signal that this branch is         ║
║    becoming reality]                         ║
║  • [Second signal]                           ║
║                                              ║
║  CONSEQUENCES:                               ║
║  → Immediate: [What happens first]           ║
║  → 30 days: [What follows]                   ║
║  → 6 months: [Where it leads]               ║
║                                              ║
║  REQUIRED RESPONSE:                          ║
║  [What action to take if this branch         ║
║   activates — specific, actionable]          ║
║                                              ║
║  WHAT MOST PEOPLE MISS:                      ║
║  [The non-obvious insight about this         ║
║   scenario that conventional analysis        ║
║   would overlook]                            ║
╚══════════════════════════════════════════════╝
```

### 第四阶段 —— 综合

在分析完所有分支之后，提供以下内容:

**概率分布**：

```
Ω Best Case ····· [██████░░░░] 15%
α Likely Case ··· [████████░░] 45%
Δ Worst Case ···· [██████░░░░] 20%
Ψ Wild Card ····· [███░░░░░░░]  8%
Φ Contrarian ···· [████░░░░░░]  7%
∞ Second Order ·· [███░░░░░░░]  5%
```

**稳健行动（Robust Actions）**： 哪些行动在*多条*分支下都是有益的?这些就是"无悔之举"——无论哪种未来成为现实，都应该去做。

**对冲行动（Hedge Actions）**： 哪些准备工作能够在不牺牲上行空间的前提下，防范最坏的几条分支?

**决策触发点（Decision Triggers）**： 哪些具体的、可观察的信号，应当促使你更新"哪条分支最可能发生"的判断?界定出这些绊线（tripwire）。

**1% 洞见（The 1% Insight）**： 关于这个情况，几乎所有分析者都会错过的那一件事是什么?那个不明显的模式、隐藏的假设，或被忽略的变量。

## 黄金比例权重法

当已有证据支持时，用黄金比例来为主要情景分配权重:

- **主要未来（最可能）**： 分配 61.8% 的关注度/资源
- **备选未来**： 分配 38.2% 的关注度/资源

这样既能防止对单一路径过度投入，也能防止在过多的应急预案之间被稀释。自然界的分支结构（树木、河流、血管）就采用这一比例。战略规划也同样适用。

## 模式

### 快速 Oracle（2-3 分钟）

仅 3 条分支:最好情况、可能情况、最坏情况。简短叙述。适用于快速决策。

### 深度 Oracle（5-10 分钟）

全部 6 条分支。包含后果、触发信号和综合分析的完整分析。适用于高风险决策。

### 情景链（Scenario Chain）

把一次 Oracle 分析的输出，再输入到另一次分析中。"如果分支 Δ 发生了，那么在这条分支*内部*又有哪些可能性?"用于复杂战略规划的递归深挖。

### 反向 Oracle（Reverse Oracle）

从期望的结果出发，反向推导:"要让 X 发生，哪些条件必须成立?通往这个结果最可能的路径是什么?"适用于目标设定和战略设计。

### 竞争性 Oracle（Competitive Oracle）

从多个利益相关方的视角分析同一个 What-If 问题:"如果我们推出这款产品，从*我们的*视角、从*他们的*视角，以及从*市场的*视角来看，可能性空间分别是什么样的?"

## 本技能不是什么

- 不是预测——它是一张可能性地图。Oracle 并不声称知道未来会怎样；它帮助你为多种未来做好准备。
- 不是水晶球——概率是基于现有证据的估计，而非确定的事实。
- 不能替代行动——世界上最好的情景分析，如果没有后续的决策和执行，也毫无价值。
