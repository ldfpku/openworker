# SPC 与过程能力

把一列测量值变成一份能回答「这道工序稳不稳、够不够格」的分析：指数怎么算的写清楚，控制图上哪些点异常点出来，结论能落到调机、换刀、改公差还是继续观察。

## 适用场景

- 客户或 API 审核要求提供关键尺寸（螺纹中径、外圆、深孔直径、硬度）的 Cpk。
- 想知道某台设备的加工过程是否稳定，还是正在漂移。
- 新设备、新刀具、新工艺参数投产前的能力验证。
- 周报或处理单里要用数据说明「超差是偶发还是过程本身不行」。
- 有人用一批全检合格的数据说「过程没问题」，需要用能力指数核一遍。

## 需要的输入

| 输入 | 常见形式 | 常见列名或内容（以用户文件为准） |
| --- | --- | --- |
| 测量数据 | CSV 或 Excel，一行一个测量值 | 日期 / 时间、批次（子组 / 炉号 / 班次）、设备、零件、测量值（实测值 / 实测 / 尺寸）、检验员、量具 |
| 规格限 | 用户口头或图纸 | USL（上限）、LSL（下限）、目标值（名义尺寸）；单边公差只给一边 |
| 分组方式 | 用户口头 | 数据是按批次 / 时间自然分组，还是一个一个单独测的 |
| 背景信息（可选） | 用户口头 | 测量期间有没有换刀、换炉、换班、调机；量具分辨力和校准状态 |

缺规格限做不了能力指数，只能出控制图，要先问。Excel 文件先把需要的列导成 CSV 再跑脚本；表头不在第一行、末尾有合计行的，先清掉。测量值少于 25 个也能算，但结论要注明「样本不足，初步参考」。

## 工作步骤

1. **确认数据和规格。** 哪一列是测量值、单位是什么、USL / LSL / 目标值各是多少、是双边还是单边公差。规格和测量值的小数位、单位要一致（图纸 mm 和千分表读数 μm 不要混）。
2. **确认分组。** 问用户数据是怎么来的：同一批次连续抽 5 件算一个子组，用均值-极差（Xbar-R）图；每次只测一件、按时间顺序排，用单值-移动极差（I-MR）图。子组大小不一致或超过 10 的，退回 I-MR 并说明。
3. **清洗。** 去掉空值和非数字，把去掉的行号报给用户；明显录错（多打一位小数、单位不一致）的点先问用户再决定去留，不要自己删。数据必须按时间或生产顺序排列，乱序的控制图没有意义。
4. **跑脚本。** `python scripts/capability.py 数据.csv --usl <USL> --lsl <LSL> --target <目标>`，有分组列加 `--group-col 批次`，没有分组列但想按相邻 N 个分组加 `--subgroup-size N`。脚本输出 Markdown，直接引用；需要机器读的加 `--json`。
5. **看稳定性，再看能力。** 先看控制图判异：有超控制限、连续同侧、连续趋势的点，过程不稳定，能力指数只能当参考，先找特殊原因（对照换刀、换炉、换班、调机的时间点）。稳定了再谈 Cpk。
6. **看分布形状。** 把数据分成 6–10 段做个简单频数表看是否大致对称单峰；明显偏斜（硬度、粗糙度、同轴度这类有自然下限的特性常见）或双峰（两台设备、两个班次混在一起）时，指数要注明「数据非正态，指数仅作相对比较」，双峰先分开再算。
7. **判定。** 对照下面的口径判定能力等级，写出结论和原因方向：Cpk 低但 Cp 高是中心偏了，调机即可；Cp 本身就低是波动大，要查设备、刀具、材料、量具。
8. **给改进建议。** 每条建议对应一个发现：中心偏 → 调整刀补 / 工艺参数；波动大 → 查设备状态、刀具寿命、材料批次一致性、量具重复性；不稳定 → 按判异点的时间去查当时发生了什么。
9. **成稿。** 按「输出」的结构写；数字直接引用脚本输出，并写明数据文件、列名、行数和剔除的行。

## 行业口径与判断规则

**定义与计算口径**（脚本按此计算）

| 项目 | 口径 |
| --- | --- |
| 均值 | 所有有效测量值的算术平均 |
| 总体标准差 | 样本标准差，分母 n−1，反映整段时间的全部波动 |
| 组内标准差 | I-MR：MR̄ / 1.128（MR̄ 是相邻两点差的绝对值的平均）；Xbar-R：R̄ / d2(n)。反映短期的、过程本身的波动 |
| Cp | (USL − LSL) / (6 × 组内标准差)，只看波动不看中心 |
| Cpk | min[(USL − 均值), (均值 − LSL)] / (3 × 组内标准差)，看波动也看中心 |
| Pp、Ppk | 同 Cp、Cpk，但用总体标准差；称为过程性能指数 |
| Cpm | (USL − LSL) / (6 × √(总体方差 + (均值 − 目标)²))，给了目标值才算，惩罚偏离目标 |
| 单边公差 | 只算 Cpu 或 Cpl，Cpk 取有的那一边，Cp / Pp 不算 |

Cpk 和 Ppk 差得多（例如 Cpk 1.5、Ppk 1.0）说明批次之间漂移大，短期稳、长期不稳；两者接近说明过程受控。

**控制限**（脚本按此计算，子组大小 2–10 的常数表内置）

- I 图：中心线 = 均值，UCL / LCL = 均值 ± 3 × MR̄ / 1.128；MR 图：UCL = 3.267 × MR̄，LCL = 0。
- Xbar 图：UCL / LCL = 总均值 ± A2 × R̄；R 图：UCL = D4 × R̄，LCL = D3 × R̄。
- 控制限是从数据算出来的，不是规格限；规格限是图纸定的。两者不能互相替代。

**判异规则**（西电规则的简版，脚本实现这三条）

- 任一点超出 UCL 或 LCL。
- 连续 7 点在中心线同一侧。
- 连续 7 点持续上升或持续下降。
- 其余规则（2/3 点在 2σ 外、14 点交替等）按贵司 SPC 规定，需要时手工补判。

**能力判定**（按贵司或客户规定，缺省建议）

| Cpk | 缺省判定 | 常见处理 |
| --- | --- | --- |
| ≥ 1.67 | 能力充分 | 可考虑放宽抽检频次 |
| 1.33–1.67 | 能力合格 | 维持现有控制 |
| 1.00–1.33 | 能力不足 | 加严巡检，启动改进 |
| < 1.00 | 不可接受 | 100% 检验，查原因，必要时停线 |

新工艺、新设备的初始能力用 Ppk 评价，缺省建议 ≥ 1.67；长期稳定后用 Cpk，缺省建议 ≥ 1.33。关键特性（API 规范要求的承载尺寸、螺纹、密封面）按客户要求，没有要求时用上表。

**样本量与分组**

- 单个能力指数至少 25–30 个有效数据；Xbar-R 建议 ≥ 20 个子组，子组内是同一短时间、同一条件下连续加工的件。
- 子组内不要混设备、混班次、混材料批次；混了就只算 I-MR 并说明。
- 量具分辨力至少是公差的 1/10；分辨力不够时数据会呈台阶状，指数偏乐观，要注明。

**常见误读**

- Cpk 高但不居中：Cp 2.0、Cpk 1.2 说明波动小但中心偏，只调中心就能把 Cpk 拉上去，别去换设备。
- 数据非正态：偏斜或双峰的数据算出的指数不能直接换算成不良率；先看分布，必要时分层或换特性。
- 把规格限当控制限：用 USL / LSL 画控制图，等到报警时已经出不良了；控制限要用过程数据算。
- 过程不稳定时报 Cpk：有判异点还报 Cpk 1.5，审核员会问「这个 1.5 代表哪段时间」；先剔除特殊原因，或如实写「不稳定，指数仅参考」。
- 全检合格 ≠ 能力够：合格率 100% 但 Cpk 0.9，说明靠检验在兜底，不是过程好。
- 样本太少的高 Cpk：10 个数据算出 Cpk 2.0 没有说服力，注明样本量。

**Cpk 与 Ppk 的组合解读**

| Cpk | Ppk | 说明 | 方向 |
| --- | --- | --- | --- |
| 高 | 高 | 短期、长期都好 | 维持，可考虑放宽频次 |
| 高 | 低 | 短期稳、批次之间漂移 | 查换刀、换炉、换班之间的差异 |
| 低，但 Cp 高 | 低 | 中心偏 | 调机、改刀补、改参数 |
| 低，且 Cp 低 | 低 | 波动大 | 查设备状态、刀具、材料、量具重复性 |

**脚本用法**（`scripts/capability.py`，只用标准库）

| 参数 | 作用 |
| --- | --- |
| `数据.csv` | 第一行表头，一列测量值；Excel 先另存为 CSV |
| `--usl` / `--lsl` | 规格上下限，至少给一个；单边公差只给一边 |
| `--target` | 目标值，给了才算偏移量和 Cpm |
| `--value-col` | 测量值列名或列序号；不给时按常见列名（测量值 / 实测值）自动找，并跳过序号列 |
| `--group-col` | 分组列名（批次 / 炉号 / 班次），相同值的相邻行算一个子组，出 Xbar-R |
| `--subgroup-size N` | 没有分组列时，把相邻 N 个值并成子组；末尾不足 N 个的不进控制图 |
| `--json` | 输出 JSON 便于再加工 |

`scripts/example.csv` 是 30 个外圆尺寸的样例（6 个批次各 5 件），可以直接试跑：
`python scripts/capability.py scripts/example.csv --usl 60.02 --lsl 59.98 --target 60.00 --group-col 批次`。
脚本会报告跳过的非数字行、子组大小不一致时退回 I-MR、n < 25 的提示；这些提示要原样带进报告。

## 输出

```markdown
# 过程能力分析：<设备 / 零件 / 特性>（数据日期范围）

## 一、数据与口径
数据文件、工作表 / 列名、有效 n、剔除的行号与原因；USL / LSL / 目标值；分组方式（I-MR 或 Xbar-R，子组大小）；量具与分辨力。

## 二、统计结果
（直接贴脚本输出的「基本统计」「能力指数」「超规格」表）

## 三、控制图与稳定性
控制限表；判异点列表（点的行号或子组标签、触发的规则）；对照当时的换刀 / 换炉 / 换班事件。
结论：过程 受控 / 不受控（原因）。

## 四、分布形状
简单频数表或文字描述；是否对称单峰；非正态或双峰时的处理说明。

## 五、能力判定
Cp、Cpk、Pp、Ppk 对照缺省或贵司标准的等级；中心偏移还是波动大；Cpk 与 Ppk 的差距说明什么。

## 六、改进建议
每条对应一个发现，写清动作、负责方向、怎么验证（重新取样算一次）。

## 数据来源
文件名、列名、数据行数、时间范围；脚本命令行。
```

## 交付前自检

- [ ] USL / LSL / 目标值和单位已和用户确认，数据顺序是生产顺序。
- [ ] 分组方式（I-MR 还是 Xbar-R、子组大小）已写明，并和数据来源一致。
- [ ] 指数口径（组内 / 总体标准差）已声明，Cp 的分母是 6 倍组内标准差。
- [ ] 判异点都列了行号或子组标签，并给了「当时发生了什么」的核查建议。
- [ ] 过程不稳定或样本不足时，结论里写了「仅参考」。
- [ ] 分布形状看过了，非正态或双峰已注明。
- [ ] 能力等级标明是「按贵司规定」还是「缺省建议」。
- [ ] 改进建议每条对应一个发现，没有空泛的「加强控制」。

## 边界

- 只做计算、判定和建议，不替用户决定停线、让步或放宽公差；这些要用户拍板。
- 不修改原始测量数据；剔除异常值必须用户同意并在报告里注明。
- 脚本只做本技能列出的指数和三条判异规则，正态性检验、测量系统分析（GR&R）不在范围内，需要时单独做。
- 不把能力指数直接换算成不良率 ppm 报给客户，除非用户确认数据正态且过程受控。
- 发送报告、写入系统、通知车间调机，先问用户。
