# 工程变更（ECR / ECN）管理

把一张变更申请变成一份能走审批、能切换、能通知到人的变更通知：影响评到哪些件和哪些文件、从哪一批开始换、旧件怎么办、谁要知道、换完怎么验证。

## 适用场景

- 设计、工艺、质量或客户提了变更申请（ECR），要评估影响并形成 ECN。
- 返厂故障分析后要改结构、改材料或改密封，要知道牵连多少图纸、工艺、库存和在外产品。
- 供应商停产或材料换牌号，要评估能不能替代、从哪批开始换。
- 车间问「这批在制的按新图还是旧图做」，要给切换点和旧件处置。
- 变更做完要确认文件都改了、验证做了、该通知的都通知了。

## 需要的输入

| 输入 | 常见形式 | 常见内容 / 列名（以用户文件为准） |
| --- | --- | --- |
| 变更申请（ECR） | 表单、邮件或口头 | 申请编号、申请人、日期、变更原因（客户要求 / 设计缺陷 / 返厂故障 / 成本 / 工艺改进 / 供应商停产 / 标准更新）、变更内容、受影响件（件号 / 图号）、紧急程度 |
| BOM 与图纸版本 | ERP 或 PLM 导出 Excel | 件号（物料编码）、名称、图号、版本（版次 / 修订号）、数量、上级件（父项）、层级、来源（自制 / 外购） |
| 在制与库存数量 | ERP 库存表、在制工单表 | 件号、库存数量（现存量）、库位、工单号、工单数量、当前工序、已完工数量、计划完工日期 |
| 已交付产品清单 | 销售或售后台账 | 序列号、型号、客户、交付日期、所在基地（广汉 / 天津 / 新疆等）、状态（在租 / 在井 / 库存 / 返厂中） |
| 客户要求 | 技术协议、合同条款、客户邮件 | 变更是否需客户批准或通知、通知时限、是否要求重新认证或送样 |
| 上游关联文件 | 工艺卡、检验规程、PFMEA、控制计划的编号清单 | 文件编号、版本、对应件号 |

缺 ECR 就先要，没有书面申请的先帮用户把口头内容整理成申请表再往下走。缺 BOM 就做不了影响评估，先要。缺库存和在制数据可以出评估表，但「处置」一节写「待补数量」。缺已交付清单时「追溯」一节注明未评估，不写「无需追溯」。

## 工作步骤

1. **读申请。** 把变更原因、内容、受影响件抄下来；原因是返厂故障或设计缺陷的，要附故障记录或评审记录编号。内容写得笼统（「优化密封结构」）的，追问改哪个尺寸、哪个件。
2. **展开 BOM。** 从受影响件向上找所有用到它的父项直到成品型号，向下找它的子件；列出「直接受影响件」和「间接受影响件（装配关系、互换性受影响）」两张清单。BOM 导出表先看表头在第几行、层级列怎么表示。
3. **判定互换性。** 对每个受影响件回答：新件能不能装进旧总成、旧件能不能装进新总成、功能和性能是否等同。按「行业口径」定变更类别。
4. **逐项评估影响。** 按「行业口径」里的十一项维度逐项填影响评估表，每项写「有 / 无 / 待确认」和说明；「无」也要写一句为什么无。
5. **算数量。** 从库存表和在制表按件号汇总：库存量、在制量（分已完工、在加工、未投料）、采购在途量；每个数字写来源表和行号。
6. **定切换点。** 按变更类别和数量选切换方式（批次、订单、日期或序列号），写成车间和仓库一眼能看懂的话：「工单 WO-xxx 起按 B 版图加工，之前的工单按 A 版完工」。
7. **定旧件处置。** 库存和在制旧件按互换性分：用完、返工成新件、报废、隔离待定、转维修备件；每类写数量、责任人、期限。
8. **评已交付产品。** 按失效后果和客户要求定：不追溯 / 下次返厂时改 / 主动召回改；每种写涉及序列号清单和通知对象。
9. **列变更后验证要求。** 哪些项要做首件检验、工艺验证、试验验证；试验项目和验证等级交试验验证岗定，ECN 里只写受影响项和失效后果。
10. **排审批路线和通知清单。** 按贵司制度；没有就用缺省路线。通知清单每条写对象、内容、方式、时限、确认方式。
11. **给用户核对。** 影响评估表和切换点先发用户确认，再出 ECN 正文。

## 行业口径与判断规则

**变更类别**（按贵司规定，缺省建议）：

- A 类：影响安全、功能、性能、互换性、材料或热处理、承压与受力件、密封、API 标准螺纹，或客户技术协议里的任何参数。走全路线，必须有变更后验证，一般需评估已交付产品。
- B 类：不影响互换性和性能，只影响工艺方法、工装、供应商、成本或交期。走全路线，验证以首件和工艺验证为主。
- C 类：图面、文字、标注规范性修改，不改尺寸和要求。可简化审批，按贵司制度。

拿不准 A 还是 B 的按 A 走；用户可以降级，但要写在评估表里。

**影响评估十一项**：图纸（含装配图、零件图、技术要求）；BOM；工艺与工装（工艺卡、数控程序、刀具、夹具、量规、热处理工艺）；检验规程与量具；PFMEA / 控制计划；采购件与供应商；库存与在制品处置；已交付产品是否追溯；客户 / 认证是否需要通知（技术协议、API 会标产品或质量体系对设计变更控制的要求，按贵司程序判断）；使用说明书、维修手册和备件清单；成本与交期。

**切换方式怎么选**：

- 按批次 / 工单：新旧件可互换、在制量大、要用完旧件时。
- 按订单：客户要求指定版本，或不同客户用不同版本时。
- 按日期：C 类或纯文件变更，不涉及实物。
- 按序列号：A 类且要追溯到每一台时；切换序列号写进 ECN 和产品档案。
- 不管哪种，切换点之前投产的在制品归「旧件」，之后的归「新件」，不能同一工单两种版本混做。

**旧件处置口径**：

- 可互换且性能不受影响：用完，写明用完期限和最后一个工单号。
- 可返工成新件：返工工艺由工艺岗出，返工后按新版检验，返工件单独标识。
- 不可互换又不能返工：报废走不良品流程，或隔离待定（期限按贵司规定，缺省建议不超过 30 天定下来）。
- 转维修备件：只在旧版产品仍在服务期内、且该件可作备件时，数量与服务基地核对。

**已交付产品追溯**：失效后果为落井、卡钻、井控风险的 A 类变更，缺省建议至少通知客户并在下次返厂时改；是否主动召回由用户和客户定，不替他定。追溯清单按序列号列，状态「在井」的单独标出，通知对象包括所在服务基地。

**审批路线**（按贵司制度；缺省建议）：设计（提出并出图）→ 工艺（工艺与工装影响、返工方案）→ 质量（检验规程、PFMEA / 控制计划、客户与认证、追溯）→ 生产（切换点、库存与在制处置、交期）→ 批准（技术负责人或按贵司授权）。涉及客户批准的，在批准前加一步「客户确认」。涉及采购件的加「采购」会签。

**变更后验证要求**：

- 首件检验：新版第一件按新版检验规程全尺寸检验，记录编号写进 ECN 关闭条件。
- 工艺验证：新工艺或新工装的首批按贵司规定抽检，热处理变更要有硬度和金相结果。
- 试验验证：受影响项交试验验证岗，由他们定验证等级（缺省对应「变更后再验证」）和试验项目；ECN 只给受影响项、失效后果和变更前后的差异。
- 文件确认：图纸、BOM、工艺、检验规程、PFMEA / 控制计划的新版本号在 ECN 关闭时逐项对照，旧版回收。
- 效果跟踪：因返厂故障引起的变更，缺省建议跟踪变更后产品的返厂记录一段时间（按贵司规定），确认故障不再出现才算有效。

**常见坑**：

- 只改了零件图没改装配图和 BOM；改了 BOM 没改备件清单。
- 工艺卡改了，数控程序和量规没改，首件按旧程序做出来。
- 库存按「现存量」算，没算采购在途和外协在制。
- 切换点写「尽快」「从下批开始」，车间和仓库理解不一致。
- 变更是客户要的，做完没回给客户书面确认。

## 交付前自检

- [ ] 受影响件从 BOM 向上向下都展开了，每个件有新旧版本和互换性结论。
- [ ] 影响评估表十一项都填了，「无影响」的有理由。
- [ ] 库存、在制、在途数量都能回指到来源表和行号；缺的标「待补」。
- [ ] 切换点是车间和仓库能执行的具体工单号、订单号、日期或序列号。
- [ ] 旧件每类处置都有数量、责任人、期限。
- [ ] 已交付产品的追溯结论有失效后果依据；「不追溯」是用户确认的，不是默认的。
- [ ] 验证等级和试验项目没有在 ECN 里替试验验证岗定。
- [ ] 审批路线标了「按贵司制度」，没有编造审批人岗位名。
- [ ] 通知清单每条有对象、内容、方式、时限、确认方式。

## 边界

- 只做评估、整理和成稿，不替用户决定变更该不该做、类别该不该降。
- 不替设计岗出新图，不替工艺岗出返工工艺，不替试验验证岗定验证等级。
- 不编造贵司的审批制度、岗位和编号规则；给缺省建议，由用户替换。
- 不在 ERP / PLM 里改版本、改库存、关工单；不发通知邮件、不通知客户和服务基地；这些都要先问用户。
- 客户技术协议和认证要求以用户提供的原文为准，不替用户解释条款。
