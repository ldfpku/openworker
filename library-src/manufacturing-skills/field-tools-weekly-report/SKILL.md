# 在外工具周报

每周一出一份格式固定的在外工具周报：在外多少、新出几支、回来几支、逾期几支、现场坏了几次、下周到期几支、哪些事要领导拍板；格式每周一样，数字每周可查，能交给定时任务自己跑。

## 适用场景

- 每周一早上商务或租赁业务要一份在外工具情况给领导或例会。
- 想把周报交给 OpenWorker 的定时任务，每周一自动生成、自动发到微信。
- 上周有周报，这周要照同样的格式续写，还要交代上周提的事有没有办。
- 基地反馈了现场故障，要和在外工具对上号写进周报。

## 需要的输入

| 输入 | 常见形式 | 常见列名（以用户文件为准） |
| --- | --- | --- |
| 租赁台账 | 一张 Excel 或每基地一个文件 | 工具编号（工具号）、工具类型（类型 / 工具类别）、规格（规格(OD,in) / 外径(in)）、客户（甲方）、井号、出租日期（出库日期）、约定归还日期（合同到期日）、实际归还日期（归还日期 / 入库日期）、日租金、状态（在外 / 已归还 / 维修中）、基地（可能没有） |
| 返厂登记 | 每基地一个 Excel | 返厂日期（登记日期 / 日期）、工具编号、工具类型（工具类别 / 类型）、规格、客户、井号、故障部位（失效部位 / 故障位置）、故障现象（故障描述 / 情况说明）、处理措施（处理 / 维修措施）、工时 |
| 现场反馈 / 故障记录 | Excel、从微信记录整理的文本、基地日报 | 日期、基地、客户、井号、工具编号、现象、现场处理、是否更换、是否返厂、状态（已处理 / 跟进中） |
| 上周周报 | Word / Markdown / Excel | 当格式参考；「需要决策的事项」要逐条回看 |
| 本周范围与「今天」 | 会话里用户给；定时任务取运行当天 | — |

缺台账做不了。缺返厂登记和现场反馈，「现场故障」一节写「本周未收到反馈记录」。缺上周周报用缺省结构，「上周事项跟进」写「无上周周报」。

## 工作步骤

1. **定日期。** 「今天」= 用户给的日期；定时运行时 = 运行当天。报告期 = 上周一至上周日（缺省；用户可改）。「下周到期」= 今天起 7 天内（缺省）。这三个日期写进周报标题和「数据来源」，每周都写，方便回查。
2. **读台账，摸底。** 工作表、表头行、合计行、总行数、各状态行数。按「在外」筛出清单，按工具编号去重；重复的进「台账异常」。
3. **在外数量。** 按基地、客户、类型三种口径各汇总一次；三张表的合计必须相等，不等先查。
4. **本周新出租与归还。** 出租日期落在报告期内的行 = 新出租；实际归还日期落在报告期内的行 = 归还。各列明细带行号。归还的工具查返厂登记里有没有对应记录，有的标「已返厂登记」。
5. **逾期未还。** 约定归还日期早于今天且仍在外的，按逾期天数从多到少排；到期日空白或非日期的单列「无法判断」。和上周周报的逾期清单比：新增哪几支、哪几支已归还、哪几支还在。
6. **现场故障与处理。** 报告期内的现场反馈和返厂登记：每条写日期、基地、工具编号、客户 / 井号、现象、处理（现场处理 / 更换 / 返厂）、状态。故障工具要在台账里找到对应的在外行；找不到的标「台账无此工具在外记录」。
7. **下周到期。** 约定归还日期在今天起 7 天内的在外工具，按日期排。
8. **需要决策的事项。** 从前面几节里挑：逾期超过 N 天（按贵司规定，缺省 14 天）的、同一客户逾期多支的、现场反复故障的、台账异常待确认的、某类工具在库不足的。每条写「事项 → 数据 → 需要谁定什么」。上周周报里的事项逐条交代：已办 / 未办 / 进行中。
9. **数据来源。** 每个文件的名字、工作表、行数、报告期内行数；逾期口径、报告期口径、「今天」。
10. **成稿。** 按上周周报的章节；没有就用缺省结构。写入固定文件名的文件。会话里做的，先发汇总表给用户核对；定时任务里做的，把需要人工核对的点写进「台账异常与待确认」节。

## 行业口径与判断规则

- **在外**以台账状态为准；状态和归还日期矛盾的进异常，不算在外也不算归还，单独报数。
- **在外数量按工具编号去重**；重复编号多半是归还后没更新台账，周报里写「去重前 N 行、去重后 M 支」。
- **逾期**缺省口径：今天晚于约定归还日期；今天到期的单列「今天到期」。用户定了别的规矩，写进周报和定时任务指令里。
- **本周新出租 / 归还**按日期列落在报告期内判断，不按状态；归还日期空白但状态已归还的进异常。
- **现场故障不等于返厂**：现场处理好的也要记一条；返厂的要和返厂登记对上，对不上的标出来。
- **故障和在外工具对号**用工具编号；编号写法不一致（大小写、空格、连字符）先统一。
- **周报里不做故障原因分析**，只记现象和处理；原因分析用返厂维修记录分析或失效分析另做。
- **需要决策的事项**只列事实和选项，不替领导定。
- 三张汇总表（按基地 / 客户 / 类型）合计相等是最基本的守恒核对，不等就先查，不出稿。
- 报告期、逾期天数、下周到期天数的阈值按贵司规定；缺省分别为上周一至上周日、14 天、7 天。

## 输出

缺省结构（有上周周报就沿用它的章节和标题）：

```markdown
# 在外工具周报（YYYY-MM-DD；报告期：MM-DD 至 MM-DD）

## 一、在外工具总览
| 基地 | 在外支数 | 其中逾期 | 本周新出租 | 本周归还 |
| --- | --- | --- | --- | --- |
| 客户 | 在外支数 | 其中逾期 | 井号 |
| 类型 | 在外支数 | 其中逾期 | 在库可租（有数据时） |
合计 M 支（台账在外 N 行，去重后 M 支）

## 二、本周新出租
| 工具编号 | 类型 | 规格 | 客户 | 井号 | 出租日期 | 约定归还 | 行号 |

## 三、本周归还
| 工具编号 | 类型 | 客户 | 井号 | 出租日期 | 归还日期 | 在外天数 | 是否已返厂登记 | 行号 |

## 四、逾期未还
| 工具编号 | 类型 | 客户 | 井号 | 约定归还 | 逾期天数 | 上周是否已逾期 | 行号 |
无法判断（到期日空白 / 非日期）：……

## 五、现场故障与处理
| 日期 | 基地 | 客户 / 井号 | 工具编号 | 现象 | 处理 | 状态 | 来源 |

## 六、下周到期
| 到期日 | 工具编号 | 类型 | 客户 | 井号 | 行号 |

## 七、需要决策的事项
每条：事项 → 数据依据 → 需要谁定什么
上周事项跟进：逐条 已办 / 未办 / 进行中

## 八、台账异常与待确认

## 数据来源
文件、工作表、行数、报告期内行数；「今天」、报告期、逾期口径
```

每个数字后面带来源：`（租赁台账.xlsx › 租赁台账 › 第 12、15、17 行）`。

### 交给定时任务：要提前准备什么

- **工作文件夹**：新建自动化时选「工作文件夹」，把下面所有文件放在这一个文件夹里——定时运行时它只看得见这个文件夹，周报也写回这里。
- **文件名约定**（缺省建议，用户可改，定下来就不要变）：
  - `租赁台账.xlsx`：每周更新后覆盖，文件名不带日期；每基地一个的用 `租赁台账-<基地>.xlsx`；
  - `返厂登记-<基地>.xlsx`：每基地一个；
  - `现场反馈.xlsx`：持续追加，按日期列筛报告期；
  - 周报输出 `在外工具周报-YYYY-MM-DD.md`（或 .xlsx / .docx，按用户要求），日期用运行当天；上周周报就是同名模式里日期最近的一份。
- **「今天」**：定时运行取运行当天的日期，写在周报标题里；周一几点运行由用户在自动化里设。
- **指令内容**：把会话里验过的那几句话（在外筛选规则、逾期口径、报告期、文件名约定、三张表合计相等的自检）原样写进自动化指令，不要只写「生成周报」。
- **第一次运行**：先点「立即运行」跑一次，和会话里的成品对比；一致了再接微信发送（收件人由用户在自动化里设置）。
- **文件没按约定放**（台账缺、文件名不对、表头变了）：周报照出，但在开头写「本周数据缺口」，不补数、不猜。

## 交付前自检

- [ ] 标题里有「今天」和报告期；三个日期口径和「数据来源」一致。
- [ ] 按基地 / 客户 / 类型三张表的合计相等，且等于去重后的在外支数。
- [ ] 逾期清单的每一条都是约定归还日期早于今天且仍在外；今天到期的没混进去。
- [ ] 新出租 / 归还按日期判断，不是按状态。
- [ ] 每条故障都对上了台账里的工具，对不上的标出来了。
- [ ] 上周周报的每条决策事项都有交代。
- [ ] 每个数字带来源行号；数据缺口写在开头，没有补数。
- [ ] 格式和上周一致，章节没有增减（增减要用户同意）。

## 边界

- 周报只汇总事实，不分析故障原因，不下「谁的责任」。
- 不修改台账、返厂登记、现场反馈。
- 定时任务里只把周报写进工作文件夹；发微信、发邮件由用户在自动化里设置，技能本身不发。
- 会话里做的周报，发出去之前先经用户确认。
- 文件缺、格式变了，如实写缺口，不补数。
