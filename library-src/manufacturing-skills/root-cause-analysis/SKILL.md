name: root-cause-analysis
description: 对一个质量、设备或返厂故障问题做根因分析：先把问题定义成「是什么 / 不是什么」，按设备、班次、材料批次、时间分层找规律，用鱼骨图（人机料法环测）列候选原因，用 5Why 一层一层追到能采取措施的根因，每个 Why 都要有证据，再给出验证计划和完整证据链。当用户说「帮我分析一下为什么」「做个 5Why」「画个鱼骨图」「根因到底是什么」「换了措施还是复发」时使用。
---

# 根因分析

把「这个问题为什么会发生」从猜测变成有数据、有验证的结论，交出一条别人能复核的证据链，而不是一句「操作不当」。

## 适用场景

- 处理单上的原因分析只有一句话，要做成能站得住的根因分析。
- 同一设备或同一不良反复出现，换过措施还是复发，怀疑原因没找对。
- 热处理硬度、机加尺寸、装配渗漏、返厂故障这类问题，不知道该从设备、材料还是操作查起。
- 做 8D 报告的 D4 步骤，或者 PFMEA 更新前要搞清楚失效的真实原因。
- 设备反复维修同一个部位，要判断是修的方法不对还是另有上游原因。

## 需要的输入

| 输入 | 常见形式 | 常见列名或内容（以用户文件为准） |
| --- | --- | --- |
| 问题描述 | 用户口头，或处理单上的不良描述 | 什么零件、什么特性、实测值与公差、发现时间、发现方式 |
| 检验记录 | 各车间 Excel | 日期、车间、设备（设备编号）、零件（零件名称 / 图号）、工序、送检数、不良数、不良类型（不良描述 / 缺陷）、处置、检验员 |
| 不良品处理单 | Excel 或表单 | 单号、日期、设备、零件、不良描述、数量、原因分析、纠正措施、状态 |
| 设备点检与维修记录（可选） | 点检表、维修记录 | 日期、设备、点检项目、结果（正常 / 异常）、异常说明、处理状态；故障现象、处理措施、停机时间 |
| 工艺参数记录（可选） | 热处理炉记录、程序单、刀具更换记录 | 炉号、设定温度、实测温度、保温时间、冷却方式；程序版本、刀补值、刀片批次 |
| 材料与来料记录（可选） | 入厂检验、炉号追溯 | 材料牌号、炉号、供应商、入厂检验结果 |
| 人员与班次（可选） | 排班表 | 日期、班次、操作工、检验员 |
| 量具与校准（可选） | 量具台账 | 量具编号、校准日期、校准结果 |
| 返厂记录（返厂故障时） | 返厂检验记录、维修记录 | 工具编号、井号、入井 / 出井日期、累计入井时间、故障部位、故障现象 |

最少要有问题描述和一份能分层的记录（检验记录或维修记录）。只有问题描述没有数据的，鱼骨图可以做，5Why 只能做到「待验证」，要明说。

## 工作步骤

1. **定义问题。** 写成一句可测量的话：「<设备> 加工的 <零件> 的 <特性> 在 <时间段> 出现 <不良>，共 N 件 / M 件送检」。再做「是什么 / 不是什么」对照：出在哪台设备、不出在哪台；哪种零件、不是哪种；哪几天、不是哪几天；哪个班次、不是哪个班次；哪个材料批次、不是哪个。对照表里「是」和「不是」的差别就是线索。
2. **读全数据。** 逐个文件打开，确认表头在第几行、有没有合计行、哪张工作表是数据。把本问题相关的行挑出来，记下文件、工作表、行号。
3. **分层。** 把相关记录至少按四个维度各切一次：按设备、按班次 / 操作工、按材料批次 / 炉号 / 刀片批次、按时间（逐日、换班前后、换刀换炉前后）。每个维度算不良数和不良率，找「集中在某一层」的规律。规律要写成「不良 12 件里 12 件出自 A 设备，B、C 设备同期 0 件」这种可核对的句子，附行号。
4. **鱼骨图。** 按人、机、料、法、环、测六类列候选原因，每类至少想两条，但只保留和分层结果不矛盾的。例如分层显示只出在一台设备，「操作工技能」就排后面，「设备状态」「刀具」「程序」排前面。每条候选原因标注：支持它的证据、反对它的证据、还没查的。
5. **筛选候选原因。** 按「有证据支持」「能解释是什么 / 不是什么的全部差别」「可验证」三条打分，挑出 1–3 条进入 5Why；其余写进「已排除」并写排除理由。
6. **5Why 追问。** 从现象开始每问一层「为什么」，每一层都要写证据来源（记录、测量值、现场照片、再现试验），没有证据的那一层标「推测」。追到满足三个条件就停：这一层是可以直接采取措施控制的；消除它之后现象应当不再出现；它能解释前面所有的「是什么 / 不是什么」。一般追 3–5 层，不是机械数到 5。
7. **分发生和流出两条链。** 发生链回答「为什么会产生」，流出链回答「为什么没有在本工序或检验环节拦住」。流出链常见落点：检验频次不够、首件没检这个项目、量具不合适、检验规程里没这项。
8. **写验证计划。** 每条候选根因给一种验证方式：再现（恢复可疑条件看问题是否重现）、对比（换设备 / 换批次 / 换班次看是否消失）、测量（直接测可疑参数，如主轴跳动、炉温均匀性、刀补值）、翻记录（时间线对齐：换刀日期、点检异常日期和不良出现日期是否吻合）。写明谁做、需要多久、什么结果算证实、什么结果算排除。
9. **出结论与证据链。** 验证做完的，写根因结论和从现象到根因每一步的证据；没做验证的，结论只能写「最可能原因（待验证）」，并把验证计划交给用户。
10. **交给下一步。** 结论回填到 8D 的 D4（`ncr-8d-report` 技能）或 PFMEA 的「潜在原因」栏，措施由那边接着做。

## 行业口径与判断规则

**根因的判定标准**

- 可控：是贵司能动手改的东西（参数、工装、程序、文件、点检项目），不是「天气」「客户要求急」。
- 可验证：消除它之后问题不再出现，或恢复它之后问题重现。
- 覆盖：能解释「是什么 / 不是什么」里的全部差别。只能解释一半的，要么不是根因，要么问题不止一个。

**常见陷阱**

- 把症状当根因：「刀片磨损」是现象，要问为什么磨得这么快（切削参数、材料硬度偏高、刀片批次、冷却不足）。
- 把责任人当原因：「操作工没按规程」要接着问为什么没按（规程不清楚、工装做不到、没培训、赶工期），停在人身上的分析下次一定复发。
- 没验证就下结论：鱼骨图上最顺眼的那条不等于根因；写进报告前至少做一次对比或测量。
- 换了措施仍复发：直接说明前次根因错了，不要在同一层再找一个相似原因，往上游走一层。
- 只找发生根因不找流出根因：问题会再出，而且还是靠客户发现。
- 多个原因叠加：分层里两个维度都集中（既集中在某设备又集中在某材料批次）时，可能是两个原因共同作用，验证时要分开试。
- 数据太少：不良只有 1–2 件时分层没有意义，老实写「样本不足，建议加严巡检积累数据」。

**本行业常用的分层维度和追问方向**

| 车间 / 环节 | 优先分层维度 | 5Why 常走的方向 |
| --- | --- | --- |
| 机加（车、铣、深孔钻） | 设备、刀片批次 / 换刀时间、程序版本、材料炉号、班次 | 刀片磨损 → 刀补更新 → 主轴 / 卡盘跳动 → 程序参数 → 材料硬度与余量 → 量具 |
| 热处理 | 炉号、炉内位置、装炉量、炉次、材料炉号 | 工艺参数设定 → 温控仪表漂移 → 炉温均匀性 → 装炉方式 → 冷却介质状态 → 硬度计校准 |
| 装配、试压 | 密封件批次、装配工位 / 人员、清洁度、工装 | 密封件来料 → 装配倒角与导入 → 清洁度 → 工装磨损 → 试压程序与判定 |
| 返厂维修 | 工具型号 / 规格、客户 / 井号、累计入井时间、上次维修基地 | 先分三类：井下工况超设计、制造 / 装配缺陷、上次维修质量；没有入井时间和工况记录时不下结论 |

**什么时候用故障树（FTA）**

- 顶事件后果严重（井下落物、压力密封失效、承载件断裂）或涉及多个原因「与」「或」组合时用；一般的尺寸超差用 5Why 足够。
- 故障树只画到能对应证据的层级，每个底事件标「已证实 / 已排除 / 待查」。

**证据的分量**（从强到弱）

测量数据和再现试验 > 时间线吻合的记录（点检异常、换刀、换炉号和不良出现同一天）> 现场照片和实物 > 当事人口述 > 经验推断。报告里每条证据标明属于哪一级。

**分层结果怎么读**

- 集中在一台设备、多种零件 → 设备、刀具、程序方向；集中在一种零件、多台设备 → 图纸、工艺、材料方向。
- 集中在某几天 → 对齐那几天的换刀、换炉、换班、调机、来料记录。
- 集中在某材料炉号 → 查入厂检验和材质证明，同炉号的其他零件有没有问题。
- 哪个维度都不集中 → 可能是量具或检验方法的问题，先做量具比对再往下查。

**验证方式举例**

| 候选根因 | 验证方式 | 证实的判据 | 排除的判据 |
| --- | --- | --- | --- |
| 刀片批次不良 | 换另一批次刀片加工一批对比 | 新批次不良消失、旧批次复现 | 两批次都出或都不出 |
| 刀补未更新 | 翻程序 / 刀补修改记录，和不良出现时间对齐 | 换刀后未改刀补的班次与不良日期吻合 | 刀补记录完整且时间对不上 |
| 主轴或卡盘跳动 | 停机打表测径向跳动 | 跳动超出设备允差 | 跳动在允差内 |
| 温控仪表漂移 | 用校准过的热电偶比对炉内实测温度 | 偏差超出工艺允许范围 | 偏差在范围内 |
| 炉温均匀性 | 多点测温，或同炉不同位置零件的硬度对比 | 不同位置硬度差明显，不良集中在某区 | 各位置一致 |
| 密封件批次 | 换批次装配并试压对比 | 换批次后渗漏消失 | 换批次仍渗漏 |

**问题定义的常见错误**

- 把多个问题写成一个：「螺纹超差和硬度不合格」是两条链，分开做。
- 没有数量和时间：「最近老出问题」没法分层，先补日期和件数。
- 用结论当描述：「刀片不好导致超差」已经预设了原因，描述只写现象。

## 输出

```markdown
# 根因分析：<设备 / 零件 / 不良>（日期）

一句可测量的问题描述；涉及记录（文件 › 工作表 › 行号）。
| 维度 | 是什么 | 不是什么 |
| 设备 / 零件 / 时间 / 班次 / 材料批次 / 发现环节 | … | … |

## 二、数据分层
每个维度一张小表：层别、送检、不良、不良率、涉及行号；一句话写规律。

## 三、鱼骨图
| 类别 | 候选原因 | 支持证据 | 反对证据 | 状态（保留 / 排除 / 待查） |
（人、机、料、法、环、测各若干行）

## 四、5Why 链
发生链：
| 层级 | 为什么 | 回答 | 证据（来源 / 级别） |
流出链：同上

## 五、验证计划
| 候选根因 | 验证方式 | 谁做 | 需时 | 证实的判据 | 排除的判据 | 结果 |

## 六、根因结论与证据链
发生根因：……；流出根因：……
证据链：现象 →（证据）→ 中间原因 →（证据）→ 根因
已排除的原因及理由。
未验证项与建议下一步。

## 数据来源
文件、工作表、数据行数、本次分析用到的行号。
```

## 交付前自检

- [ ] 问题定义是一句可测量的话，并有「是什么 / 不是什么」对照。
- [ ] 分层至少做了设备、时间两个维度，规律句子带行号，没有凭印象。
- [ ] 鱼骨图每条候选原因都标了支持 / 反对证据和状态。
- [ ] 5Why 每一层有证据来源，没有证据的标了「推测」；没有停在人身上。
- [ ] 分了发生链和流出链。
- [ ] 每条根因有验证方式，没做验证的结论写成「待验证」。
- [ ] 复发问题已注明前次原因和措施，并说明为何不成立。
- [ ] 样本太少时如实写「样本不足」，没有硬下结论。

## 边界

- 不替用户认定责任，不写「某某操作失误」的结论；分析对象是过程、设备、文件。
- 不修改用户的原始记录。
- 验证计划里的试验、停机测量、拆检由用户安排，本技能只给计划和判据。
- 措施的制定和验证归 `ncr-8d-report` 技能的 D5–D7，这里只交根因和证据链。
- 缺数据就写缺，不编造测量值、不假设工艺参数。
