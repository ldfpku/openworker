# 内审与管理评审

把内审从「翻文件打勾」变成按过程问问题、看证据、开得出站得住的不符合项；把管理评审从「念 PPT」变成有输入、有决定、有跟踪的会议。

## 适用场景

- 年度内审要开始了，要按过程做检查表、分配审核员。
- 内审现场发现了问题，要写成规范的不符合项报告并分级。
- 上次内审和外审的不符合项要跟踪，看纠正措施有没有关闭、有没有效。
- 管理评审会前要准备输入材料（质量目标、客户反馈、不良、审核结果、供应商、资源），会后要写纪要。
- 外审（认证机构、API、客户）前自查，怕哪个过程没有证据。

## 需要的输入

| 输入 | 常见形式 | 常见列名或内容（以用户文件为准） |
| --- | --- | --- |
| 内审计划 | Excel 或 Word | 审核日期、受审过程 / 部门、审核员、依据（ISO 9001 条款、API Q1、贵司程序文件）、范围 |
| 过程 / 部门清单 | 过程清单、组织架构 | 过程名称、负责部门、过程负责人、相关程序文件编号、绩效指标 |
| 上次不符合项 | 内审 / 外审报告 | 编号、条款、描述、分级、纠正措施、责任人、期限、状态 |
| 各部门绩效数据 | 质量目标完成表、周报月报 | 指标名称、目标值、实际值、周期；合格率、准时交付率、客户投诉数、返厂数、供应商合格率、设备完好率、培训完成率 |
| 客户反馈 | 投诉记录、满意度调查、返厂记录 | 日期、客户、问题、处理、关闭 |
| 上次管理评审记录（可选） | 纪要 | 决定事项、责任人、期限、完成情况 |
| 贵司程序文件（可选） | 质量手册、程序文件清单 | 文件编号、版本 |

缺内审计划可以先帮用户起草；缺过程清单就按 ISO 9001 的章节划分过程并让用户对应到部门；缺绩效数据的管理评审输入项写「待补」，不补数。

## 工作步骤

1. **定范围和依据。** 本次审核覆盖哪些过程、依据哪些标准（ISO 9001 哪些章节、API Q1、贵司程序文件）、审核员是谁、审核员不能审自己的部门。
2. **读上次不符合项。** 逐条列状态：已关闭的要看有没有验证证据；未关闭的本次必审；重复出现的升级分级。
3. **读绩效数据。** 每个过程的指标：目标、实际、趋势；没达标的作为本次审核的重点提问。
4. **按过程生成检查表。** 每个过程一张，每条写「提问 + 要看的证据 + 对应 ISO 9001 章节」。提问要能追到记录（「最近一次 XX 的记录给我看」），不要「你们有没有程序」这种只能答有的问题。把上次不符合项和绩效未达标项编成专项提问。
5. **现场审核记录（用户提供发现后）。** 每个发现写：过程、看到了什么（文件编号、记录日期、设备、人员角色）、对照的要求、判定（符合 / 不符合 / 观察项）。
6. **开不符合项报告。** 每条：编号、过程 / 部门、条款（ISO 9001 章节号）或贵司程序要求、客观证据、不符合的描述（要求是什么、实际是什么）、分级、责任人、纠正措施期限。分级规则见口径。
7. **跟踪纠正措施。** 跟踪表：纠正（先把眼前问题处理掉）、根因分析（可调用 `root-cause-analysis` 技能）、纠正措施、完成日期、验证方式、验证人、关闭日期。超期的标出来。
8. **准备管理评审输入。** 按下面的输入清单逐项整理，每项给数据和来源，没有的写「待补」；上次评审的决定事项逐条交代完成情况。
9. **出管理评审纪要。** 会后把决定、责任人、期限、所需资源写成纪要，并开下一周期的跟踪表。
10. **给用户核对。** 检查表先给审核组看一遍再定稿；不符合项分级先和质量负责人确认再发受审部门。

## 行业口径与判断规则

**按过程划分与 ISO 9001 章节对应**（通俗说法）

| 过程 | 常见负责部门 | 主要对应章节 | 典型提问 | 要看的证据 |
| --- | --- | --- | --- | --- |
| 领导与策划 | 管理层、质量 | 5、6 | 质量目标是什么、怎么分解、今年完成情况？风险和机遇识别过吗？ | 方针、目标分解表、绩效数据、风险清单 |
| 文件与记录控制 | 质量 / 文控 | 7.5 | 现场用的工艺卡 / 检验规程是现行版吗？作废文件怎么处理？ | 文件清单、受控章、更改记录 |
| 人员与培训 | 人力、各车间 | 7.1、7.2 | 热处理工、探伤员的资质？新员工上岗前培训记录？ | 资质证书、培训记录、考核 |
| 设备与基础设施 | 设备部 | 7.1.3、7.1.5 | 点检表最近一次异常怎么闭环的？量具校准有没有过期的？ | 点检表、维修记录、校准台账 |
| 销售与合同评审 | 销售 | 8.2 | 客户要求（规格、交期、API 要求）怎么传到生产？变更怎么通知？ | 合同评审记录、订单、变更记录 |
| 设计开发（如适用） | 研发 | 8.3 | 新产品的评审、验证、确认记录？设计变更有没有评审？ | 设计输入 / 输出、评审记录、ECN |
| 采购与供应商 | 采购 | 8.4 | 合格供应商怎么评的？外协热处理怎么控制？来料不合格怎么处理？ | 供应商评价、审核记录、来料检验记录 |
| 生产与服务提供 | 各车间、服务基地 | 8.5 | 工艺参数怎么记录？产品怎么标识和追溯（炉号、工具编号）？返厂维修的记录？ | 工艺记录、标识、追溯记录、维修记录 |
| 监视与测量 / 产品放行 | 质量 | 8.6、9.1 | 首件、巡检、终检记录完整吗？放行谁签？ | 检验记录、放行记录 |
| 不合格品与纠正措施 | 质量 | 8.7、10.2 | 处理单闭环率？复发的怎么处理？根因有没有验证？ | 处理单、8D、复发统计 |
| 客户满意与投诉 | 销售、售后 | 9.1.2 | 投诉关闭天数？返厂故障有没有分析到制造环节？ | 投诉记录、返厂分析 |
| 内审与管理评审 | 质量、管理层 | 9.2、9.3 | 上次内审不符合项都关了吗？管理评审的决定落实了吗？ | 审核报告、纪要、跟踪表 |

API Q1 在上述基础上对风险管理、变更管理、应急计划、供应商控制、产品放行与追溯有更细的要求，审核时按贵司依据 API Q1 编的程序文件逐条问；本技能不引用 API Q1 的具体条款号。

**不符合项分级**（按贵司规定，缺省建议）

- 严重：体系要求整体缺失或系统性失效（某过程完全没有记录、关键工序无控制、不合格品未隔离流到客户、上次严重不符合项未整改）；可能影响产品符合性或认证。
- 一般：要求有但个别执行不到位（某批记录缺签字、一台量具过期、一份文件版本不对）。
- 观察项：目前符合但有风险或改进机会。
- 同一问题上次是一般、本次又出现，升为严重。

**不符合项的写法**

- 三要素：要求（条款或程序文件原文要点）、证据（具体到文件编号、日期、设备号、记录名）、事实（实际看到的和要求的差别）。
- 不写人名，写角色；不写「可能」「似乎」，只写看到的。
- 一条不符合项只写一个问题，便于跟踪。

**管理评审输入清单**（ISO 9001 第 9.3 条，通俗写法）

| 输入 | 通俗说法 | 来源 |
| --- | --- | --- |
| 上次评审的措施落实情况 | 上次开会定的事做了没有 | 上次纪要、跟踪表 |
| 内外部环境变化 | 客户、市场、法规、新基地、新产品有什么变化 | 管理层、销售 |
| 客户满意与相关方反馈 | 投诉、返厂、满意度、客户审核结果 | 投诉记录、返厂记录、调查 |
| 质量目标完成情况 | 各项指标目标 vs 实际 | 目标分解表、月报 |
| 过程绩效与产品符合性 | 合格率、一次交检合格率、准时交付、返修报废、处理单闭环 | 质量周报月报、生产报表 |
| 不合格与纠正措施 | 处理单数量、重复不良、8D 关闭情况 | 处理单台账 |
| 监视测量结果 | 关键特性 Cpk、量具校准状态 | SPC 报告、校准台账 |
| 审核结果 | 内审、外审、客户审核的不符合项和关闭情况 | 审核报告 |
| 供应商表现 | 来料合格率、准时率、供应商等级 | 供应商评价 |
| 资源充分性 | 人员、设备、量具、培训够不够 | 各部门提报 |
| 风险和机遇的应对效果 | 识别过的风险有没有发生、措施有没有用 | 风险清单 |
| 改进机会 | 各部门提的改进建议 | 各部门 |

**管理评审输出清单**

- 改进机会的决定：做什么、谁负责、什么时候完成。
- 体系需要的变更：文件、组织、过程。
- 资源需求：人、设备、量具、培训、预算。
- 每条输出要有责任人和期限，否则下次评审无法核对。

**几条判断规则**

- 审核员不能审自己的部门；检查表里注明审核员和受审部门。
- 「有程序文件」不等于符合，要看记录；记录齐全但指标没达标也要问原因。
- 绩效数据引用周报、月报的原数，不重算；要重算的注明口径。
- 内审发现的复发问题（和处理单、周报里的重复不良对得上）要在报告里点明，并建议进 8D。
- 管理评审至少每年一次（按贵司规定），频次写进纪要。

## 交付前自检

- [ ] 每个受审过程都有检查表，提问能追到记录，有对应的 ISO 9001 章节号（只到章节层面）。
- [ ] 上次不符合项逐条有状态；未关闭和重复的进了专项提问。
- [ ] 不符合项三要素齐全，证据具体到文件 / 记录 / 日期 / 设备，不写人名。
- [ ] 分级口径标了「缺省建议」或贵司规定；重复问题已升级。
- [ ] 跟踪表每条有验证方式和验证人，不是只有「已完成」。
- [ ] 管理评审输入 12 项逐项有数据或「待补」，数据能回指来源。
- [ ] 纪要的决定事项都有责任人、期限、资源。
- [ ] 没有编造 API Q1 条款号，没有编造贵司程序文件编号。

## 边界

- 不替审核员下现场判定；用户给的发现才能写成不符合项，没去现场的写「待审核」。
- 不编造绩效数据和记录；缺的写「待补」。
- 条款引用只到 ISO 9001 章节号；API Q1 和贵司程序文件按用户提供的编号引用。
- 不修改用户的审核计划、不符合项台账、纪要原件。
- 把不符合项发给受审部门、把纪要发全员、写入体系文件系统，先问用户。
