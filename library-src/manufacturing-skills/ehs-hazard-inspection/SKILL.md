# 安全隐患排查与事故报告

把安全员手里的隐患排查表、事故经过和月度数据整理成三样东西：谁在什么时候之前整改什么的清单、逾期项汇总、结构完整的事故 / 未遂事件报告，再加一张月度安全统计表。

## 适用场景

- 周检、月检后隐患排查表里几十条记录，要分级、定责任人和期限，形成整改清单。
- 安全例会前要知道哪些隐患到期没改、挂了多少天、集中在哪个区域。
- 出了事故或未遂事件（险肇），要写一份结构完整的报告交给领导或上级。
- 月底要出安全统计：隐患数、整改率、事故和未遂事件、培训情况。
- 客户或审核方要看隐患闭环记录，要把表整理得能追溯。

## 需要的输入

| 输入 | 常见形式 | 常见列名（以用户文件为准） |
| --- | --- | --- |
| 隐患排查表 | Excel，每行一条隐患 | 日期（排查日期 / 发现日期）、区域（车间 / 部位 / 位置）、隐患描述、类别（设备 / 电气 / 消防 / 起重 / 危化品 / 职业健康 / 现场管理 / 作业行为）、级别（一般 / 重大）、整改措施、责任人（责任部门）、整改期限（完成日期 / 期限）、验收人、状态（未整改 / 整改中 / 已整改 / 已验收 / 已关闭）、完成日期、照片 |
| 事故 / 未遂事件描述 | 口述、事故快报、微信记录 | 时间、地点、涉及人员与岗位、设备或作业、经过、伤害情况、财产损失、目击人、现场处置、报告时间 |
| 月度安全数据 | 培训记录、事故台账、工时记录 | 培训日期、主题、参加人数、应到人数、考核结果；事故件数与类型；总工时或在册人数（用于计算率，有就用，没有不编） |
| 贵司安全制度 | 隐患分级标准、整改时限、事故报告流程 | 有就以它为准；没有就用本技能的缺省口径并注明 |
| 统计范围 | 用户口头给：月份、起止日期、「今天」是哪天 | — |

缺隐患排查表就做不了整改清单和逾期汇总，先要。缺事故描述就不写报告。缺「今天」不能算逾期，先问。缺贵司制度用缺省口径，成稿时写明「按通用口径，待对照贵司制度」。

## 工作步骤

1. **定范围。** 确认统计月份或起止日期、「今天」是哪天。用户没说就问，不要自己猜。
2. **读全排查表。** 看有几张工作表、表头在第几行、末尾有没有合计行；记下文件名、工作表、数据行数。
3. **统一写法。** 把同一含义不同写法的列和值对齐：「责任人」=「责任部门」、「已整改」=「已完成」、「闭环」=「已关闭」；类别写法不同（「吊装」「起重」「行车」）要合并，合并口径列给用户认可。
4. **分级。** 有贵司分级标准按它来；没有就按「行业口径」里的缺省判断分一般 / 重大，并把每条重大隐患的判定理由写出来给用户确认。用户的级别和缺省判断不一致时以用户为准，但把差异列出。
5. **生成整改清单。** 每条隐患带责任人、期限、验收人、状态；责任人或期限空着的标「待指定」，不替用户填。重大隐患按贵司规定要求立即停用或采取临时措施，清单里单列。
6. **算逾期。** 逾期 = 今天晚于整改期限且状态不是已验收 / 已关闭；算已逾期天数；按区域、责任人、类别各汇总一次；同一隐患多次出现在不同排查记录里的（同区域同描述）要合并并标「重复发现」。
7. **写事故 / 未遂事件报告。** 按「输出」里的结构，经过只写用户给的事实，直接原因和间接原因分开写，损失按用户给的数据写，纠正与预防措施分临时措施和长期措施；责任分析一节留空给用户。
8. **出月度统计。** 隐患数（按级别、类别、区域）、整改率（口径见「行业口径」）、事故与未遂事件件数、培训场次与覆盖率；每个数字能回指到来源。
9. **给用户核对。** 先发分级结果、逾期汇总和统计表让用户确认口径，再出全文。

## 行业口径与判断规则

**隐患分级（按贵司制度；缺省两级）**

- 重大隐患（缺省判断）：可能导致人员死亡、重伤、多人受伤，或重大财产损失、重大环境事件，或需要停产停用才能整改的。车间里常见的例如：起重设备制动或限位失效仍在用、热处理燃气炉泄漏或联锁失效、淬火油槽附近消防设施失效、受限空间作业无通风和监护、高压液压试压无防护区、消防通道被完全堵死、主要电气柜无接地或裸露带电。
- 一般隐患（缺省判断）：其余可能造成轻伤或较小损失、且能限期整改不需停产的，例如防护罩缺失、地面油污、灭火器压力不足、劳保穿戴不规范、物料堆放超高。
- 判定要看后果严重程度和发生可能性，拿不准的往上靠并注明「建议按重大处理，待贵司确认」。
- 国家对事故有分类等级（特别重大、重大、较大、一般），企业的隐患分级要和贵司制度对应；本技能不引用具体法规条款号和处罚标准。

**整改时限与逾期**

- 整改时限按贵司规定，缺省建议：一般隐患 7 天内整改完成；重大隐患立即采取停用或隔离等临时措施，整改期限由贵司按风险确定并报备。
- 逾期按用户给的「今天」算；期限空着的不算逾期但列为「未定期限」。
- 延期要有记录（谁批准、延到几号、理由），没有延期记录的到期即逾期。
- 验收：整改完成后要有验收人确认才算关闭；状态是「已整改」但没有验收人的标「待验收」，不算关闭。

**整改率口径**（成稿时写明）

- 缺省口径：整改率 = 截至统计日已验收关闭的隐患数 ÷ 截至统计日整改期限已到的隐患数。期限未到的不计入分母。
- 另一种口径是按本月发现的全部隐患算，数值会偏低；用户要哪种就用哪种，但要声明。
- 重大隐患的整改率单独算，不和一般隐患混在一起。

**事故与未遂事件**

- 事故分类和等级按国家事故分类和贵司制度；本技能不给人数、金额阈值。
- 未遂事件（险肇、险情）是没有造成伤害或损失但差一点就出事的事件，要单独统计，不并入事故，也不因为「没出事」就不记。
- 直接原因：人的不安全行为（违章操作、未穿戴劳保、未断电上锁）和物的不安全状态（防护缺失、设备故障、照明不足）。
- 间接原因：管理缺陷（培训不到位、制度缺失、检查未发现、隐患整改不及时、设备维护不到位）。
- 原因分析只写有依据的事实和用户的判断；没有证据的写「待调查」。责任分析（谁负什么责任）留给用户和贵司的调查组。
- 纠正措施针对本次事故（修复、更换、停用）；预防措施针对根本原因（制度、培训、设计改进、检查频次），要写清负责人和完成期限。

**月度安全统计口径**

- 隐患数按发现日期落在本月计；跨月未关闭的隐患在「结转」里单列。
- 事故件数按发生日期计；未遂事件单列。
- 培训覆盖率 = 实际参加人数 ÷ 应参加人数；应参加人数以用户给的为准，没有就只列场次和人数。
- 有总工时数据时可算工伤率等指标，口径按贵司规定；没有总工时就不算，不编。

**油田工具厂车间常见隐患类别**（用来核对排查表是否漏项，不是排查表本身）

- 机加：卡盘扳手未取下、防护罩缺失、切屑飞溅、长料伸出主轴无防护、吊装棒料无专人指挥、冷却液地面湿滑。
- 热处理：高温辐射与烫伤、燃气泄漏与联锁、淬火油槽火灾与排烟、一氧化碳与通风、行车吊运热件路线。
- 装配与试验：液压试压防护区与压力表校验、起重与翻转、螺纹上扣区域夹手、受限空间（大型缸体内部）。
- 仓储与危化品：油品与化学品存放、消防器材、通道与堆高、叉车作业。
- 公共：电气柜接地与防护、应急照明与疏散指示、劳保穿戴、动火作业审批。

**常见坑**

- 同一隐患每周被重复发现、每次都算新隐患，整改率被稀释；要合并并标「重复发现」。
- 状态写「已整改」但没验收人就关闭。
- 把未遂事件当没事；把「没出事」当「安全」。
- 事故报告把责任写在原因里，调查还没做就下结论。

## 输出

整改清单：

```markdown
# 隐患整改清单（统计日：YYYY-MM-DD）
| 序号 | 发现日期 | 区域 | 隐患描述 | 类别 | 级别 | 整改措施 | 责任人 | 期限 | 验收人 | 状态 | 已逾期天数 | 来源 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | | 机加车间 | | 设备 | 重大 | | | | | 整改中 | 3 | 排查表 › 第 5 行 |
重大隐患单列在前；责任人或期限空着的标「待指定」
```

逾期未整改汇总：

```markdown
## 逾期未整改汇总
| 区域 | 逾期条数 | 其中重大 | 最长逾期天数 | 责任人 |
按区域、责任人、类别各一张；逾期最久的前 5 条逐条列出，带行号
```

事故 / 未遂事件报告结构：

```markdown
# 事故（或未遂事件）报告
## 一、基本信息
时间、地点、涉及人员与岗位、设备或作业、报告人、报告时间、事件类型（事故 / 未遂）
## 二、经过
按时间顺序只写事实，注明信息来源（当事人陈述 / 目击人 / 监控 / 记录）
## 三、直接原因
人的不安全行为 / 物的不安全状态，每条注明依据
## 四、间接原因
管理缺陷，每条注明依据；证据不足的写「待调查」
## 五、损失
人员伤害（部位、程度、是否就医）、财产损失（设备、物料、估算金额按用户给的）、停产时间
## 六、纠正措施与预防措施
| 措施 | 类型（纠正 / 预防） | 负责人 | 期限 | 验证方式 |
## 七、责任分析
（留给用户按贵司制度填写）
## 八、附件
照片、记录、证人陈述清单
```

月度安全统计：

```markdown
# 安全月报（YYYY 年 M 月）
| 指标 | 本月 | 上月 | 口径 |
| --- | --- | --- | --- |
| 发现隐患数（一般 / 重大） | | | 按发现日期 |
| 已关闭数 / 整改率 | | | 缺省口径见说明 |
| 逾期未整改数 | | | 统计日 |
| 结转隐患数 | | | 跨月未关闭 |
| 事故件数（按类型） | | | 按发生日期 |
| 未遂事件件数 | | | 单列 |
| 培训场次 / 参加人数 / 覆盖率 | | | 应到人数以用户给的为准 |
按区域、类别的隐患分布表；本月重大隐患和事故的简述；下月关注点 3–5 条
## 数据来源
文件名、工作表、数据行数、本月范围内行数；合并口径说明
```

数字后面的来源写法：`（隐患排查表-9月.xlsx › 排查记录 › 第 5、12、18 行）`。

## 交付前自检

- [ ] 「今天」和统计范围是用户给的，逾期天数按它算。
- [ ] 每条重大隐患都写了判定理由，并标明是贵司标准还是缺省判断。
- [ ] 责任人、期限空着的标了「待指定」，没有替用户填。
- [ ] 整改率的分子分母和声明的口径一致；重大隐患单独算。
- [ ] 重复发现的隐患已合并并标注；合并口径经用户认可。
- [ ] 事故报告里直接原因与间接原因分开，责任分析一节留空。
- [ ] 没有引用法规条款号和处罚标准；没有编造贵司制度。
- [ ] 每个数字能回指到文件、工作表、行号；缺的数据写在「数据来源」里。

## 边界

- 不认定事故责任，不给处罚建议；责任分析和处理由用户和贵司按制度进行。
- 不替代应急处置：有人受伤或险情还在持续，先救人、先报告、先隔离，本技能只做事后整理。
- 不引用具体法规条款号、处罚金额和事故等级的人数金额阈值；需要时请用户查贵司制度和现行法规。
- 不修改用户的原始排查表和事故记录；不补数据。
- 向上级、客户或监管部门报送报告、写入系统、通知责任人，都要先问用户。
