# 运维手册

> **读者**：日常维护这套东西的人。
> **什么时候读**：有人要加进来、有人走了、有人说用不了、月底要看用量、要升级。
> **前置**：这套东西已经搭好了。没搭好看 [01-管理员初始化手册](./01-管理员初始化手册.md)。

---

## 0 · 三十秒速查

| 我要… | 命令 |
| --- | --- |
| 加人 | 改 `roster.csv` → `roster.ps1 -Import` → `-AccessList` → 把邮箱贴进 Access 策略 |
| 删人 | `roster.ps1 -Remove <邮箱>` → **同时**去 Access 策略删掉 |
| 调额度 | `roster.ps1 -Add <同一个邮箱> -Name <姓名> -Rpd 3000`（重复登记即覆盖） |
| 临时停用 | `roster.ps1 -Add <同一个邮箱> -Name <姓名> -Rpd 0` |
| 看名单 | `roster.ps1 -List` |
| 看本月用量 | `usage_report.py --month 2026-08 --by-dept` |
| 看今天谁快撞限额 | `usage_report.py --days 1 --quota` |
| 测中转通不通 | `test_relay.py` |
| 提交代码前 | `check_pii.py` |

所有 `roster.ps1` 命令可以在任意目录下跑，脚本内部会自己切到 `gemini-relay/worker`。
前提是在那个目录下 `npx wrangler login` 过一次。

## 1 · 加人 / 删人：记住是两道闸

| 闸 | 工具 | 管什么 | 生效延迟 |
| --- | --- | --- | --- |
| Access 策略 Emails | Cloudflare 控制台 | 谁收得到验证码 | 立刻 |
| KV 名单 | `roster.ps1` | 谁换得到令牌、令牌还有效 | 最长 5 分钟 |

### 加人

```powershell
# 1) 把新同事加进 roster.csv（那份不进 git 的真实名单）
# 2) 导入
.\gemini-relay\scripts\roster.ps1 -Import
# 3) 打印该贴进 Access 策略的完整邮箱列表
.\gemini-relay\scripts\roster.ps1 -AccessList
# 4) 复制输出，粘进 Zero Trust ▸ Access ▸ Applications ▸ gemini-relay-login
#    ▸ Policies ▸ Include ▸ Emails
```

也可以不改 CSV 直接单加，但**建议还是走 CSV**——CSV 是唯一那份完整名单，绕过它迟早对不上账：

```powershell
.\gemini-relay\scripts\roster.ps1 -Add wang@example.com -Name 王五 -Dept 供应链部 -Role staff
```

### 删人

```powershell
.\gemini-relay\scripts\roster.ps1 -Remove wang@example.com
```

删 KV 条目会让他名下**所有设备**的令牌失效（令牌记录只存邮箱，所以不用逐台吊销）。
**然后必须去 Access 策略里也删掉。** 脚本每次都会提醒你。

只删 KV 没删 Access 是最常见的疏漏。这**不是安全漏洞**（他能收到验证码、能过登录页，
但换不到令牌，调不了 Gemini），只是体验上让人困惑——他会看到「这个邮箱不在允许名单里」。

### 生效延迟：5 分钟

Worker 查名单带 `cacheTtl: 300` 边缘缓存，绝大多数请求不触达 KV 中心存储。代价是
**删人后最长 5 分钟内他的令牌仍可能被放行**。离职/设备丢失场景要心里有数，目前没有比
等 5 分钟更快的机制。

真的要立刻切断，只能改 Access 策略 + 等——或者把他的额度直接设成 `0`（见下节），
那个走的是同一条缓存，一样是 5 分钟，但至少不用删人。

## 2 · 额度：调整和停用

三档上限，每人可以单独设：

| 档 | 默认 | 它防什么 |
| --- | --- | --- |
| `rpm` 每分钟请求数 | 30 | **自动循环跑飞**。一轮带工具调用的 agent 对话十几次请求是常态，跑飞的循环一分钟几百次。 |
| `rpd` 每天请求数 | 1200 | 治理。既然各付各的，更像是「你今天用得比平常多得多」的提醒。 |
| `tpd` 每天 token 数 | 5000000 | 同上，按量而不是按次。 |

三个哨兵值：**留空 = 用默认值，`-1` = 不限，`0` = 停用**。

```powershell
# 给某人放宽日上限（重复登记就是覆盖，姓名部门要一起带上，否则会被清空）
.\gemini-relay\scripts\roster.ps1 -Add li@example.com -Name 李四 -Dept 技术研发部 -Rpd 3000

# 临时停用：人还在名单和 Access 策略里，但所有请求 429
.\gemini-relay\scripts\roster.ps1 -Add li@example.com -Name 李四 -Dept 技术研发部 -Rpd 0

# 恢复：把那一档改回留空（用默认）或具体数字
```

**改额度和停用只动 KV 一边**，不用碰 Access 策略。这正是把停用做成 `0` 而不是删人的原因——
不会留下「删了一半」的状态，也随时可逆。

**`rpm` 不建议对任何人设成 `-1`**，包括管理员自己。那道闸拦的是失控循环不是省钱；真要跑
批量任务临时调高（比如 `-Rpm 120`），跑完改回来。

看当前生效的上限：

```powershell
.\gemini-relay\scripts\roster.ps1 -List
```

`Limits` 那一列会显示「默认 / 不限 / 停用 / 具体数字」。显示「默认」的取 `wrangler.jsonc`
里的 `QUOTA_*`。

## 3 · 看数据

### 用量报表

先设三个环境变量（一次性，建议写进 PowerShell profile）：

```powershell
$env:CF_API_TOKEN     = "..."   # 只需要 Account / D1 / Read 权限
$env:CF_ACCOUNT_ID    = "..."
$env:CF_D1_DATABASE_ID = "..."  # npx wrangler d1 info gemini_relay_usage 能查到
```

```powershell
$py = "C:\Users\liude\github\openworker\.venv\Scripts\python.exe"

& $py gemini-relay\scripts\usage_report.py                                 # 最近 30 天，每人一行
& $py gemini-relay\scripts\usage_report.py --month 2026-08 --by-dept       # 8 月，按部门
& $py gemini-relay\scripts\usage_report.py --days 1 --quota                # 今天的限额闸门读数
& $py gemini-relay\scripts\usage_report.py --month 2026-08 --by-model --csv usage-08.csv
```

**`usage` 和 `quota` 两张表回答的问题不一样**：`usage` 是流水账，问「这个月谁用了多少」；
`quota` 是当下的闸门读数，问「谁今天快撞墙了」。quota 的分钟桶三天后被定时任务清掉，
所以它只能看今天，历史一律查 `usage`。

`--quota` 输出里的 `peak_per_min` 是今天最忙的那一分钟打了多少次——比「此刻是多少」有用得多，
一次跑飞的循环在这一列上非常明显。

口径提醒：报表统计的是**经中转的 token 数**，供内部按人归因用。权威计费口径以 Google 侧
（各人自己的 AI Studio 后台）为准，两者不保证逐位对齐。

### 登录审计

`auth_events` 表记录每一次登录的成败。同事说「登不上」时先查这张表，它会告诉你失败在哪一段：

```sql
SELECT ts, email, event, detail, country
FROM auth_events
WHERE ts >= datetime('now', '-2 days')
ORDER BY ts DESC;
```

| `event` | 含义 |
| --- | --- |
| `login-ok` | 过了验证码、也在名单里，已签发一次性 code |
| `login-denied` + `not in roster` | 过了验证码但 KV 名单里没有他 → 只加了 Access 没加 KV |
| `token-issued` | 令牌真的发出去了 |
| `token-denied` + `pkce mismatch` | 兑换请求不是发起登录的那个进程发的 |
| `logout` | 主动登出 |

**没有任何记录** = 他根本没走到 Worker。要么没点登录，要么被 Bot 挑战拦在门外（见第 5 节）。

### 被限额拦了多少次

```sql
SELECT email, error, COUNT(*) AS blocked
FROM usage
WHERE status = 429 AND ts >= datetime('now', '-7 days')
GROUP BY email, error
ORDER BY blocked DESC;
```

`error` 是 `quota-rpm` / `quota-rpd` / `quota-tpd` / `quota-suspended` 之一，直接告诉你撞的是哪一档。

## 4 · 例行检查

不用天天看，建议节奏：

**每周**——扫一眼 `--quota`，看有没有人的 `peak_per_min` 异常高（跑飞的信号）。

**每月**——出一次 `--month YYYY-MM --by-dept`，顺便核对名单和实际在职人员对不对得上。

**人员变动时**——立刻做，别攒着。攒着最容易出「离职了还能收验证码」这种事。

**每次改完名单**——`-List` 确认一遍，尤其是用 `-Add` 覆盖额度的时候：**姓名和部门要一起带上，
不带会被清空**（`-Add` 是整条覆盖，不是局部更新）。

## 5 · 同事报障：按症状分诊

先问一句「**你是登不上，还是登上了用不了？**」——这一句能把范围砍一半。

| 症状 | 先看哪里 | 多半是什么 |
| --- | --- | --- |
| 收不到验证码 | Access 策略的 Emails 列表 | 邮箱不在里面。**被拒的人不会收到邮件，但页面仍显示「验证码已发送」**（Cloudflare 故意不泄露谁在名单里）。其次让他看垃圾箱——名单里有几个 QQ 邮箱。 |
| 填了码说「这个邮箱不在允许名单里」 | KV 名单 | 只加了 Access 没加 KV。跑 `-Import`，等 5 分钟。 |
| 验证码说「已被使用」 | — | 企业邮箱的安全网关替他点了邮件里的链接，把一次性码消费掉了。让他**手动输入 6 位码**而不是点链接。 |
| 登录成功但应用里还是「未登录」 | 本机回环 | 浏览器回跳的是 `http://127.0.0.1:<随机端口>/relay/callback`。本机装了拦截回环请求的安全软件会失败。让他看那个标签页停在什么页面。 |
| 「还没有填自己的 Gemini API key」 | 用户侧 | 只做了一半。让他去 https://aistudio.google.com/apikey 申请再填进设置。 |
| 「客户端版本过旧」 | 用户侧 | 装的是旧版应用，把令牌塞在了 key 的位置。升级客户端后重新登录一次。 |
| 「今天的额度用满了」/ 429 | 限额闸门 | 错误文案会写明是每分钟还是每天。每分钟那档等一分钟；每天那档等次日 0 点或调高。 |
| 用着用着提示要重新登录 | 令牌 | 30 天到期，或者他被移出名单了。重新点登录；真被收回会停在「不在允许名单里」。 |
| 收到一整页 `Just a moment...` 的 HTML | zone 安全设置 | Bot Fight Mode 把程序化请求判成 bot 了。见下。 |

### Bot 挑战那一条单独说

zone 上的 Bot Fight Mode / Super Bot Fight Mode 会在请求**到达 Worker 之前**就把它拦下，
返回挑战页。`/login/*` 是真浏览器不受影响，**`/auth/*` 和 `/v1beta/*` 会被彻底打死**。

特征：403，响应体是 HTML，里面有 `_cf_chl_opt` / `cRay` / `challenge-platform` 字样。

处理：Cloudflare 控制台 ▸ Security ▸ Bots 关掉；或更精细地在 Security ▸ WAF ▸ Custom rules
建一条 `Hostname equals gemini.smjtools.com` → Skip 挑战类规则。顺手检查 Security ▸ Settings
的 Security Level 有没有被设成 High / "I'm Under Attack"。

**这不是「配得越严越好」的地方**——这个端点本来就是给程序调用的，没有浏览器去解挑战。

## 6 · 升级

### 升级中转（Worker）

```powershell
cd gemini-relay\worker
git pull
npm install
npx wrangler d1 migrations apply gemini_relay_usage --remote   # 有新迁移才需要
npx wrangler deploy
```

Worker 部署是原子的，秒级切换，同事无感。回滚就是 `git checkout <上一个 commit>` 再 deploy，
或者在 Cloudflare 控制台的 Deployments 里点回滚。

**注意迁移不可回滚**。加列、建表是向前兼容的（旧代码不读新列），但如果某次迁移改了现有列的
含义，回滚代码前要想清楚数据怎么办。

### 升级桌面端

同事那边不会自动更新（没配更新签名 key，见
[01-管理员初始化手册第 6 节](./01-管理员初始化手册.md#6--为什么-github-上没有可下载的-dmg--exe)），
所以每次升级都要发新包 + 通知。

流程见管理员手册第 6 节。核心是：**抬版本号 → 提交 → 打 tag → 推 tag → 等构建 → 发布草稿**。

> 值得花半小时做的一件事：配 `TAURI_SIGNING_PRIVATE_KEY` secret（免费，
> `npx tauri signer generate` 生成），之后应用就能自己提示升级，省掉每次通知全公司下载。

## 7 · 事故处置

### 有人的 key 泄露了

**不用你做任何事。** 中转不持有任何人的 key，泄露只影响他自己。让他去 Google 后台
（https://aistudio.google.com/apikey）删掉那把、生成新的，在 OpenWorker 里填新的。其他人不受影响。

这正是从「共享一把 key」改成「各自带 key」换来的性质——以前这种事要全公司换 key。

### 有人的自动循环跑飞了

1. 先止血：`roster.ps1 -Add <他的邮箱> -Name <姓名> -Rpd 0` 停用，5 分钟内生效。
2. 查现场：`usage_report.py --days 1 --quota` 看 `peak_per_min`，
   `usage_report.py --days 1 --by-model` 看打的什么模型。
3. 问清楚是什么任务，调整后把额度改回来。

代价落在他自己的 Google 账单上，所以这更多是「帮他止损」而不是「追责」。

### 有人离职

1. `roster.ps1 -Remove <邮箱>`
2. Cloudflare 控制台删掉 Access 策略里的邮箱
3. 从 `roster.csv` 里删掉那一行（保持 CSV 是唯一真相）
4. 他机器上的令牌 5 分钟内失效；他自己的 Gemini key 是他自己的，与我们无关

### 中转整个不通了

按 [验证与排错](../../gemini-relay/docs/05-验证与排错.md) 的五级阶梯从下往上定位：
DNS → TLS → REST 裸调用 → SDK 脚本 → 应用端到端。

`curl https://gemini.smjtools.com/healthz` 返回 `ok` 就说明 Worker 活着，问题在更上层。
连 `/healthz` 都不通就是 Worker 挂了或 DNS/证书出问题，去 Cloudflare 控制台看 Deployments。

**中转不可用时没有回退**——这是设计决定：与其静默改连大陆不可达的 Google 原始域名，
不如直接报错。

## 8 · 提交代码前：PII 检查

这个仓库是 **andrewyng/openworker 的公开 fork**，同时装着公司内部的东西。真实姓名配真实邮箱
一旦进了公开 git 历史基本清不掉——改文件没用，历史还在。

```powershell
& "C:\Users\liude\github\openworker\.venv\Scripts\python.exe" gemini-relay\scripts\check_pii.py
```

它拿不进 git 的 `roster.csv` 当黑名单，扫一遍所有会被提交的文件。**这不是形式主义**：
首次运行就在 `tests/test_relay_auth.py` 的测试夹具里抓到一个真实邮箱+姓名——那是写测试时
顺手拿真人当例子留下的。

写文档举例一律用 `alice@example.com` / `张三` 这类占位符。

## 9 · 别做的事

踩过或者差点踩的：

- **别把整个域名挂到 Access 后面**。google-genai 不是浏览器，会被 302 到登录页，应用直接不能用。
  只保护 `/login`。
- **别把关键参数放 query string 过 Access**。Access 做路径匹配时不看 query，跳转中还可能改写它。
- **别给任何人 `rpm = -1`**，包括你自己。那道闸防的是循环跑飞。
- **别用 `-Add` 只带额度不带姓名部门**——那是整条覆盖，姓名会被清空。
- **别把 `roster.csv` 加进 git**。它在 `.gitignore` 里，别用 `git add -f`。
- **别在 zone 上开 Bot Fight Mode**，会把 `/auth/*` 和 `/v1beta/*` 打死。
- **别忘了 `--remote`**。`wrangler d1 migrations apply` 不带它作用在本地模拟存储上，
  线上表根本没建。
- **别找 `wrangler secret` 放 key 的地方**——这个 Worker 一个机密都没有，这是有意的。
