> **读者**：第一次把 OpenWorker + Gemini 中转搭起来的人（名单里 `role=admin` 的那两位）。

## 0 · 先搞清楚你在搭什么

同事装的 OpenWorker 桌面应用，所有 Gemini 请求都走一台 Cloudflare Worker（`gemini.smjtools.com`），
而不是直连 Google——因为 `generativelanguage.googleapis.com` 在大陆不通。这台中转干三件事：

1. **认人**：只有允许名单里的邮箱能用。身份来自 Cloudflare 发到邮箱的一次性验证码。
2. **转发**：把请求原样转给 Google。**每人一把你签发的 Gemini key**，中转一把都不存。
3. **记账 + 限额**：按邮箱记用量、按邮箱设上限，防止有人的自动循环跑飞。

三件事拆开看很重要，因为**登录不等于能用**——同事必须既登录、又填上你发给他的 key，
缺一半就报错。

关于 key 的关键决定：**你在自己的 Google AI Studio 里给每个人建一把，用他的名字命名**，
而不是让 12 个人各自去申请。理由有三条，第三条最实际：

- Google 后台按 key 显示用量，所以你在 Google 那边也能看到每个人花了多少——这是一条
  **独立于我们自己 D1 记账**的交叉校验，两边对不上就说明有人绕过了中转。
- 吊销是按 key 的：删掉一把，正好切断一个人，别人无感。
- 名单里七个部门的同事多半没有能用的 Google 账号，也不该为这件事去折腾一个。

代价要认：这些 key 花的是公司的钱，泄露一把就是公司的账单。所以限额闸门在这个模型下
不是可选的治理工具，而是**唯一在事前起作用的东西**——具体见第 3.5 节和
[06-安全与风险](../../gemini-relay/docs/06-安全与风险.md)。

### 你需要准备的

| 东西 | 说明 |
| --- | --- |
| Cloudflare 账号 | `smjtools.com` 这个 zone 和 gemini-relay 这个 Worker 都在这个账号下。**整套信任模型的地基就是这一条**——中转能看到全部对话明文，账号不在你手里就等于把公司对话交给别人。 |
| Cloudflare Zero Trust | 免费方案够用，用来发验证码。在同一个账号里开通。 |
| Node.js + npm | `npx wrangler` 要用。 |
| 一台能打包的 Windows 机器 | 见第 5 节。macOS 安装包要 Mac 或 GitHub Actions。 |
| 一个能开 Gemini API 的 Google 账号 | 全公司的 key 都从这一个账号签发，账单也记在它头上。 |

时间预算：Cloudflare 那套配置第一次做大约 40 分钟，Worker 部署 10 分钟，签发 12 把 key
大约 15 分钟，打包 20–30 分钟。

## 1 · Cloudflare 侧：让验证码发得出去

完整分步（带截图级别的字段名）在 **[gemini-relay/docs/08-Access登录配置.md](../../gemini-relay/docs/08-Access登录配置.md)**，这里只给骨架和容易踩的地方。

1. **Zero Trust ▸ Settings ▸ Authentication ▸ Login methods**，打开 **One-time PIN**。
   这是唯一不需要接外部身份提供商的登录方式，正好适合我们这种「一堆 QQ 邮箱 + 几个 Gmail」的名单。

2. **建一个自托管 Access 应用**，Path 填 **`login/*`**——只保护这一条路径。
   > 两个都容易做错的地方：
   >
   > **别整域保护。** 直觉是「全保护起来更安全」，但 google-genai SDK 不是浏览器，
   > 整域挂 Access 会让每一次 API 调用被 302 到登录页，应用直接不能用。
   >
   > **星号不能少。** 不带通配符的 Path 是精确匹配，`login` 只保护 `/login` 这一个 URL，
   > 而真正要保护的是 `/login/<sid>`。填错了 Access 不介入，Worker 验签失败，
   > 同事看到「身份校验没通过」而控制台看起来一切正常——很难查。

3. **策略就是允许名单**：Include ▸ Emails，把名单里的邮箱**一个一条规则**加进去。
   `roster.ps1 -AccessList` 会把该加的邮箱一行一个打印出来。
   >
   > **不要拼成逗号串粘进同一个框。** `Emails` 选择器精确匹配**单个**地址，一整串会被原样
   > 存成一个谁都匹配不上的字面值——**全员收不到验证码，而且不报任何错**，登录页照样显示
   > 「验证码已发送」。这个坑非常难查，因为控制台把多条规则也渲染成一行逗号列表，看起来一样。
   > 配完用 API 核一遍 `include`：应该是**每个邮箱一个对象**，不是一个对象塞一长串。

4. **（建议）给登录页挂公司 logo**：Zero Trust ▸ Settings ▸ Custom Pages，logo 填
   `https://gemini.smjtools.com/brand/logo.png`，主色 `#1F7A3C`。同事看到的第一个页面是
   Cloudflare 的，挂上 logo 才不像钓鱼。
   > 必须是 `.png`：Cloudflare 的 logo 字段只收 png/svg/jpg/jpeg，填 webp 会被直接拒。
   > App Launcher 那个 logo 用方形的 `/brand/logo-mark.png`。

5. **记下两个值**填进 `gemini-relay/worker/wrangler.jsonc`：
   - `ACCESS_TEAM_DOMAIN`：`https://smj-cf.cloudflareaccess.com`
   - `ACCESS_AUD`：Access 应用详情页的 Application Audience (AUD) Tag

   两个都不是机密（前者出现在每次登录跳转里，后者出现在每个签发的令牌里），所以放 `vars`。
   **还是 `TODO-…` 占位符时，登录会一律 403。**

## 2 · Worker 侧：建资源、定限额、部署

```powershell
cd gemini-relay\worker
npm install
# 本机 proxy-guard 会留下代理变量，wrangler 直连 api.cloudflare.com 不需要它们
Remove-Item Env:HTTP_PROXY, Env:HTTPS_PROXY, Env:ALL_PROXY -ErrorAction SilentlyContinue
npx wrangler login
```

**首次才要建资源**（输出的 id 填回 `wrangler.jsonc`；现有部署已经建好，跳过）：

```powershell
npx wrangler kv namespace create ROSTER
npx wrangler d1 create gemini_relay_usage
```

**建表**（三个迁移按序号跑，`--remote` 别漏——漏了作用在本地模拟存储上，线上表不存在）：

```powershell
npx wrangler d1 migrations apply gemini_relay_usage --remote
```

| 迁移 | 建什么 |
| --- | --- |
| `0001_init.sql` | `usage` 用量流水表 |
| `0002_login.sql` | 给 `usage` 补 `name`/`dept` 两列，建 `auth_events` 登录审计表 |
| `0003_quota.sql` | `quota` 限额计数器表 |

**定限额**。`wrangler.jsonc` 的 `vars` 里三个数字，是**每个人**的默认上限：

```jsonc
"QUOTA_RPM": "30",        // 每分钟请求数
"QUOTA_RPD": "1200",      // 每天请求数
"QUOTA_TPD": "5000000"    // 每天 token 数
```

一轮带工具调用的 agent 对话轻松十几次请求，所以 rpm 不能按「一条消息一次请求」来估。
默认值是按「一个人用手驱动 agent」的强度定的，跑飞的循环一分钟几百次，几秒就撞上。

**这个 Worker 没有任何 `wrangler secret`。** 不要找放 key 的地方——没有。如果这个部署以前
有过共享 key，顺手清掉那个已经不再被读取的机密：`npx wrangler secret delete GEMINI_API_KEY`。

**部署**：

```powershell
npx wrangler deploy
```

`routes` 里的 `custom_domain: true` 会自动建 DNS 记录和 TLS 证书，通常几分钟内生效
（部署前 `gemini.smjtools.com` 是 NXDOMAIN，这是预期状态不是故障）。同一条命令还会注册
每天清理限额计数桶的定时任务。

## 3 · 名单：两道闸都要过

名单有**两个执行点**，两边都有这个人才真的能用：

| 闸 | 在哪维护 | 管什么 |
| --- | --- | --- |
| Access 策略的 Emails 列表 | Cloudflare 控制台 | 谁能**收到验证码**、过得了登录页 |
| KV 名单 | `roster.ps1` | 谁能**换到令牌**、令牌还有效 |

只加 Access 不加 KV → 能登录但拿不到令牌（看到「这个邮箱不在允许名单里」）。
只加 KV 不加 Access → 连验证码都收不到。

真实名单在 `gemini-relay\scripts\roster.csv`。**这个文件不进 git**——本仓库是公开 fork，
同事的姓名和私人邮箱只留在管理员本机；仓库里只有占位用的 `roster.example.csv`。

CSV 格式：四列必填 + 三列选填限额。

```csv
email,name,dept,role,rpm,rpd,tpd
alice@example.com,张三,技术研发部,lead,,,
admin@example.com,王五,,admin,,-1,-1
```

- `role`：`admin` | `gm`（总经理）| `lead`（部门负责人）| `staff`。目前只用于报表和审计，不影响权限。
- `rpm/rpd/tpd`：留空 = 用 Worker 默认值，`-1` = 不限，`0` = 停用。
- 惯例：**管理员和总经理放开日上限（`-1`）但 rpm 留空**。那道闸防的是循环跑飞，谁都不该关。

```powershell
cd ..\..
.\gemini-relay\scripts\roster.ps1 -Import      # 从 CSV 批量登记，重复运行是幂等的
.\gemini-relay\scripts\roster.ps1 -AccessList  # 打印该贴进 Access 策略的邮箱
```

## 3.5 · 签发 key：每人一把，以人命名

在 **https://aistudio.google.com/apikey** 用那个公司 Google 账号操作：

1. **Create API key**，为名单里的每个人建一把。
2. **改名字**——这一步是整个做法的意义所在。用能一眼对上人的名字，和名单里的 `name` 一致，
   比如 `张三-技术研发部`。改名的入口在 key 列表里点那一行。
3. 记在一个只有你看得到的地方（不是仓库、不是群、不是共享文档）。

命名之后你在 Google 的用量页就能按 key 看到每个人花了多少。**这是和我们自己 D1 记账
互相独立的第二本账**——两边差得多，说明有人拿着 key 绕过中转直接调 Google 了。

### 怎么把 key 交到人手上

一对一给，别群发。可接受：当面、企业 IM 的单聊、或者他登录后你远程口述让他自己敲。
不要走：群聊、共享表格、邮件转发链。

给的时候连着说三句话：这是公司的凭证不是你的；别转给别人；泄露了第一时间说，换一把
是几分钟的事、不追究。第三句尤其要说——瞒着不报才是真正会出事的情形。

### 有人离职或 key 泄露

去 Google 后台删掉那一把即可，**立刻生效**，其他人完全不受影响。这比中转侧的名单删除
（受 5 分钟边缘缓存影响）更快，所以紧急情况下**先删 key，再删名单**。

## 4 · 自查：确认真的通了

按顺序做，每一步都能把故障范围缩小一半。完整的五级阶梯和排错矩阵见
[gemini-relay/docs/05-验证与排错.md](../../gemini-relay/docs/05-验证与排错.md)。

```powershell
curl https://gemini.smjtools.com/healthz                  # 期望：ok
curl -i https://gemini.smjtools.com/v1beta/models         # 期望：401（公开但要登录令牌）
curl -i https://gemini.smjtools.com/login/whatever        # 期望：302 跳 Cloudflare 登录页
```

第三条要是返回 200 或 404 而不是跳转，说明 Access 应用的 Path 没生效，回第 1 节第 2 步。

然后**自己走一遍真流程**：打开 OpenWorker ▸ 设置 ▸ 模型 ▸ Gemini ▸ 登录 → 浏览器收码 → 填码
→ 回到应用应该显示「✓ 已登录」和你的姓名/部门 → 在下面填一把你签发的 key → 点「测试」。

最后跑冒烟测试（它会自动从本机读刚拿到的令牌，并打印你的限额读数）：

```powershell
& "C:\Users\liude\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe" gemini-relay\scripts\test_relay.py
```

两个测试都 PASS 就说明非流式和流式两条链路都通。

> **别把安全设置调过头**：zone 上的 Bot Fight Mode / Super Bot Fight Mode 会把 OpenWorker
> 这种程序化请求判成 bot，返回一整页 `Just a moment...` 的挑战页——请求根本到不了 Worker。
> `/login/*` 是真浏览器不受影响，但 `/auth/*` 和 `/v1beta/*` 会被打死。症状是收到 403 且
> 响应体是 HTML 而不是 JSON。

## 5 · 打包桌面端

本机 Windows 工具链已经跑通过一次，构建会话需要设置的环境：

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;" + $env:PATH
$env:LIBCLANG_PATH = "C:\Users\liude\.llvm\bin"
$env:PATH = "C:\Program Files\Microsoft Visual Studio\18\Professional\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin;" + $env:PATH
$env:TAURI_BUNDLER_TOOLS_GITHUB_MIRROR = "https://gh-proxy.com"
.\packaging\build_windows.ps1
```

产物在 `surfaces\gui\src-tauri\target\release\bundle\{nsis,msi}\`。

几个已知的坑：

- **PyInstaller / typer / Pillow 是临时装进根 `.venv` 的**，跑一次 `uv sync` 会被清掉。
  前两个打包要用，Pillow 是 `gen_brand_assets.py` 转 png 要用。缺了就
  `uv pip install --python .venv/Scripts/python.exe pyinstaller typer tzdata pillow`。
- `build_windows.ps1` 会无差别 `Stop-Process` 所有 `openworker-server` 进程，**包括你正在用的
  安装版应用的 sidecar**。介意的话手动跑脚本里的三步。
- **产物未签名**：Windows 首次运行会弹 SmartScreen，要点「更多信息 → 仍要运行」。macOS 的
  .dmg 同理，未公证的话要 `xattr -cr /Applications/OpenWorker.app`。这一条要提前告诉同事，
  否则他们会以为装到了病毒。

## 6 · 发版：让 GitHub 上有可下载的安装包

`.github/workflows/release.yml` 会在**推 tag** 时构建三个平台并把产物挂到一个 GitHub
Release 上。三条容易踩的规则先说在前面：

1. **只有 tag 触发**。release 那个 job 的条件是 `if: startsWith(github.ref, 'refs/tags/v')`。
   在网页上手动点「Run workflow」也能构建，但 `github.ref` 是 `refs/heads/main` 不是 tag，
   release job 会被跳过，产物只留在 workflow artifact 里（要登录才能下、还会过期）。
   2026-08-20 那次「构建成功但仓库里什么也看不到」就是这么来的。
2. **生成的是草稿**。workflow 写死 `draft: true`，要你手动点 Publish 才对外可见。这是有意的。
3. **tag 必须等于 `tauri.conf.json` 的 `version`**，否则 job 直接报错退出——不然装好的应用
   会看到一个永远装不上的幻影更新。

### 步骤

```powershell
# 1) 抬版本号：改 surfaces/gui/src-tauri/tauri.conf.json 的 "version"
# 2) 提交并推
git add surfaces/gui/src-tauri/tauri.conf.json
git commit -m "Prepare app release 0.1.9"
git push origin main
# 3) 打 tag 并推 —— 这一步才触发 release job
git tag v0.1.9
git push origin v0.1.9
# 4) 等约 21 分钟（三个平台并行构建）
# 5) GitHub ▸ Releases，review 那个草稿，点 Publish
```

发布后固定下载链接（永远指向最新版，不用改）：

```
https://github.com/ldfpku/openworker/releases/latest/download/OpenWorker-windows-setup.exe
https://github.com/ldfpku/openworker/releases/latest/download/OpenWorker-macos-arm64.dmg
```

### 自动更新已经配好了

`TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 两个 Actions secret 已经
生成并写进仓库（2026-08-22）。有了它，构建会额外产出签名的更新工件和 `latest.json`，
装好的应用会自己发现新版本——**你不用再挨个通知同事下载**。

两件必须知道的事：

- **私钥要备份**。它只存在 GitHub secret 里（secret 存进去之后**读不出来**）和当时生成它的
  那台机器上。丢了就再也签不出能被现有安装接受的更新包——所有人只能手动重装一次新版。
  把它存进密码管理器，现在就存。
- **`tauri.conf.json` 的 `plugins.updater.endpoints` 必须指向我们自己的仓库。** 上游模板里
  写的是 `andrewyng/openworker` 和 `download.openworker.com`，照抄的话同事的应用会去拉
  **上游的**版本，把带中转和汉化的这一版覆盖成原版英文应用。已经改成
  `ldfpku/openworker` 了，以后从上游合并时留意别被改回去。

### 没做的两样签名（有意的）

- **Apple 签名/公证**：需要 $99/年的开发者账号。不做的代价是 macOS 用户装完打不开，
  要 `xattr -cr /Applications/OpenWorker.app`。
- **Windows Authenticode**：要买证书。不做的代价是每次首装弹 SmartScreen，
  点「更多信息 → 仍要运行」。

这两个和自动更新是**互相独立**的——上面那个更新签名是 Tauri 自己的 minisign，免费，
和操作系统的代码签名没关系。

## 7 · 分发给同事

给他们两样：

1. **安装包**（`OpenWorker-windows-setup.exe`，或发布后的 GitHub 下载链接）
2. **[03-用户手册](./03-用户手册.md)** 的链接或打印件

然后口头强调三件事，因为这三件事是最容易卡住的：

- **要做两步**：登录（收验证码）**和**填你发给他的 Gemini API key。只做一步用不了。
- **key 是公司的**：别转发、别贴群、别提交进仓库；泄露了第一时间说。
- **首次运行会弹安全警告**：包没签名，点「更多信息 → 仍要运行」。
