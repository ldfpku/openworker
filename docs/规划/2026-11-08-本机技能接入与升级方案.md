# 本机技能接入与升级方案（2026-11-08）

## 范围与依据

- 目标：让程序直接使用用户用其他代理工具（`npx skills`、Claude Code、Kiro 等）装在本机的技能；在「设置 ▸ 技能」里列出每个技能的状态，勾选有更新的技能升级。
- 本库代码基线：`v1.2.4`（`0d9a0bfa`）。
- 行业做法参照 [vercel-labs/skills](https://github.com/vercel-labs/skills)：`skills check` 只检查、`skills update [names]` 按名升级；全局锁文件 `~/.agents/.skill-lock.json`（v3）每条记录 `source`、`sourceUrl`、`skillPath`、`skillFolderHash`（GitHub 上技能文件夹的 tree SHA）；各代理的全局技能目录见其 `docs/agents.md`。
- `disable-model-invocation: true` 沿用 Claude Code 技能 frontmatter 的同名字段。

## 二、来源与升级 §1–§8（本次新增）

### §1 来源与默认关闭

- 只扫用户级目录：`~/.agents/skills`、`~/.claude/skills`、`~/.kiro/skills`、`~/.codex/skills`、`~/.cursor/skills`、`~/.gemini/skills`、`~/.config/opencode/skills`，加用户自己添加的目录。
- 所有来源默认关闭，由用户逐个打开。项目里的代理目录（如 `<仓库>/.claude/skills`）不扫：别人的仓库可以借它往会话里塞指令。
- 自定义目录必须是已存在的绝对路径，不能是家目录、磁盘根目录，也不能是本程序自己的技能目录。
- 外部技能原地只读引用，不复制。编辑、删除、移动一律拒绝，提示到原工具里管理；可以单个启用/停用（和自己的技能共用 `skills-settings.json` 的停用名单），可以显示文件夹。
- 状态存 `state_dir()/skill-sources.json`。代码：`coworker/skills/external.py`。

### §2 优先级与去重

- 同名技能的生效顺序：项目 > 全局 > persona > 外部。加载器按「优先级低的在前」排目录，后扫到的覆盖先扫到的。
- 外部来源之间按来源表顺序，`agents` 最先。
- 多个来源里指向同一真实路径的条目（链接、junction）只算一个，记在 `also_in`；同名但内容不同的，排在前面的来源生效。
- 自己的技能遮蔽同名外部技能，外部行标 `shadowed_by`。

### §3 调用方式与手动门控

- 外部技能默认「仅手动」（`manual`）：不进每轮目录，用户 `/技能名` 时才加载正文。可以单个切成「自动」（`auto`）。
- frontmatter 写了 `disable-model-invocation: true` 的技能一律只能手动，界面上锁定。这一条对自己的技能也生效。
- 门控：`load_skill` 的放行集合＝有效菜单 −（手动技能 − 本会话手动调用过的 − 本会话历史里已加载过的）。强制运行校验通过后登记「已手动调用」；历史里已加载过的照样放行，服务重启后不会把它误判成「被关掉」。
- 手动技能不出现在 `load_skill` 报错返回的 `available` 列表里。
- 定时任务里没有强制运行，手动技能在定时任务里不可用；需要的话切成自动。
- 调用方式存 `skill-sources.json` 的 `invocation`。

### §4 目录上限

- 每轮目录总长度上限 4000 字（`_CATALOG_BUDGET_CHARS`）。不超时输出和以前逐字一致。
- 超出时按 项目 → 全局 → persona → 外部 的顺序给描述，放不下的只列名字，合并成一行。

### §5 状态模型

| 状态 | 含义 |
| --- | --- |
| `up_to_date` | 已是最新 |
| `available` | 有更新 |
| `modified` | 本地已修改（无更新） |
| `modified_and_available` | 有更新，且本地已修改或无法确认没改过 |
| `untracked` | 无来源记录，不可升级（手动创建、上传的技能，外部目录里 lock 没记录的技能） |
| `unsupported` | 来源类型不支持（非 GitHub）或 lock 版本未知 |
| `unchecked` | 还没检查过 |
| `error` | 检查出错（含 API 额度用尽和恢复时间） |

- 外部技能：对照 `~/.agents/.skill-lock.json` 和 GitHub 远端。
- 库技能：安装时在 `state_dir()/skills-library-lock.json` 记文件清单作基线，对照「已安装 / 基线 / 当前库」三份内容；已装但没有基线的老技能，内容等于当前库就静默补基线，否则按「有更新且可能改过」处理。库技能不联网，每次列表都比对。

### §6 检查策略与 API 额度

- 有「检查更新」按钮；打开技能页时距上次检查超过 24 小时，在后台自动查一次。结果存 `skills-update-cache.json`。
- 只检查已打开来源里列出的外部技能。按仓库分组，每个仓库调一次 `GET /repos/{o}/{r}/git/trees/HEAD?recursive=1`；结果被截断时按路径逐级取子树。最多 4 个并发，单次 30 秒超时。
- 本地修改检测不在本地重算目录 tree 哈希（Windows 读不到可执行位，会误报），而是逐个文件算 git blob SHA，和锁定版本的文件清单比对；不一致时把 CRLF 换成 LF 再比一次。锁定版本的树按 SHA 永久缓存。
- 不带 token 时 GitHub 每小时 60 次；设置 `GITHUB_TOKEN` / `GH_TOKEN` 后为 5000 次。token 只从环境变量读，不进日志和返回结果。
- 额度用尽时返回 `error` 和恢复时间，不重试。

### §7 升级与备份回滚

- 「有更新」的行可勾选；本地已修改的默认不勾，勾了要再确认（接口要求 `overwrite_modified`，否则返回 `modified_requires_confirm`）。
- 外部技能升级：重新取远端树 → 从 `raw.githubusercontent.com` 下载、逐个校验 blob SHA → 暂存目录过 `hygiene` → 旧版本改名移入 `state_dir()/skills-backups/<name>/<时间戳>/` → 新版换入 → 写回 lock（只改这一条的 `skillFolderHash` 和 `updatedAt`）。`npx skills check` 因此也认这次升级。
- 其他代理目录里的同名条目：指向同一真实路径的链接不用动；独立副本内容等于旧版本时一并更新并备份，否则保留并在结果里说明。
- 库技能升级：从当前库复制，备份机制相同，更新基线。库页的「恢复原版」也改成先备份再替换。
- 回滚：恢复最近一份备份（含 lock / 基线条目），当前版本直接丢弃（它能重新升级得到）。每个技能保留最近 3 份备份。
- 任何一步失败，原目录保持不动；Windows 上文件被占用时给出友好提示。

### §8 安全边界

- 只从 lock 记录的 GitHub owner/repo 下载，owner/repo 用正则校验；树里的路径禁止 `..` 和绝对路径；软链接（120000）和子模块（160000）条目跳过并报告。
- 下载内容过 `hygiene`：含密钥文件整项拒绝，构建垃圾剔除并报告，检查文件大小、总量、个数、深度。
- 写 `state_dir()` 之外（`~/.agents/skills`、lock 文件、其他代理目录）只在用户明确点击升级或回滚时发生。
- lock 写回先重新读一遍，其余条目和字段原样保留，写临时文件后 `os.replace`。
- `load_skill` 返回的外部技能带 `origin: external` 和来源目录，模型能分辨这是第三方内容。

## 三、接口

| 接口 | 作用 |
| --- | --- |
| `GET /v1/skills/sources` | 来源列表：id、名称、路径、是否存在、技能数、是否打开、是否自定义 |
| `PATCH /v1/skills/sources/{id}` | `{enabled}` 开关来源 |
| `POST /v1/skills/sources` | `{path, label}` 添加自定义目录 |
| `DELETE /v1/skills/sources/{id}` | 移除自定义目录 |
| `GET /v1/skills` | 原有字段不变，新增 `origin`（own / library / external）、`source_id`、`source_label`、`read_only`、`shadowed_by`、`also_in`、`invocation`、`invocation_locked`、`update`、`can_rollback` |
| `PATCH /v1/skills/{name}` | 新增 `invocation: auto|manual`（只对外部技能） |
| `GET /v1/skills/updates` | 缓存的检查结果、`checked_at`、`stale`、`available_count` |
| `POST /v1/skills/updates/check` | 立即检查外部技能 |
| `POST /v1/skills/updates/apply` | `{items:[{name, origin, overwrite_modified}]}`，逐项返回结果 |
| `POST /v1/skills/{name}/rollback` | 恢复最近一份备份 |

### 实测（2026-11-08，本机）

- 核对 lock 哈希：`cloudflare/skills` 的 `cf-cli`、`wrangler` 等 lock 里的 `skillFolderHash` 与 GitHub 返回的 tree SHA 完全一致，方案成立。
- 只读检查本机 32 个外部技能（agents + Claude Code + Kiro 三个来源）：15 次树列表调用、约 3 秒。结果：有更新 22、有更新且本地已修改 3、本地已修改 1、已是最新 3、无来源记录 3。
- 本地 tree 哈希能离线证明 29 个有 lock 记录的技能里 22 个没改过，这些即使有更新也不需要额外调用。其余靠逐文件比对：Windows 上 CRLF 检出不算改动，`node_modules` 等构建产物不算改动。
- 在真实技能的副本（临时家目录）上升级 `basin`：下载、校验、替换、写回 lock 成功，lock 其余字段不变；随后 `npx skills check -g` 报告「All global skills are up to date」。
- 自动化测试：pytest 全量 5567 通过；vitest 新增 7 条全部通过（另有 3 个文件 15 条在 Node 26 下因 `localStorage` 不可用而失败，main 上同样失败，与本次无关）；Playwright 540 条中 539 通过，1 条 WebKit 滚动用例在并发负载下偶发失败，单独重跑 6/6 通过。

### 手动核对清单（桌面应用）

- [ ] 设置 ▸ 技能：顶部「外部技能来源」列出 agents / Claude Code / Kiro 等，全部关闭，各自显示技能数；不存在的目录显示「未找到」、开关不可点。
- [ ] 打开「通用目录（npx skills）」：列表出现外部技能行，带来源、「只读」标签，没有编辑和删除按钮；「显示文件夹」能打开对应目录。
- [ ] 外部技能默认「仅手动」：新会话里看不到它进入目录（不会被模型主动使用）；输入框 `/` 菜单里有它，带「仅手动」标签，选中后能正常使用。
- [ ] 把一个外部技能切成「自动」：下一条消息起模型能自己调用它；作者锁定的技能显示「仅手动」且不能切换。
- [ ] 首次打开技能页自动在后台检查一次；「检查更新」按钮可用，显示上次检查时间；导航「技能」上出现可升级数量角标。
- [ ] 「有更新」筛选只列有更新或本地改过的技能；纯更新默认勾选，本地改过的默认不勾，并显示改动摘要。
- [ ] 勾选本地改过的技能点「升级所选」：先弹确认框；确认后显示逐项结果；终端里 `npx skills check -g` 认为它已是最新。
- [ ] 点「回滚」：恢复升级前版本，状态回到「有更新」。
- [ ] 从专家库装一个技能，在设置里改它：显示「本地已修改」；库页「恢复原版」后可以在技能页「回滚」找回改过的版本。
- [ ] 文件被占用（例如在编辑器里打开技能目录下的文件）时升级：提示被占用，原目录不变。
