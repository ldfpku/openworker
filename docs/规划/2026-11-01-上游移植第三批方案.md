## 三、安全底线（自动批准默认开启，价值高于上游平均）

本库 `config.py:92` 的 `auto_approve` 默认 `True`，以下各组让「无论审核模型怎么判，某些动作必须由人确认 / 必须被拦」。按上游依赖顺序带入（`workspace_safety.py` 由 OPE-233 创建，`review_facts.py` 由 OPE-235 创建，OPE-236 依赖二者）：

| 组 | 提交（按序） | 作用 |
| --- | --- | --- |
| OPE-232 只读授权收紧 | `b45f47df` `6f2ef8be` `d7b3f129` `038e37a7` | 会话只读授权知道自己的 shell（PowerShell/POSIX）并失败即关；只放行审核过的旗标；`env`、`git config` 改为询问；仓库 git 设置无害时 git 命令才走只读授权（新增 `git_settings.py`） |
| OPE-231 受保护文件 | `197a1c4d` `6e521413` `9e4a5263` | 会被自动执行的文件（hooks、启动脚本、构建配置等）不论大小写、不论通过哪个工具、按真实路径一律受保护 |
| OPE-233 安全写入档 | `9a5dfc2e` `ca8f9aa4` `9f9a9de4` `7af498a0` `0243bbf9` `54d2ebc2` | 工作区内对文档/图片的可撤销写入不再调用审核模型（省费用和延迟）；可带脚本的格式、删除和移动始终交审核 |
| OPE-235 代码算出的事实 | `15627a18` `e8075dd0` | 发往审核模型的请求附上代码算出的事实（真实目的地、上下文中的外部内容） |
| OPE-236 密钥外发底线 | `f44f760d` `9ab855f9` `bd04516e` `e7c46ff1` `a9e16a08` `2ffebb56` `8b682c46` | 看起来像密钥的数据要离开本机时，必须由人确认；识别文件内容、`git push`、发布类程序、脚本、`Authorization: Basic` |

带入原则：

- 上游文档里涉及 headless、Windows/macOS 沙箱、Jev/OpenAI Decisions 的段落不带。
- `scripts/build_layered_corpora.py` 与 `tests/` 下的评测语料只在本库已有对应文件时才带；缺的语料不硬造，相应测试一并不带，并在提交信息里注明。
- 改到 `agent.py`/`engine.py` 的部分以本库现有结构为准，不能回退本库的网关、微信、压缩等改动。

## 七、已知取舍

- OPE-232 会让部分原先自动放行的只读命令（`env`、`git config`、未审核过的旗标）改为询问一次，这是刻意的。
- OPE-233 让工作区内文档/图片写入跳过审核模型，属放宽；但删除、移动、可带脚本的格式、受保护文件不在此列。
- OPE-236 让含密钥样式数据的外发一律要人确认；若公司脚本经常把带 token 的配置推到内部服务，会多出确认。
