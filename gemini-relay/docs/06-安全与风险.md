# 06 - 安全与风险

> 本文是什么：中转方案引入的信任边界、PII（邮箱）边界、滥用面、平台风险与合规提示的一次性说明。
> 建议在决定长期使用中转（而不只是临时验证）、尤其是分发给同事之前通读一遍。

## 信任边界

中转 Worker 是明文请求的必经之路，能看到完整的 `x-goog-api-key` 请求头和对话
内容——这是反向代理的固有性质，不是这个方案特有的缺陷。这个前提可接受的**唯一
条件**是：域名 `smjtools.com` 与 Worker 都由管理者本人的 Cloudflare 账号控制。研究
阶段只核实了该域名托管在 Cloudflare 的 NS 上（norm/georgia.ns.cloudflare.com），
**没有、也无法核实账号归属**——启用前请自行确认你能登录管理该 zone 的 Cloudflare
账号。要清楚地意识到：v2 把中转地址内置进了 `gemini_provider.py`（`RELAY_BASE_URL`
常量），装了 openworker 的每台机器上，所有 Gemini 请求（包括 `x-goog-api-key`）
**默认**发往这台主机；如果它不在管理员的控制之下，等同于全公司把 key 交给了别人。
分发前必须确认账号归属。

Worker 代码本身（[worker/src/index.ts](../worker/src/index.ts)）不记录、不持久化
任何请求正文或响应正文——没有一行 `console.log` 输出请求体或敏感头；日志输出只有
两处 `console.error`：D1 写入失败时的 "usage insert failed" 一行、记录支路整体失败
（如上游流没读完就中断）时的 "recordUsage failed" 一行（这种情况仍会补记一条
`error='parse-fail'` 的用量行）。两处都只打印错误对象，行内没有请求内容或 key。v2 起
Worker 会把**用量元数据**持久化进 D1（邮箱、模型名、token 计数、HTTP 状态、
key 的 SHA-256 前 12 位——完整 key 和对话内容永不入库），边界详见下面的 PII 一节。
`wrangler tail` 只是运维时临时接上的实时流，用完即止，不落盘存储；启用它
不会让代码本身多产生任何日志。

## 个人信息（PII）边界

v2 引入了一类新数据：**同事的邮箱地址**。它存在两个地方——KV 名册（value 是邮箱
纯文本，metadata 里也带一份供 `roster.ps1 -List` 显示）和 D1 `usage` 表的每一行
流水（按人记账的依据）。要点：

- **保留期是永久**：D1 没有配置任何 TTL 或清理任务，删除名册条目（吊销 key）只
  影响准入，**不会**删除该邮箱名下已有的历史用量行。想抹掉某人的历史记录需要手动
  在 D1 控制台执行 DELETE。
- **谁能读到**：Cloudflare 账号的登录者（控制台 KV/D1 界面），以及任何持有带
  Account → D1 → Read 权限 API Token 的人（`usage_report.py` 用的 `CF_API_TOKEN`
  就是这种）。Token 建议按最小权限创建（只给 D1 Read、限定到目标账号），并按
  秘密对待。
- **除邮箱外无其他 PII**：流水里没有请求体、响应正文或完整 key；key 只以
  SHA-256 前 12 位出现，用于排查，无法还原。
- 在公司内分发前，应让同事知道"经中转的调用会按邮箱记录 token 用量"这一事实
  （记录内容与查询方式见 [07-多用户与用量统计.md](./07-多用户与用量统计.md)）。

## 滥用面

v2 的名册准入把滥用面收得比 v1 小得多：`gemini.smjtools.com` 即使被外部发现，
外人拿自己的 Gemini key 来也会被 `403 unregistered key` 拒绝（v1 时代"任何带
key 的请求都能过"的状态已不存在）；不带 key 是 `401 missing api key`。最坏情况
是消耗 Cloudflare 侧的请求配额、带宽和 D1 写入额度——被拒绝的请求也会各记一条
流水（email 为 `(no-key)`/`(unregistered)`），极端的扫描洪泛理论上能写满 D1 的
每日写入额度，但不会泄露账号或 key。

需要留意的一点：吊销不是瞬时的。名册查询带 `cacheTtl: 300` 边缘缓存，删除条目
后对应 key 在最长 5 分钟内仍可能被放行（离职/key 泄露场景下这 5 分钟窗口要心里
有数；名册操作见 [07-多用户与用量统计.md](./07-多用户与用量统计.md)）。

缓解手段（按接入成本从低到高）：

- 域名保持低调，不在公开渠道宣传。
- 名册只登记在册同事，人员变动及时 `roster.ps1 -Remove`。
- 在 Cloudflare WAF 加速率限制规则，压制异常高频请求（含未登记 key 的扫描）。

## 平台风险

**SDK 内部机制风险（v2 已大幅收窄）**：v1 依赖 `GOOGLE_GEMINI_BASE_URL`
这个 google-genai SDK 内部实现细节做隐式接线，openworker 代码里毫无痕迹；
v2 改为在 `gemini_provider.py` 的 `_ensure_client()` 里显式传
`http_options=types.HttpOptions(base_url=...)`——这是 SDK 公开、优先级最高
的一等入口，中转地址从此有代码和测试背书。残余风险只剩调试通道：
`resolve_base_url` 里的环境变量分支仍读 `GOOGLE_GEMINI_BASE_URL`，SDK
升级不影响它（读取在 openworker 自己的代码里），但升级 SDK 后仍建议重走
一遍 [05-验证与排错.md](./05-验证与排错.md) 的验证阶梯。

**版本锁定建议**：当前确认可用的运行环境是 `google-genai==2.16.0`
（安装在 hermes-agent venv 下），而项目 `pyproject.toml` 目前只约束
`google-genai>=1.0`，上限完全开放。建议在部署环境里显式钉住
`google-genai==2.16.x`，充分验证新版本行为之后再放开升级。

**作用域风险（v1 遗留）**：v2 正常部署**不需要**设置任何环境变量——中转
地址内置在 openworker 自己的 provider 代码里，作用域天然只覆盖 openworker。
但如果本机还留着 v1 时代 `set-relay-env.ps1 -Install` 写入的 User 级
`GOOGLE_GEMINI_BASE_URL`，它会影响该用户下**所有**使用 google-genai 的
进程（同一台机器上的 hermes-agent 也会受影响），并且在 openworker 里会
**盖过**内置常量（调试覆盖的优先级更高）。不做调试时用
`set-relay-env.ps1 -Uninstall` 清掉它；临时调试用会话级的
`start-openworker-cn.ps1`。

**免费额度上限**：Cloudflare Workers 免费版是 100,000 请求/天、10ms
CPU 时间/次调用（流式等待上游响应的时间不计入 CPU，只有实际执行 JS
的时间算）、100MB 最大请求体、每次调用 50 个外部子请求。一次 Gemini
对话对应中转侧 1 个请求、1 个外部子请求，远低于这些上限；持续高频
使用才需要关注是否触顶。

**大陆可达性非保证**：以下三条均来自研究阶段的取证，置信度如实标注，
不夸大，也不做超出证据范围的保证：

| 结论 | 置信度 | 依据 |
|---|---|---|
| `*.workers.dev` 在大陆被 DNS 层面污染/阻断 | 中等 | 多个 Cloudflare 社区帖子一致报告，无官方声明 |
| 自定义域名一般比 `workers.dev` 可达，但不保证任何具体域名都能连通 | 低到中等 | GFW 具备基于 SNI 的定向阻断能力；未对 `smjtools.com`/`gemini.smjtools.com` 做过系统性实测 |
| `generativelanguage.googleapis.com` 本身在大陆受限 | 中等 | 多个二手来源一致报告，无权威一手来源 |

这也是本方案坚持只用自定义域名、完全不启用 `workers.dev` 的原因——但
即便如此也不构成「一定可达」的保证。以实测为准，验证方法见
[05-验证与排错.md](./05-验证与排错.md) 的五级验证阶梯；一旦中转不可达，
v2rayN + proxy-guard 的正向代理方案作为回退始终可用，两者互不冲突。

## 合规提示

Google 按地区限制 Gemini API 的使用；经中转访问相当于绕开这个地区限制，
属于用户自行承担的服务条款风险——这里只陈述事实，不做法律判断。

Key 与 `.env` 必须保密：研究阶段确认项目根目录的 `.env` 文件里有一个
真实的 `GEMINI_API_KEY`，绝不能提交进任何仓库、复制进任何文档或分享
出去。本目录下所有文档和示例代码中出现的 key 一律用占位符
`<YOUR_GEMINI_API_KEY>`，不会出现真实值。
